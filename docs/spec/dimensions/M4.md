# M4: Documentation accuracy

**Lens:** maturity · **Scored:** yes

## Property

Whether the project's current-state documentation describes the code that exists.

## Applies to

Any language. The documents are prose markup files (for example Markdown, MDX, reStructuredText or AsciiDoc). Each claim is checked against the repository's own tree at the analysed commit. The tree means its files and folders and its build and package manifests (for example project files, `package.json`, `go.mod` or `pyproject.toml`). The tree includes files that are not production code. No document's text counts as evidence that a claim holds, and that includes the document that makes the claim.

The language of the prose matters:

- **Links** are checked in prose of any natural language.
- **Version and artefact-count claims** are checked only in prose written in English. A version or count claim in prose of another language, or in prose whose language cannot be told, is not a checked claim. How an engine tells the language of a passage is its method.

## Population

A document is in scope when it is **current-state documentation**: it describes this repository as it is now. Typical examples are a README, the documents of a documentation folder (for example `docs/`), and a contributor, install, build or getting-started guide at the repository root.

These are out of scope:

- **History:** for example changelogs, release notes, and migration and upgrade guides. Also files that record people or terms rather than the code, for example author, licence, notice, code-of-conduct or security files.
- **Intent:** decisions, proposals, plans, task lists and roadmaps.
- **Examples:** examples, samples, templates, fixtures, test data, and the documents that come with them.
- **Not this project's own:** vendored, third-party or generated documentation, and documentation that describes something other than this project. For example, a project template's README left unchanged describes the template.
- **Not reading material:** blog posts, meeting notes and journals.

Only statements about the present tree are claims. These are not claims:

- a statement about the past, a plan or an absence (for example "since Go 1.16" or "added in Python 3.8");
- an example;
- a statement about another repository;
- a version the document says is unsupported;
- text inside a code block in a programming language;
- a comment.

## Unit and denominator

**Checked claims.** A checked claim is a statement in a current-state document that the tree can settle. Three kinds are checked:

- **Link:** a relative link to a file or folder in this repository. Links are checked only in READMEs and in root-level contributor or build guides. They are not checked in the source of a documentation site, because the site resolves those links itself. External URLs and in-page anchors are not links to the tree.
- **Version:** a version of a runtime or of a toolchain or platform that the document states the project requires, installs, uses, targets, is built with or runs on, and that the repository itself declares, so the tree can settle it:
  - **Runtime version:** a version of a runtime (today .NET and Node.js) where the repository declares a version of that runtime (for example a target framework, or a Node.js engines field or pinned version).
  - **Toolchain version:** a version of any other language, toolchain or platform where a build file in the document's scope (see Thresholds) declares a minimum for it (for example Go, Python, Java, Rust or an Apple platform). A declared range with no lower bound declares no minimum.

  How an engine recognises such a statement in prose (its wording, the shape of the version) is its method.
  A number that counts or measures something is not a version (for example "2 replicas", "50%" or "300 ms").
- **Artefact count:** a number the document states for a kind of artefact the tree can count, where the tree holds at least one of that kind. Today there are two kinds:
  - widgets: UI component classes, for example Flutter widgets;
  - services: modules the project builds and runs as their own services.

  The tree's count leaves out tests and test support, and examples and samples, as [production-code.md](../production-code.md) defines them.

A build file inside tests, examples, fixtures or vendored code declares nothing for the project.

**C** is the number of checked claims across all current-state documents, whether they hold or not. Every repetition of a claim counts in C.

**D** is the number of document items. A document item is a checked claim that the tree contradicts. Within one document, a contradicted claim counts once however often the document repeats it:

- a link: once per target;
- a runtime version: once per runtime and major;
- a toolchain version: once per toolchain and version as written. The version is major.minor, or the major alone when the document names only a major. For example, "Go 1.18" and "Go 1.19" are two items. A Rust edition counts once per edition year;
- a count: once per kind of artefact.

**R** is the number of README items. A README item is one of these:

- an infrastructure product the root README advertises that has no footprint in the tree;
- a module the root changelog records as removed that the root README still documents.

Today neither kind of README item is checked, so R is 0 and README items add nothing to C.

## Thresholds

- **Link:** holds when the target exists in the tree as a file or folder. It also holds when the target is in build output or in a path that version control ignores, because the build creates those files.
- **Runtime version (.NET, Node.js):** holds when at least one declaration of that runtime admits it.
  - An exact version holds when it equals a declared major or falls inside a declared range.
  - A minimum ("18 or later", "at least 18", ">= 18", "18+") holds when some declaration is at or above it.
- **Toolchain version:** holds when it is at or above at least one declared minimum in the document's scope. The comparison uses major.minor, or the major alone when the document names only a major. "Or later" changes nothing. A Rust edition holds when it is at or above a declared edition.
  - **Scope:** a document is held to the build files in its own folder and below it. If there are none, it is held to the nearest folder above that has some. So a module's README is held to its module, and a root README is held to the whole repository.
- **Artefact count:** is an item only when the stated number and the tree's count are an order of magnitude apart, meaning one is 10 or more times the other.

## Score

score = clamp(10 − 2 · R − 2 · D · min(1, 25 / C), 0, 10)

- Each README item costs 2 points, whatever C is.
- While C is 25 or less, each document item costs 2 points.
- Above 25 checked claims, each document item costs 2 · 25 / C points.

For example, 3 items in 20 claims score 4, and 3 items in 100 claims score 8.5.

## Not measured when

- The repository has no current-state document.
- The current-state documents make no checked claim (C = 0). This includes the case where every version or count claim is in prose other than English, or in prose whose language cannot be told, and no link is checked.

## What the result is not

- **Not every claim.** These are read but not checked, and they do not affect the score:
  - paths named in prose, command arguments, install steps and `cd` targets;
  - environment variables, settings and routes;
  - project and package names;
  - README items (see R).
- **Not every language.** A version or count claim in prose other than English is not checked. It adds nothing to C or D. So a contradicted version in such prose costs nothing.
- **No package versions.** A version of a package or other dependency, whether shown in a badge or written in prose, is not checked today. It adds nothing to C or D.
- **No web links.** External links are not followed.
- **Not quality or completeness.** A repository with few documents and no contradicted claim scores 10.
- **Not a run of the steps.** It does not run the documented steps or time how long a newcomer takes to get started.
- **No build-time or outside footprint.** It cannot see something that exists only at build time, is read only by a hosting platform, or lives outside the repository. A true claim about such a thing can still count as an item.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each one with a threshold on the property.

- **Reference claims:** 25. Each document item costs the full 2 points while C is 25 or less.
- **Items per document:** at most 25 document items are counted from one document.
- **Documents read:** at most 200 current-state documents, shallowest path first. A document larger than 512 KiB (524,288 bytes) is not read, and still takes one of the 200 places.
- **Tree size:** at most 50,000 files of the repository are read as the tree. A file beyond these is not part of the tree, so a link to it counts as an item. A document beyond these is not read.
- **Declaring file size:** a file other than a document that is larger than 1 MiB (1,048,576 bytes) declares nothing. Its versions are not declarations and its artefacts are not counted.
