# R4: Test Coverage

**Lens:** productionReadiness · **Scored:** yes

## Property
Static test reachability: the share of production files that at least one test reaches by following imports, directly or through other imported files, found without running anything. It is not runtime line or branch coverage.

## Applies to
JavaScript and TypeScript in all their file kinds. This includes JSX and TSX, ES module and CommonJS variants (for example `.mjs`, `.cjs`, `.mts`, `.cts`), and single-file components (for example Vue or Svelte), each counted as one file.

## Population
The files counted are the production code in the languages above, as [production-code.md](../production-code.md) defines it. This dimension also leaves out the files listed below. Some have no behaviour of their own (declarations, data, re-exports). Some the product does not ship (developer scripts). Some no import can reach (service workers).

- **The authors' own developer scripts and tools** that the product does not ship. [production-code.md](../production-code.md) counts these as production code. This dimension leaves them out because they are not part of the shipped product.
- **Declaration-only modules:** files that hold only type, interface or namespace declarations and that compile away entirely, as `.d.ts` files do. They have no behaviour.
- **Behaviour-free data modules:** files whose whole content is imports plus one exported object literal, with no function, class or branch anywhere. They have no behaviour.
- **Re-export barrels:** files in which every statement re-exports from another module and nothing else is declared. They have no behaviour of their own.
- **Registration data modules:** files in which every statement is an import, a type declaration, or an exported constant bound to a literal, and at least one of those constants is an object or array literal (a table). They hold data, not behaviour. A call anywhere in the file is behaviour and keeps the file in. A lazy `() => import('...')` inside such a table is not a call. A file whose only constant is a single scalar stays in.
- **Service workers:** scripts the browser starts from a URL handed to the service-worker registration call. They have behaviour, but no module can import them, so no test can reach them through imports.

An empty production file stays in the population and counts in the denominator.

**Tests** are test files as [production-code.md](../production-code.md) defines tests. A test file is never production code, even when it cannot load. A type test is a test that only a type checker verifies and that never runs (for example a type-check-only test project). It is not production code, and it reaches nothing at run time.

## Unit and denominator
- **Unit:** a production file that at least one loadable test reaches.
- **Reaches:** the test imports the file, or imports a file that imports it, and so on through any number of production or non-production files. An import is any statement by which one module loads another at run time, for example a static `import`, `require`, or dynamic `import()`. This includes loads whose target the code computes (for example a module that loads every file in its own folder) and imports made through a module the build generates. An import resolves to the file that the test's own run-time environment would load. For example, a package's browser substitution applies when every test runs in a browser.
- **Not an import:** a type-only import. It is erased before the code runs, so it reaches nothing.
- **Loadable test:** a test that cannot load reaches nothing. A test cannot load when one of its run-time imports uses a path inside the repository (for example a relative import) to point at one of the repository's own files that does not exist and that no build writes. An import of a declared dependency package never makes a test unloadable.
- **Denominator:** all production files in the population above.

## Thresholds
- **Reached share:** P = 100 × reached production files ÷ production files, rounded to one decimal place.
- **Incidental frontend:** the production lines of JavaScript, TypeScript and HTML pages together are less than 15 % of all the repository's production lines (production lines as [production-code.md](../production-code.md) defines them).
- **Tested elsewhere:** the repository has at least one line of test code (not blank and not only a comment) in a language other than JavaScript, TypeScript or HTML.

## Score
score = clamp(P ÷ 10, 0, 10)

Each ten percent of reached share is one point. At 100 % the score is 10. With no loadable test the score is 0, unless one of the "not measured" rules below applies.

## Not measured when
- The repository has no JavaScript or TypeScript source.
- The population holds no production file.
- At least one loadable test exists and P is 0.0. In that case the tests are taken to exercise the code by some means other than imports.
- No loadable test exists, the frontend is incidental, and the repository is tested elsewhere (see Thresholds).

## What the result is not
- It is not runtime line, branch or statement coverage. A reached file counts in full, even if the test runs only one line of it.
- It does not measure assertion strength. A file that a test imports but never checks counts as covered.
- By its definition, reach follows imports only. A test that runs a file only by its path, opens it in a browser by URL, or tests it from another language does not reach it.
- When most of a repository is written in other languages, the result describes only its JavaScript and TypeScript part.
