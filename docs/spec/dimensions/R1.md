# R1: Type Safety

**Lens:** codeHealth · **Scored:** yes

## Property
How much of the frontend is typed TypeScript vs untyped JavaScript.

## Applies to
The JavaScript family of languages:

- **TypeScript**, in any of its source file forms (for example `.ts`, `.tsx`, `.mts`, `.cts`). Declaration-only `.d.ts` files are not counted, as [production-code.md](../production-code.md) states.
- **JavaScript** (for example `.js`, `.jsx`, `.mjs`, `.cjs`).
- **Single-file components** (for example Vue `.vue` and Svelte `.svelte`).

Here "frontend" means all of the repository's production code in these languages, wherever it runs. It includes server-side code written in TypeScript or JavaScript. Code in other languages, and script embedded in HTML pages, is not part of this dimension.

## Population
The population is the repository's production code, as [production-code.md](../production-code.md) defines it, written in the languages above.

This dimension also leaves out the following files, which [production-code.md](../production-code.md) would otherwise count as production code:

- **The authors' own developer tools and scripts:** for example scripts a developer runs by hand.
- **Examples, samples, demonstrations and playgrounds:** for example a demo app, a quick-start project or an interactive playground that ships beside the product.
- **Load and performance test scripts:** for example scripts that drive a load-testing tool.
- **Email template generators:** code that only builds email templates.
- **Static script assets of a server-side web application:** for example the static files folder of an ASP.NET or Blazor app. That folder holds scripts the server serves, but it is not a frontend codebase.

Tests and test support are left out, as [production-code.md](../production-code.md) already states.

## Unit and denominator
**Unit:** one file in the population. A file is **typed** when a static type checker that the repository configures checks it. That means one of these:

- a TypeScript file;
- a single-file component whose script block declares TypeScript as its language. A component that declares no script language is untyped;
- a JavaScript file that a TypeScript project in the repository type-checks. Either the project turns on checking of JavaScript and covers the file, or the file opts in with `// @ts-check` inside a project that allows JavaScript;
- a JavaScript file that Flow checks, as the repository configures Flow (for example with a Flow configuration file, or by declaring Flow as a dependency). Flow checks a file when the file opts in with an `@flow` pragma, or when the Flow configuration that covers the file checks all files. A file that opts out with `@noflow` is not checked.

Every other file in the population is **untyped**.

**Denominator:** all files in the population, typed and untyped. Each file counts once, whatever its length.

**Typed share** = typed files / (typed files + untyped files). When the population holds no file, the typed share is 1.

**Strictness:** how much checking the repository's root TypeScript configuration turns on. The root configuration is the `tsconfig.json` at the repository root. If there is no `tsconfig.json`, it is the `tsconfig.base.json` there. Three core checks are read: `noImplicitAny`, `strictNullChecks` and `noImplicitThis`.

- A check's effective value is its own setting if it has one. Otherwise it is the value of `strict`.
- A check that has neither its own setting nor `strict` is left out.
- Only settings written in the root configuration file itself count. Settings it inherits from another configuration (through `extends`) are not read.

**Strictness** = checks in effect / checks with an effective value.

Strictness is 1 when the root configuration is missing or cannot be read. It is also 1 when the configuration gives none of the three checks an effective value.

## Thresholds
- A file counts as typed only through one of the routes listed under Unit. `any` types, `@ts-ignore` and `@ts-nocheck` do not change whether a file counts as typed.
- A check counts toward strictness only when its effective value is true.

## Score
score = typed share × 10 × (0.7 + 0.3 × strictness)

- A fully typed frontend scores 10 whenever strictness is 1. That covers three cases:
  - every core check that has an effective value is in effect (for example a root configuration that sets only `noImplicitAny: true`, with no `strict`);
  - no core check has an effective value;
  - the root configuration is missing or cannot be read.
- A fully typed frontend whose root configuration turns all three checks off scores 7.
- A frontend with no typed file scores 0, whatever its strictness.
- When the dimension is measured but the population holds no file, the typed share is 1. The score is then 10 × (0.7 + 0.3 × strictness). For example, this happens when a repository has a `package.json` and every production frontend file is one of the authors' own developer tools.

## Not measured when
- The repository has no frontend: it has fewer than 5 files in the JavaScript family, counted as stated under Pending re-definition.
- Every production frontend file is a test or test support.
- The repository has no npm package manifest (`package.json`) anywhere, and every production frontend file is one of the authors' own developer tools.

## What the result is not
- It does not check that the types are sound. A TypeScript file full of `any`, or one that turns checking off with `@ts-nocheck`, counts as typed.
- It does not run a type checker. Type errors in the code do not lower the score.
- It weighs files, not lines. A 10-line typed file counts as much as a 5,000-line untyped one.
- Strictness comes only from the settings written in the root configuration file. A package configuration that is stricter or looser than the root does not change the score. Neither does a base configuration that the root extends.
- It says nothing about typing in languages outside the JavaScript family. Server-side code written in these languages counts like any other file in the population.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Minimum frontend size:** the dimension is measured only when the repository has at least 5 files in the JavaScript family. A file counts toward the 5 if it is in the population, or if it is a test, test support or one of the authors' own developer tools. Every other exclusion above, and the file size cap, applies first.
- **File size cap:** a file larger than 1,000,000 bytes is left out of the population.
- **Strictness weight:** strictness can lower the score by at most 30 % (the 0.7 and 0.3 terms of the curve).
- **Empty population:** when the dimension is measured but the population holds no file, the typed share is 1.
