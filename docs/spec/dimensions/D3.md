# D3: God Classes

**Lens:** codeHealth · **Scored:** yes

## Property
Over-large classes that try to do too much ("god classes").

## Applies to
Any programming language, read as source code. Some rules depend on what the language has:

- **Types:** classes, structs, records, singleton objects and their equivalents in each language. A module that the code declares as a unit of functions also counts as a type for the member-count rules (for example an Elixir, Erlang, F#, Ruby or Rust module, including a Rust module that is one file). The top-level functions of a file do not form a type just because they share that file (for example the top level of a Python, JavaScript, TypeScript, Kotlin or Swift file). The file-length rule covers such a file. A Go package is not a type.
- **Component and view files:** the code blocks of a Razor component or view are judged as code (for example the `@code` or `@functions` block of a `.razor` or `.cshtml` file), even though [production-code.md](../production-code.md) leaves server-side views out. The markup around those blocks is not judged. These code blocks are judged only in a repository that has at least one C#, Visual Basic or F# project. In any other repository, Razor files are not judged at all.
- **HTML pages:** an HTML page is judged for file length only by the script written inside it. Its markup does not count.
- **CSS:** style files are not judged.

## Population
Production code as [production-code.md](../production-code.md) defines it, with the differences below. Code left out below is never charged. It still counts in L if it is in a language that L reads (see Unit and denominator).

- **Left out:** examples, samples, demonstrations and playgrounds. Each of these is an app that exists to show the product. It is not shipped and is not compiled into a user's build.
- **Left out:** scaffolding templates. These are starter projects that a tool copies out to its users (for example a project template pack).
- **Left out:** CSS files.
- **Left out:** a file that is a literal lookup table. Each of its code lines is an entry that maps a key to a plain literal or constant. Its only other lines are declarations, branch openers and punctuation. This holds even when each entry is wrapped in a function (for example a translation file of getters, each matching a language key to a string). A table whose entries call other code is not a lookup table. A lookup-table file is not charged for any offence.
- **Generated regions:** a file is not charged for its length when generated code makes up more than half of its significant lines. A type is not charged as a long type or for too many methods when generated code makes up more than half of the significant lines of its declarations.
- **Inline test code:** test code written inside a production file does not count toward that file's lines (for example a Rust `#[cfg(test)]` module or a bare `#[test]` function).
- **Added:** the code blocks of Razor components and views, under the condition in Applies to. They are judged but do not count in L.

## Unit and denominator
**Significant line:** a line that carries code. These lines are not significant:

- blank lines;
- comment-only lines;
- lines that hold only structural punctuation (`{ } ( ) [ ] ; ,` and whitespace);
- lines of a constant table (see Thresholds).

There are five offences:

1. **Long file:** the file's significant lines.
2. **Long type:** the type's own significant lines. The lines of a nested type belong to that nested type, which is judged on its own. A type declared in several parts (for example a C# partial class) is judged on all its parts together.
3. **Too many methods:** every method a type declares across all its parts, as the language defines a method. Constructors, finalizers and operators count. So do overrides, interface or trait implementations, and methods declared without a body. Properties and fields do not count.
4. **Too many fields:** the stored instance fields and stored properties a type declares. Constants and static members do not count.
5. **Long method:** the significant lines of one method or function body. A method or function is any named callable with a body, including constructors and operators. An anonymous function counts as part of the body that encloses it. Declarations without a body are not measured.

**Offending file:** a file with at least one offence. A file offends through its own length, or because it holds a type or a method body that offends. A type declared across several files offends in the file that holds most of its methods. When two parts hold the same number of methods, the part with more significant lines decides.

**What is counted:** N, the number of distinct offending files. A file counts once, however many offences it has.

**Denominator:** L, the non-blank lines (comment lines included) of the repository's production code files, as [production-code.md](../production-code.md) defines them, in the languages L reads. Exactly one of the three cases below sets L. They are checked in this order, and the first one that applies decides:

1. **A .NET product.** Both of these hold:
   - the repository has at least one C# or Visual Basic project that compiles at least one source file (production, test or generated);
   - the production lines of the C# and Visual Basic files in those projects, taken together, are at least the production lines of each of these, taken one at a time: F#, Java, Kotlin, Scala, Python, PHP, Ruby, Elixir, Go, Erlang, Swift, Dart, Rust, and JavaScript and TypeScript together. JavaScript and TypeScript take part in this comparison only when no other language on that list has production lines equal to at least 25 % of the JavaScript and TypeScript production lines together. On a tie, the repository is a .NET product.

   L is the C# and Visual Basic files those projects compile. Nothing is added for JavaScript, TypeScript, single-file components or HTML script, even when the repository also has a large JavaScript or TypeScript part.
2. **A JavaScript-family product:** the repository is not a .NET product, and either JavaScript on its own or TypeScript on its own has more production lines than every other single language on [production-code.md](../production-code.md)'s production-lines list. JavaScript and TypeScript are compared with each other here, not added together. The script written inside HTML pages counts as JavaScript. L is the files in case 3's set, plus JavaScript files, Vue and Svelte single-file components counted whole, and the script written inside HTML pages (only those lines, not the markup).
3. **Any other repository:** files in C#, Visual Basic, F#, Java, Kotlin, Scala, Python, PHP, Ruby, Elixir, Go, Erlang, Swift, Dart, Rust and TypeScript.

In cases 2 and 3, if no file in the set has a production line, L is the count from case 1's projects.

No other file counts in L, even when it is production code. For example, all of these are left out of L: C and C++, CSS, HTML markup, the code blocks of Razor components and views, and JavaScript in a repository that is not a JavaScript-family product. Code that Population leaves out of judging still counts in L if it is in a language L reads, for example examples, samples and lookup-table files.

## Thresholds
An offence counts only when the measure is strictly over its bar:

| Offence | Counts when |
|---|---|
| Long file | more than 500 significant lines |
| Long type | more than 400 significant lines |
| Too many methods | more than 30 methods |
| Too many fields | more than 30 stored fields |
| Long method | more than 100 significant lines in one body |

**Hand-written JavaScript files** (`.js`, `.mjs`, `.cjs`): the file-length rule depends on whether the file belongs to a JavaScript or TypeScript package that the repository declares.

- **In a declared package:** the file is judged on the 500-line bar like any other file.
- **Loose:** the file is not part of a declared package (for example scripts served as static assets of a C# web app). If it has 4 or fewer top-level units, its file-length bar is 1,500 significant lines. Otherwise the bar is 500. A top-level unit is a function, a class, or a variable assigned a function, declared at the top level of the file. Only loose files inside the cap under Pending re-definition are judged.

**Constant table:** a run of 50 or more consecutive significant lines that differ only in their literal values (strings, characters, numbers), with at least two different lines in the run. Such a run is data, and its lines are not significant.

**Types not judged as types.** The types below are never charged as long types, for too many methods or for too many fields. The long-method rule still judges method bodies inside them, except as stated for registration blocks.

- **Pure contract:** an interface or other type whose members declare behaviour without a body (for example a Rust trait with no default bodies).
- **Extension host:** a static type in which more than half of the methods extend other types (for example a C# static class of extension methods).
- **Registration block:** a type with at most 2 methods whose code mainly registers services, routes or middleware on an object it was given, with at least 3 registration calls. A method body in such a type is not charged as a long method when at least 3 of its top-level statements, and at least half of them, are registration steps on an object the method was given rather than one it builds itself.

**Files not charged for length.** A file that declares at least one type, where every type is a pure contract, an extension host or a registration block, is not charged as a long file. A file with no type at all is still charged.

**Branch tables are not long methods.** A method is not charged as a long method when nearly all of it is one branch table (a switch or match) with short arms. The table must have many arms, its arms must be short on average, and it must be the method's final statement or its expression body.

**Types whose method count is set by a contract or a table.** The types below are not charged for too many methods. They can still offend through file length, type length, field count or long methods.

- **Stateless constant table:** a type with no instance fields and no stored instance properties, where nearly all methods take no argument and return a value from a body of at most one line.
- **Forwarding type:** a type with at most one piece of its own instance state, where nearly all methods only pass the call on to one collaborator.
- **Declaration surface:** a type with at most one piece of its own instance state, where nearly all methods do no work of their own. A method does no work of its own when it has no body, only throws, only forwards, or makes one call into a shared handler.
- **Value catalogue:** a singleton object whose methods are mostly parameterless accessors that return a value.

**Width set from outside.** A type is not charged for too many fields when an outside source fixes its stored fields and its own methods read or write fewer than half of them. The outside source can be an external schema, format or layout. Examples:

- a type whose declaration maps it onto a serialisation or wire format, or onto a fixed memory layout (for example a Rust serialisation derive, or Go format tags on more than half of the fields);
- a mirror of an operating-system structure whose fields are all sized numbers;
- a table held as fields, where every stored field has the same declared type.

**Read language:** a language counts as read only when this dimension judged at least half of that language's production lines (production lines as [production-code.md](../production-code.md) defines them). A language read only in part, below that bar, counts as not read.

## Score
```
score = clamp(10 - 5.0 × N / ((L + 2000) / 1000), 0, 10)
```

Each offending file costs 5 points per thousand lines, where the number of thousands of lines is (L + 2,000) / 1,000. N = 0 scores 10. The score reaches 0 once N is at least 2 × (L + 2,000) / 1,000.

For example, 3 offending files in 40,000 lines score 10 - 5 × 3 / 42 = 9.64.

## Not measured when
- The repository has no production code that this dimension can judge.
- The read languages (see Thresholds), with all their production lines counted, hold less than half of the repository's production lines. Only the lines of read languages count toward this share. When they hold half or more, the score covers the code that was judged.

## What the result is not
- It measures shape: lines, method counts and field counts. No offence looks at how a type's methods share its state. A long but cohesive file still counts, for example one driven by a large table that the constant-table and lookup-table rules do not catch. A small class with tangled responsibilities does not count.
- It does not measure branching. A long straight-line method counts here, and the same method may still score well on complexity.
- It counts offending files, not god classes. Two oversized types in one file count once.
- It never charges test code, however large.
- Its density is not taken over all production lines. L reads a fixed set of languages, so a file can be charged while its lines are not in L (for example loose JavaScript beside a C# app).
- It is not the coverage rule. That rule (95 % of production lines, production-code.md) decides whether CAI is published at all.

## Pending re-definition
These are parameters of the existing reading's model. Today's scores depend on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Small-repository smoothing:** 2,000 lines are added to L.
- **Languages in L:** the three cases under Unit and denominator, not the production-lines list of [production-code.md](../production-code.md). For a .NET product, L holds only the C# and Visual Basic files its projects compile. JavaScript, single-file components and HTML inline script count only in a JavaScript-family product.
- **.NET product:** the C# and Visual Basic lines together must be at least those of each language in case 1's list, with ties going to .NET. JavaScript and TypeScript take part in that comparison, counted together, only when no other language on the list has production lines equal to at least 25 % of the JavaScript and TypeScript production lines together.
- **JavaScript-family product:** JavaScript alone or TypeScript alone must have the most production lines of any single language.
- **Cohesive loose JavaScript:** a loose JavaScript file with 4 or fewer top-level units has a file-length bar 3 times the usual one (1,500 instead of 500).
- **JavaScript file cap:** the cap ranks all hand-written JavaScript files (`.js`, `.mjs`, `.cjs`) in the repository, both loose files and files in declared packages. Only files of at most 1,000,000 bytes take part. The 300 largest by size in bytes are kept, with ties broken by path. Only the files kept are judged by the loose-JavaScript file-length rule. A loose file outside the 300, or over 1,000,000 bytes, is not judged in this dimension at all. Files in declared packages still take places among the 300, and they are judged on the 500-line bar whether or not they are kept.
- **Component and view file cap:** only in a repository that has at least one C#, Visual Basic or F# project, at most 500 Razor component and view files are read for their code blocks, each of at most 2,000,000 bytes. Files beyond the cap are not judged at all.
- **Generated regions:** more than half of the significant lines of a file, or of a type's declarations.
- **Literal lookup table:** at least 40 entry lines, and entries make up at least 90 % of the file's code lines once the lines around them are set aside.
- **Constant table run:** 50 consecutive same-shaped lines.
- **Branch table:** at least 20 arms, an average of at most 2 significant lines per arm body, and the table holds at least 80 % of the method's significant lines.
- **Extension host:** more than half of the methods.
- **Registration block:** at most 2 methods and at least 3 registration calls. For a method body: at least 3 top-level statements, and at least half of them, are registration steps.
- **Stateless constant table, forwarding type, declaration surface:** at least 90 % of the type's methods. Forwarding types and declaration surfaces may hold at most one piece of their own instance state.
- **Value catalogue:** at least 80 % of the methods, and at least 2 methods.
- **Width set from outside:** the type's own methods touch fewer than half of its stored fields. Format tags count as a mark when more than half of the fields carry one.
- **Read language:** at least 50 % of that language's production lines judged by this dimension.
- **Measured share:** the dimension is scored only when the read languages hold at least 50 % of the production lines.
