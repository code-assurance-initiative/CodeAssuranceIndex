# D6: Cohesion (LCOM4)

**Lens:** architecture · **Scored:** yes

## Property
Whether a class's methods are focused on a single responsibility.

## Applies to
Any language with classes or something like them: a type whose instances hold their own state and whose methods act on that state. For example, a class in C#, Visual Basic .NET, F#, Java, Kotlin, Scala, Python, PHP, Ruby, Dart, Swift, TypeScript or JavaScript; a Go or Rust struct with its methods; or an Erlang or Elixir module that keeps process state in a record, struct or map. Markup (HTML) and styles (CSS) are out of scope.

## Population
The population is the classes declared in production code, as [production-code.md](../production-code.md) defines it.

A class is its whole declaration. That includes every part of a partial or reopened class, every `impl` block of a Rust struct, and every trait or module the language copies into the class (for example a PHP trait, or a Ruby module that is `include`d or `prepend`ed). A trait or mixed-in module is never measured on its own.

Two tests decide whether a method is trivial:

- **Narrow trivial:** the method has no body or an empty body. Or its body is one statement that does one of these: throws, returns nothing, returns a constant, a member, a string with holes, a collection literal, a new object or a call result, or forwards one call.
- **Wide trivial:** the method is narrow trivial, or it is a chainable accessor that returns the instance, or it only stores into the class's own state (see Unit).

The following classes are also left out. They count in neither the numerator nor the denominator:

- **Fewer than two methods.** The class declares fewer than two methods of any kind. Instance, static and class methods all count here. Constructors, operators, property accessors and nested functions do not. For example a record, a DTO or another pure data type.
- **Stateless classes.** The class holds no instance state: none of its own, and none that a base class in the repository declares. For example a static class, a singleton `object` or module, a holder of extension methods, or a library module of free functions.
- **Stub-like classes.** Most of the class's instance methods are narrow trivial. Methods that only store into state and chainable accessors are not trivial for this rule. For example a null object, or a proxy, decorator or adapter that only forwards calls.
- **Event-sourced aggregates and projections.** The class rebuilds its state by applying events, with one handler for each kind of event.
- **Classes whose state comes from outside the repository.** The class derives from a base class whose state is not in the repository, and either:
  - (a) declares at most one state member of its own, whatever its number of groups; or
  - (b) splits into 2 or more groups (see Unit), and at most one of those groups uses the class's own state.
- **Classes shaped by a contract.** The class has two or more contract obligations and splits into 2 or more groups, but into no more groups than it has obligations. An obligation is an interface the class implements, or a distinct base-class method it overrides.
- **Partly generated classes.** A source generator writes part of the class from attributes on the hand-written part.
- **State holders.** The class splits into 2 or more groups, every group uses at most one of the class's own state members, and the class holds at most one collaborator whose type is an interface. For example an aggregate root whose commands each change one part of it, an options bag, or an entity with mutators.
- **Fluent builders.** The class splits into 2 or more groups and has two or more methods that are not narrow trivial, and every one of those methods returns the instance itself. Setters that store a value and return the instance, and chainable accessors, are not trivial for this rule.

## Unit and denominator
**Unit: the LCOM4 of one class.** LCOM4 is the number of separate groups of methods in the class, counted as follows:

- **Methods.** For LCOM4, a method is an ordinary named instance method. Constructors, operators, property accessors and nested functions are not methods.
- **Methods that cannot use the instance.** Some methods cannot use the instance. These are static methods, class methods, and methods that never use the instance in a language with no way to declare them static (for example a Python method that never uses `self`, or an Erlang or Elixir function that never reaches the process state). Such a method does not form a group of its own, but it still links the methods that call it.
- **When two methods are linked.** Two methods are linked when both use the same instance state member, or when one calls the other. An instance state member is an instance field, a property, a captured constructor parameter, a state key of the process, or non-private state that a base class in the repository declares. A call made through a class-level table of the class's own methods counts as a use of that table.
  - Overloads of one name are separate methods. A call to that name links them.
  - The clauses of one function (same name and arity) are one method.
- **Groups.** A group is a set of methods linked to each other, directly or through other methods.
- **What LCOM4 counts.** LCOM4 counts only groups that hold at least one method that is not wide trivial. A trivial method still links the methods it shares state with, but a group made only of trivial methods does not count. A method is wide trivial when:
  - it is narrow trivial (see Population);
  - it is a chainable accessor that returns the instance;
  - it only stores parameters or literals into the class's own state (and may return the instance), and it calls nothing, branches nowhere and reads no other state.
- **Several build targets.** When a class compiles to different members under different build targets, the target with the highest LCOM4 counts.

**Denominator:** the number of classes in the population.

## Thresholds
- **Low cohesion:** a class has low cohesion when its LCOM4 is greater than 3, that is, when it splits into 4 or more groups.
- **Smallest class measured:** a class must declare at least 2 methods of any kind (instance, static or class methods) to be in the population.

## Score
Let `low` be the number of classes with low cohesion and `n` the number of classes in the population.

`score = clamp(10 − 12 × low / n, 0, 10)`

The score is 10 when no class has low cohesion. It drops 1.2 points for every 10 % of classes with low cohesion. It reaches 0 when 5 in 6 classes (83.3 %) or more have low cohesion.

## Not measured when
No class is left in the population after the exclusions above, for example in a repository that has only free functions. The dimension then does not apply and gives no score. It never scores 10 in this case.

## What the result is not
- **Not a count of responsibilities.** It counts groups of methods that share no state and do not call each other. Such groups suggest separate concerns but do not prove them.
- **Not a full view of cohesion.** A class can hang together through something it does not hold as its own state and still read as low. For example: a collaborator passed in as an argument, state in a base class outside the repository, or global configuration.
- **Not class size, coupling or complexity.** A large class can score as cohesive, and a small one can split.
- **Not a verdict on the excluded shapes.** It says nothing about the classes left out of the population.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Two trivial tests:** to count LCOM4 groups, a method is trivial when it is wide trivial. For the stub-like and fluent-builder exclusions, a method is trivial only when it is narrow trivial: no body, an empty body, or one trivial statement.
- **Trivial body:** a narrow trivial body has at most one statement. A chainable accessor has at most two statements.
- **Stub-like:** at least 70 % of the instance methods are narrow trivial, in a class with 2 or more instance methods.
- **Event-sourced:** at least 60 % of the methods are one-argument event handlers, in a class with 3 or more methods.
- **Inherited state:** a base class outside the repository, and either at most 1 state member of the class's own (at any LCOM4), or LCOM4 above 1 with at most 1 group that uses the class's own state.
- **Contract-shaped:** at least 2 contract obligations, LCOM4 above 1, and LCOM4 no greater than the number of obligations.
- **State holder:** LCOM4 above 1, each group uses at most 1 state member of the class's own, and at most 1 collaborator whose type is an interface.
- **Fluent builder:** LCOM4 above 1, and at least 2 methods that are not narrow trivial, all of which return the instance.
