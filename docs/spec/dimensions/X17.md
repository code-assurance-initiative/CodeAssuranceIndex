# X17: Uncapped recursion over a caller-supplied document

**Lens:** securityCompliance · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether a walk that recurses through a JSON or XML tree handed in by its caller bounds how deep it will go (for example with a depth or remaining-levels value carried through each recursive call): an uncapped walk lets the document's nesting choose the stack depth, and the resulting stack overflow in some runtimes (for example .NET) cannot be caught and ends the process.

## Applies to
Any programming language in which a function can call itself. Markup (HTML) and styles (CSS) hold no walks and are not read.

## Population
The production code as [production-code.md](../production-code.md) defines it, with one more exclusion. This dimension also leaves out the authors' own build and site tooling that runs only over the repository's own files, for example a script that walks the repository's navigation, site configuration or manifests. No caller hands that code a document.

Within that code, the population is every **caller-reachable recursive document walk**. That is a function or method where all three of these hold:

- **It takes a document.** One of its parameters, or its receiver, is a node of a JSON or XML tree. Examples: a JSON value or object node, an XML element, node or document, or a DOM node of a parsed document. A list of nodes is not a node. A walk over the application's own page (for example its own DOM elements) takes a document only when a parsed document reaches it from a caller.
- **It descends.** It calls itself, directly or through other functions that call back to it (mutual recursion), and in the document's position it hands on a part of the node it got: a child, a property value or an element. A call that hands back the same node, or the node's parent or an ancestor, is not a descent. A recursive call that the language guarantees to run without a new stack frame is not a descent either, for example a Kotlin `tailrec` function or a Scala self-call that the compiler turns into a loop.
- **The caller chooses the document.** Code outside the walk's own type or module can call it, or can call a member that takes a document and hands it to the walk. In C#, Java and Kotlin that means a member that is not private. In JavaScript and TypeScript it means exported. In Python and Ruby it means public.

These are not in the population:

- A walk over a document type whose nesting is bounded by how it is built. For example, .NET's `JsonElement` comes only from parsers that stop at 64 levels by default.
- A walk over a leaf type, which has nothing to descend into. An example is a JSON scalar value node.
- An iterative walk that keeps its own explicit stack or queue.

## Unit and denominator
- **Unit:** an uncapped walk. This is a walk in the population that does not bound its descent. A walk is **capped** when either of these holds:
  - It carries a value through each recursive call that counts the levels it has gone down or the levels it has left, and it stops, or rejects the document, once that value passes a fixed bound.
  - It checks the document's depth against a fixed bound before it descends.
- **Counted once:** each uncapped walk counts once, however many descending calls it makes.
- **Denominator:** P, the number of walks in the population. Each walk counts once whatever its verdict.

## Thresholds
- Any fixed bound counts as a cap. The standard sets no maximum value for the bound.
- A depth value that is carried along but never compared with a bound is not a cap.
- A walk counts as uncapped from its first descending call. There is no minimum nesting depth and no minimum number of descents.

## Score
Let F be the number of uncapped walks and P the population.

- If F = 0, the score is **10**.
- If F > 0:
  - N = max(P, F + 1)
  - d = F / N
  - isolation = max(0, 1 − d / 0.10)
  - headroom = min(1, log10(N) / log10(200))
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − d) × (ceiling − 1), clamped to [1, ceiling] and rounded to two decimals (a half goes to the even digit).

Any uncapped walk keeps the score at 8 or below. It stays at 6 or below once uncapped walks make up 10 % or more of N. The score never reaches 0.

Examples:
- P = 1, F = 1 gives N = 2, ceiling = 6 and score = 3.50.
- P = 10, F = 1 gives score = 5.50.
- P = 100, F = 1 gives ceiling ≈ 7.56 and score = 7.50.

## Not measured when
- The repository has no production code in a language that has functions.
- The population is empty (P = 0). A repository with no caller-reachable recursive document walk is not measured, and it does not score 10.
- None of the in-scope files could be read.

## What the result is not
- It does not claim that the document is controlled by an attacker. It claims only that the walk's callable signature lets the caller's document decide the stack depth.
- It does not judge whether a bound is low enough for the runtime's stack, or how deep any given runtime can go.
- It does not cover walks that the caller cannot reach, or data trees that the code builds and never takes from a caller.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each one with a threshold on the property.

- **Score ceiling:** 6 is the highest score a repository with any uncapped walk can earn. It rises by up to 2 for a lone uncapped walk in a large population.
- **Isolation density:** 0.10. The ceiling's lift falls to zero once d reaches this value.
- **Headroom population:** 200. The ceiling's lift is fully available only from N = 200.
- **Denominator floor:** N = max(P, F + 1). This keeps d below 1 even when every walk examined is uncapped.
