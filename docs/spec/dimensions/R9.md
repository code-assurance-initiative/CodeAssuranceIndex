# R9: Circular Imports

**Lens:** architecture · **Scored:** yes

## Property
Import cycles in the module graph of the frontend code (the code of the user interface that runs in the browser or another client): source files that import each other in a loop, directly (two files importing each other) or through others (A imports B, B imports C, C imports A), so they can only be understood and changed together.

## Applies to
JavaScript and TypeScript (including their JSX forms and module variants, for example `.mjs` and `.cjs`), and single-file components (for example Vue or Svelte), read whole.

## Population
- **Files in the module graph:** files in these languages that are production code as [production-code.md](../production-code.md) defines it, plus tests, test support and evaluation inputs in these languages. Every other exclusion of [production-code.md](../production-code.md) still applies: for example, generated code, vendored code, build output and TypeScript declaration files (`.d.ts`) are not in the graph.
- **Which cycles count:** a cycle counts when at least one of its files is production code. All of its files then count toward its size, tests included. A cycle made only of tests, test support and evaluation inputs does not count.
- Today the languages set the boundary. A file in these languages is read whether it runs in a browser, another client or a server, because the code does not say where it runs.
- Only the repository's own files are in the graph. An import of a package or a runtime built-in is not.

## Unit and denominator
**The import.** File A imports file B when loading A also loads B. That covers a static import, a re-export from B (`export ... from`), a require, and a dynamic `import()` at the module's top level (awaited or not), each naming B. These are not imports for this dimension:
- an import or re-export of types only (for example `import type`, or an import that names nothing but types). It is removed before the code runs.
- a deferred import: a dynamic `import()` written inside a function body. It runs only when that function is called, not while A loads.
- an import that expands a pattern of files (for example a glob import), and a reference to an asset by URL.
- an import that only one build variant uses in place of another (for example a platform-specific substitute, or one alternative of a conditional export).
- a file importing itself.

**The unit: an import cycle.** An import cycle is a largest group of two or more files in the graph where every file can reach every other file by following imports. Two loops that share a file form one cycle. A cycle's size is the number of files in its group.

**Counted:** C is the number of counted import cycles. F is the sum of their sizes (the files in counted cycles).

**Denominator:** none. The score is an absolute count. It is not divided by the size of the code.

## Thresholds
- An import cycle has at least 2 files.
- The dimension is measured only when the module graph's population holds at least 5 files (production code plus tests, test support and evaluation inputs in these languages). See Pending re-definition.

## Score
- No counted import cycle: score = 10.
- Otherwise: score = clamp(10 − 1.5 · C − 0.1 · F, 0, 10).

Each cycle costs 1.5 points, and each file in a cycle costs another 0.1 points. Examples:
- One cycle of 2 files scores 8.3.
- Three cycles of 4, 3 and 2 files score 10 − 4.5 − 0.9 = 4.6.
- The score reaches 0 when 1.5 · C + 0.1 · F ≥ 10, for example at 6 cycles of 2 files each.

## Not measured when
- The population above holds fewer than 5 files.
- None of those files is production code.
- There are such files, but none of them could be read as modules.

A measured repository with no counted import cycle scores 10. That is a score, not "not measured".

## What the result is not
- It does not see a cycle that closes only through deferred imports, type-only imports, pattern imports or conditional alternatives. These are excluded by definition.
- It does not count every distinct loop. A group of files with many loops among them is one cycle, weighted by its size.
- It does not show that a cycle fails at runtime. A cycle can load correctly and still tie its files together.
- It does not cover cycles between folders or packages when there is no loop between single files. If one folder imports another and is imported back through different files, there is no file cycle.
- It is not limited to code that runs in a browser. Production code in the same languages that runs on a server is read too.

## Pending re-definition
These are parameters of the existing reading's model. Today's scores depend on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Minimum size:** at least 5 files in the module graph's population before the dimension is measured.
- **Curve weights:** 1.5 points per cycle and 0.1 points per file in a cycle.
