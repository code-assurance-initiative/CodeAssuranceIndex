# DM12: Ambient inputs in the domain

**Lens:** domainModelling · **Scored:** yes

## Property
Whether domain types receive the time and randomness their rules depend on, rather than reading the process clock or a global random source directly — an ambient read makes the rule it feeds untestable at the instant that matters and lets two reads inside one operation disagree.

## Applies to
C# and Visual Basic .NET. The ambient sources listed below belong to these languages and their platform. This dimension does not cover code in any other language.

## Population
The population is production code as [production-code.md](../production-code.md) defines it. Within it, only **domain types** count. A domain type is any type that the project places in its domain layer. It can be of any kind: class, record, struct, interface, enum or delegate. For example, a domain layer can be a domain project, or a namespace that holds the domain model with its aggregates and value objects. Adapters next to the domain are not domain types. Examples are persistence, infrastructure and data-access code.

Each type counts once. A nested type counts separately from the type that contains it.

## Unit and denominator
**Unit:** a domain type that **reads an ambient source in a rule**. Such a type has at least one ambient read in one of these bodies:

- one of its own methods
- one of its own property getters (read accessors)

An **ambient read** is a direct use of one of these sources:

- **The process clock:** the current date and time, today's date, or the current date and time with offset, in local or universal time. Examples are `DateTime.UtcNow`, `DateTime.Now`, `DateTime.Today`, `DateTimeOffset.UtcNow` and `DateTimeOffset.Now`. These members also count when they are reached through a static import of `DateTime` or `DateTimeOffset`. They do not count when the type declares or inherits its own member with that name. A time library's process-clock instance also counts, for example NodaTime's `SystemClock.Instance`.
- **Timers and tick counters:** reading a high-resolution timestamp, starting a stopwatch, reading the process tick count, or creating a timer or periodic timer.
- **A global random source:** the shared random generator (`Random.Shared`), or a new random generator created without a seed.

These are **not** ambient reads:

- A clock or random generator that the type receives. Examples are a parameter, an injected clock or time-provider abstraction, a clock wrapper that the repository writes itself, and a random generator created with a seed that the caller supplies.
- Creating a new globally unique identifier, for example `Guid.NewGuid()`.
- Reading environment variables or other process configuration.
- Text inside comments and string literals.

These member bodies are not read:

- **Constructors.** A creation stamp set while the object is built is not charged.
- **Field and property initialisers.** For example, `{ get; init; } = DateTime.UtcNow` is a creation stamp.
- **Property setters and init accessors.**
- **Event-applying methods** in event-sourced code. These methods rebuild state from a recorded event and are usually named `Apply` or `When`. Another dimension covers them.

The exemption depends on where the read is written, not on what it does. A creation stamp taken in an ordinary method is charged. Examples are a static factory method and a method that emits an event.

An anonymous function or local function belongs to the member that encloses it. A type with several ambient reads still counts once.

**Denominator:** all domain types, of every kind. Types without bodies, such as interfaces and enums, are in the denominator and count as clean.

## Thresholds
- A domain type counts as reading an ambient source when the bodies that are read contain one or more ambient reads.
- One domain type is enough for a score. There is no higher minimum.

## Score
Let *N* be the number of domain types and *A* the number of domain types that read an ambient source. The clean share is *f* = (*N* − *A*) / *N*.

Score = 3 + 7 × *f*, rounded to two decimals.

- If no domain type reads an ambient source, the score is 10.
- If every domain type reads one, the score is 3.

Between these two points the score falls in a straight line. It never goes below 3.

**Repositories not built around a domain model.** Some repositories as a whole are not built around a domain model of aggregates, entities and value objects. For these, the score uses the same formula over the types in a domain layer. The score is published only when at least one of those types reads an ambient source. If none does, the dimension is not measured. Such a repository is never reported as clean.

## Not measured when
- The repository has no domain types in C# or Visual Basic .NET.
- The repository is not built around a domain model, and none of its domain-layer types reads an ambient source.

## What the result is not
- It does not show whether the domain's time logic is correct. It shows only whether time and randomness are received rather than taken.
- It does not charge creation stamps in constructors or initialisers, or reads in setters and init accessors. A type whose only ambient reads are in these places scores as clean. A creation stamp taken in an ordinary method, such as a factory method, is still charged.
- It does not see a process clock reached through a wrapper that the repository writes itself, or through any source not listed on this page.
- It does not count how often a type reads the clock. One read and twenty reads in a type weigh the same.
- It does not judge how identifiers are generated, environment configuration, or event-applying methods.
