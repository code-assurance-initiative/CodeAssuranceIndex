# X29: Per-element action decided by a fixed element

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether a decision taken once per element is taken ABOUT that element — a test inside a counted loop that reads a fixed subscript of the very collection its guarded statement indexes by the loop variable applies element zero's answer to all of them, so the elements that differ from it are all handled wrongly, and in the same direction.

## Applies to
Any language that has loops over the elements of a collection and reads elements by position. Examples are a counted `for`, a range loop, an index kept by hand in a `while` or `do` loop, a `foreach` or `for...of` loop, and a per-element callback such as `forEach`, `map` or `Select`.

## Population
Production code as [production-code.md](../production-code.md) defines it. This dimension adds no file kinds and no exclusions of its own.

## Unit and denominator
- **Per-element loop:** a loop that runs once for each element of a collection. Each pass is "on" one element. That element is named either by an index variable (a counted loop with exactly one loop variable, or a loop whose single index is declared before it and stepped upward inside it) or by an element variable (the iteration variable of a for-each loop, or the single parameter of a callback passed to a call on the collection).
- **Decision:** a test inside the loop body that decides whether, or how, some code runs. The kinds are:
  - an `if`: its then-branch, and a plain `else`. An `else if` is its own decision. When the then-branch only leaves the pass (`continue` or `break`) and there is no `else`, the decision also covers the rest of the enclosing block.
  - a conditional expression: both of its arms.
  - a short-circuit `&&` or `||`: its right operand, but only where the element is passed to a call there.
- A decision belongs to the innermost per-element loop that encloses it. Code inside a function written in the loop, other than a per-element callback, does not run where it is written and belongs to no outer loop.
- **Site (the denominator):** a decision in which two things hold:
  - the code it decides acts on the element the pass is on. That means it indexes a collection by the loop's index alone (`c[i]`, not `c[i + 1]` and not `c[i, j]`), or it names the element variable.
  - its condition never mentions the index or the element variable.

  Most sites are correct code. One decision is one site.
- **Finding (the unit counted):** a site, paired with one collection its decided code acts on, whose condition reads an element of that same collection at a position that does not move from pass to pass. "The same collection" means the same variable, field or property path, with no call and no subscript inside the path, written the same way in both places. A fixed position is one of these:
  - a literal or other value that the loop does not change, for example `xs[0]`, `xs[^1]` or `xs[head]`.
  - the language's accessor for the first, last or nth element with no search condition, for example `First()`, `Last()` or `ElementAt(0)`.

  The fixed read may be written in the condition itself. It may also be reached through a local variable that is bound to it before the loop, in the same function, and never reassigned inside the loop.
- A site can carry more than one finding, one per collection, so findings can exceed sites.

## Thresholds
- A fixed read is not a finding when its position is below the loop's lowest visited index and both are integer literals, for example `rows[0]` under a loop starting at 1. The loop never visits that element.
- A fixed read is not a finding when the collection is one group of a grouping, and the members the condition reads off the fixed element are all members the grouping key reads. Every element of that group gives the same answer.

## Score
Let *f* be the number of findings, *p* the number of sites, and *n* = max(*p*, *f* + 1).

- If *f* = 0, the score is 10.
- Otherwise:
  - density *d* = *f* / *n*, clamped to [0, 1]
  - isolation = max(0, 1 − *d* / 0.10)
  - headroom = log10(*n*) / log10(200), clamped to [0, 1]
  - ceiling = 6.0 + 2.0 × isolation × headroom
  - score = 1.0 + (1 − *d*) × (ceiling − 1.0), clamped to [1.0, ceiling] and rounded to 2 decimals.

10 means a decision taken once per element is taken about that element. One finding among many sites scores at most 8.0. Pervasive findings sink toward 1.0.

## Not measured when
The production code holds no site and no finding. Code with none of this construct is not a 10.

## What the result is not
- It is not a lint against conditions that do not change inside a loop. A mode flag or null check that is the same on every pass is not a finding unless it reads a fixed element of the very collection the decided code acts on.
- It does not see a fixed element reached through a method call (for example `Head().IsInitialized`) rather than through a position.
- A loop whose author meant the condition to be the same on every pass is still counted, because the test belongs above the loop under that reading.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace them with a threshold on the property.

- The 10 % density at which the ceiling's lift above 6.0 vanishes.
- The population of 200 at which headroom saturates.
- The base ceiling of 6.0, the lift of 2.0 and the floor of 1.0.
- The denominator floor *n* = max(*p*, *f* + 1).
