# P10: Library API & versioning

**Lens:** productionReadiness · **Scored:** yes

## Property
For a library: a deliberate (small) public API surface and explicit semantic versioning so consumers can depend on it safely.

## Applies to
- **Versioning half:** any language whose packages are published through a package manifest or build declaration. Examples are .NET packages, npm, PyPI, crates.io, Maven or Gradle, Go modules, RubyGems, Composer, SwiftPM, CocoaPods, pub.dev, Hex, sbt, Mill and scala-cli.
- **Surface half:** only these languages are scored on the surface half: C#, Visual Basic .NET, Java, Kotlin, Rust, Swift, Go and Dart.
- Every other language is scored on the versioning half only. This includes F#, Scala, Python, Ruby, PHP, Elixir, JavaScript and TypeScript. For example, in JavaScript and TypeScript a package's surface is whatever its entry point re-exports, not what each module exports.

## Population
- **The repository:** only a repository that publishes at least one library is in scope. A library is a package that the repository declares it publishes for other code to link against or import. For example: a .NET project that declares a package and does not build an executable; an npm package that is not marked private and names an entry point; a crate, gem or Maven artifact that declares publication; or a Go module whose packages are meant to be imported by other modules. These are not libraries: a packaged command-line tool (installed and run, not linked against), an executable, a service and an application. A repository that contains only such things is out of scope.
- **The surface:** the types declared in the production code of each published library, as [production-code.md](../production-code.md) defines it. This dimension also leaves out the library's examples, samples, demonstrations, documentation and benchmarks, and code in projects that do not publish a package. Where a package declares which of its packages or items it exports (for example a Java module's exports, Rust re-exports, or a SwiftPM library product), only the source it ships is read. A type declared several times (for example Kotlin multiplatform expect and actual) counts once.

## Unit and denominator
- **Public type:** a type that a consumer of the published package can name. It is declared public, its enclosing types are also visible, and nothing in the language keeps it off the package's surface (for example Go's `internal/` folders). Where the package declares its exports, the type must also be exported or re-exported.
- **Exposed type:** a public type that is not deliberately API. A type is exposed in either of two ways:
  1. **Marked as implementation:** one segment of its namespace or package, or one folder below the library's own root, is exactly one of `internal`, `internals`, `impl`, `impls`, `implementation`, `implementations` or `detail`. Letter case does not matter, and only whole segments count, so `International` marks nothing. A type is also marked when its name ends in `Impl` (this exact case) and has at least one character before it. This applies in every surface-half language.
  2. **Used only inside its own library (C# only):** all of these conditions hold:
     - the library's own code uses the type outside its own declaration;
     - no other C# project of the repository that references the library uses it;
     - no type, member or signature visible outside the library names it (as a base type, interface, constraint, return, parameter, property, field or event type);
     - it is not an exception, an attribute, or a static class of extension methods.

     This reading applies only to a C# library, and only when at least one other C# project of the repository references it and uses at least one of its public types by name. In every other language only the implementation markers count.
- **Count:** E is the number of exposed types and P is the number of public types. Both are summed over all published libraries.
- **Versioned:** a published library is versioned when it states the version it ships with in a place its build or release reads. For example: a version in its manifest or project file, a version that the release pipeline or a versioning tool stamps onto the package, a hand-written assembly version, a changelog with semantic-version release headings, or a semantic-version release tag in the repository. The repository counts as versioned only when every published library is versioned. A version string that is only mentioned somewhere does not count.

## Thresholds
- A type counts as exposed only when it has one of the markers above or meets the conditions above. A public type that has no marker and does not meet the conditions is not exposed. It counts only in P, so a large surface alone never lowers the score.
- The surface term reaches its floor when exposed types make up half or more of the public types (2E/P ≥ 1).

## Score
The surface is measured when at least one type is declared in published library source written in a surface-half language.

- **Surface term:** S = 0.6 if P = 0 or E = 0. Otherwise S = 0.6 − 0.4 × min(1, 2E / P).
- **Versioning term:** V = 0.4 if the repository is versioned, otherwise 0.
- **Surface measured:** score = 10 × (S + V), rounded to 2 decimals. The score is between 6 and 10 when the repository is versioned, and between 2 and 6 when it is not.
- **Surface not measured:** score = 10 if the repository is versioned, otherwise 0.

For example: a versioned library with 200 public types, 10 of them exposed, gets S = 0.6 − 0.4 × 0.1 = 0.56 and a score of 9.6. The same 10 exposed types among 40 public types give S = 0.6 − 0.4 × 0.5 = 0.4 and a score of 8.0.

## Not measured when
- The repository publishes no library (for example an application, a service or a packaged tool). It is out of scope and is not penalised.
- None of the repository's packaging declarations can be read for its stack, so there is no way to tell whether it publishes a library. The dimension is reported as not measured, not as 0.

## What the result is not
- It is not a size measure. A large public surface costs nothing by itself: the score falls only when exposed types exist, and the number of public types matters only as the denominator of their share (2E/P). The share of all types that is public plays no part.
- It does not check that versions follow semantic versioning rules, or that breaking changes were released as major versions. It only checks that a version is stated explicitly.
- "Used only inside its own library" reads only consumers inside the repository. A type that only outside consumers use can be counted as exposed.
- It does not judge whether the API is well designed, documented or stable over time.
