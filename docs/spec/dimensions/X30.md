# X30: Support guard that admits what it rejects

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property

Whether a guard written as the negation of a logical OR of two or more terms, which mixes capabilities the code needs (for example true/false flags) with a fault it refuses (for example a test that a value is not equal to a constant), says what its author meant. By De Morgan's law the negation of an OR is the AND of the negated terms, so, for example, `!(a || b || x != k)` with `k` a constant means `!a && !b && x == k`: an early-exit guard (one that leaves before the code it protects) turns inside out, firing only where every capability is absent and the value equals the constant, and letting every value the fault term was meant to refuse (here every x other than k) into the code that cannot handle it, whatever the capabilities. A negated OR whose terms are all capabilities or all faults is not this; a finding marks logic that contradicts the guard's evident intent, not a confirmed runtime failure.

## Applies to

Any programming language that has a logical negation, a logical OR and an inequality test, written the way that language writes them. For example: C#, Java, Kotlin, Scala, Dart, Go, Rust, JavaScript and TypeScript (`!(a || b)`), Python (`not (a or b)`), Ruby (`!(a || b)`, `not (a || b)`, or `unless a || b`), PHP (`!(a || b)`), and Erlang (`not (A orelse B)`). In a single-file component (for example Vue or Svelte), only its script counts.

## Population

Production code as [production-code.md](../production-code.md) defines it, in the languages above. This dimension has no exclusions of its own.

## Unit and denominator

- **Site (the denominator):** each negation applied directly to an OR of two or more terms. Terms are counted through nested parentheses, so `!(a || (b || c))` is one site with three terms. Every such negation is one site, wherever it appears. A negated AND is not a site.
- **Guard:** a condition, or one term of a condition, of a branch that leaves or refuses before the code it protects (for example it returns, throws, breaks or continues). A negated OR that is returned or assigned as a value (for example `return !(p.method || p.kind !== "init")`) is a classifier, not a guard.
- **Capability term:** a term that reads a true/false value, written as a bare name or a member read (for example `isRgba` or `format.IsRgbaOrder`). Where the language reads a property through a zero-argument accessor (for example Java's `format.isRgbaOrder()`), that accessor counts as the read. A comparison with the language's null, absent or unset value is a presence check, and it also counts as a capability term. Examples: `x != null`, `x !== undefined`, `x != nil`, PHP's `x !== false`, or Go's `x != ""` where the empty string means "unset". A call that takes arguments is a predicate, not a capability. A term that is itself negated (`!b`) is not a capability term.
- **Fault term:** a term of the form `x != k` (or the language's own inequality, for example `!==`, `=/=` or `/=`), where `x` is a value and `k` is a constant: a literal other than the null, absent or unset value, an enumeration member or a named constant. Equality tests (`x == k`) and ordering comparisons (`<`, `>=`) are not fault terms.
- **Finding (the unit):** a site that is (part of) the condition of a guard and has at least one capability term and at least one fault term. A site counts once, however many terms of each kind it has.

## Thresholds

- A site needs 2 or more terms.
- A site is a finding when it is in a guard and has 1 or more capability terms and 1 or more fault terms.

## Score

Let F be the number of findings and P the number of sites.

- F = 0: the score is 10.
- F > 0: let n = max(P, F + 1) and d = F / n. Then
  - isolation = max(0, 1 − d / 0.10)
  - headroom = min(1, max(0, log10(n) / log10(200)))
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − d) × (ceiling − 1), kept between 1 and the ceiling, rounded to 2 decimals.

So any finding caps the score at 8. Once findings reach 10 % of sites the cap is 6, and the score falls toward 1 as d approaches 1.

## Not measured when

- The production code holds no site and no finding. Code with nothing to examine does not score 10.
- The repository holds no production code in a language this dimension reads.
- None of the production code in these languages could be read. If only some of it could be read, the dimension is scored on the code that was read, and the result lists the files that could not be read.

## What the result is not

- It is not proof of a runtime failure. A finding marks a guard whose logic contradicts its evident intent.
- It does not judge negated ORs whose terms are all of one kind, negated ORs used as values rather than guards, or capabilities read through a call that takes arguments.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Density of 10 %:** the share of findings among sites at which the isolation term reaches 0.
- **Population of 200:** the site count at which the headroom term reaches 1.
- **Ceiling 6 to 8 and floor 1:** the best score with any finding is between 6 and 8, and the lowest is 1.
- **Denominator floor F + 1:** the site count used is never less than findings plus one.
