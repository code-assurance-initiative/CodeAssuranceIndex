# X28: Index access outside its own emptiness guard

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether a condition that tests a value for emptiness (for example a null-or-empty check, a length or count compared with a constant, or an any-element check) indexes that same value only where the test has established that it is not empty: for example, an or placed one parenthesis too far to the left can leave one index access outside the guard while another stays inside it, so the empty case the guard exists to anticipate reaches the index and fails.

## Applies to
Any programming language that can read a sequence, string or tuple by position and has short-circuit boolean operators (and, or). Examples include C#, Visual Basic .NET, F#, Java, Kotlin, Scala, Swift, Dart, Go, Rust, Python, Ruby, PHP, JavaScript, TypeScript, Elixir and Erlang.

## Population
Production code as [production-code.md](../production-code.md) defines it. In addition:

- **Conditions:** a condition is one whole boolean expression joined by short-circuit and/or, however many operators it holds. Examples are the header of an `if` or a `while`, or such an expression anywhere else. A condition nested inside another as one of its operands is part of the outer condition, not a second one.
- **Guards that fail quietly:** some languages make a guard fail instead of raising an error when an error happens inside it. In those languages such a guard is not a condition for this dimension. Examples are Erlang guards, including every Erlang `if`, and Elixir `when` clauses.
- **Indexed values:** the indexed value must be a plain local name, parameter or field. An access whose indexed value is itself a member read or a call result (`a.B[0]`, `f()[0]`, `a.b.charAt(0)`) is out of scope, because each evaluation may return a different object. A positional read written as a call on a plain name (`s.charAt(0)`, `hd(L)`) is in scope.
- **Deferred code:** an index access or an emptiness test inside an anonymous function within the condition is out of scope, because it does not run where it is written.
- **Accesses safe when empty:** a slice or range access whose bounds are valid for every length, including zero, is out of scope (for example `s[0..]`, `s[..^0]`, or any Python slice). `s[1..]` and `s[..^1]` fail on an empty value, so they stay in scope.
- **Values the condition never tests:** an index access to a value that the same condition does not test for emptiness is out of scope. It is not counted and not judged.

## Unit and denominator
- **Index access:** a read of one element of a sequence, string or tuple by its position, or of a range of its elements. It may be written with the language's subscript syntax (`s[i]`) or as a positional read from the language or its standard library. Examples are `s.charAt(i)` and `list.get(i)` in Java; `hd(L)`, `element(N, T)`, `lists:nth(N, L)`, `binary:at(B, N)`, `binary:first(B)` and `binary_part(B, P, L)` in Erlang; `hd(xs)`, `elem(t, i)`, `binary_part(s, i, n)`, `:binary.at(s, i)`, `Enum.fetch!(xs, i)`, `Enum.at(xs, i)` and `String.at(s, i)` in Elixir. The indexed value is the sequence being read, not the position. A lookup by key in a map or dictionary (for example `m["k"]`, `d[key]` on a dictionary, or a Java `Map`'s `get`) is not an index access.
- **Emptiness test:** a test that, on one of its outcomes, shows in the language's own terms that the value is not empty. These are the kinds:
  - A null-or-empty, empty or blank check, as the language, its standard library or a common library defines it. Examples are `string.IsNullOrEmpty(s)`, `isEmpty()`, `isNullOrEmpty()`, `isBlank()`, `is_empty()`, `empty?`, `blank?`, Scala's `isEmpty`, PHP's `empty($s)`, `StringUtils.isEmpty(s)`, and equality with the empty value (`s == ""`, `s.equals("")`, `L =:= []`). These show the value is not empty when false.
  - A non-empty check: an is-not-empty check (for example `isNotEmpty()`, `nonEmpty`, `present?`), an any-element check with no predicate (for example `s.Any()`, `any()`, `any?`, `Enum.any?(xs)`), or inequality with the empty value (`s != ""`, `L =/= []`). These show the value is not empty when true.
  - A truth-value test, in a language where an empty value is false: the value itself, or its length or count, used as a truth value. Examples are `s` or `len(s)` in Python, `$s`, `strlen($s)` or `count($a)` in PHP, and `s.length` in JavaScript and TypeScript. These show the value is not empty when true, so `not s` and `!s.length` show it when false. In a language where an empty string or list is true (for example Ruby, Elixir), the bare value is not an emptiness test.
  - A comparison of the length or count n with an integer constant b:
    - `n > b` with b >= 0, or `n >= b` with b >= 1: not empty when true;
    - `n < b` with b >= 1, or `n <= b` with b >= 0: not empty when false;
    - `n != 0`: not empty when true; `n == 0`: not empty when false.

    No other length or count comparison is an emptiness test, even one whose outcome implies a non-empty value (for example `n == 1`, `n != 1` or `n >= 0`). The constant may stand on either side (`0 < n` is `n > 0`).

  A test that shows only that the value is not null (`s != null`), or that reads its first or last element, is not an emptiness test.
- **Covered access:** an index access to the value is covered in either of these cases:
  - An enclosing and/or step has the access in its right operand, and its left operand proves the value is not empty whenever the right operand runs. An and runs its right operand only when its left operand is true. An or runs its right operand only when its left operand is false.
  - The access is in one branch of a conditional expression (`c ? a : b`) inside the condition, and `c` proves the value is not empty for that branch: true for the first branch, false for the second.

  Every other access to the value in the condition is uncovered.
- **Site (denominator):** a pair made of a condition and a value that the condition both tests for emptiness and indexes. Nothing else is a site.
- **Finding (numerator):** one uncovered index access at a site that also holds at least one covered access to the same value. Each access is counted separately, so one site can hold several findings.
- **Length already established:** an uncovered access does not count when both of these hold:
  - The weakest length the condition's tests prove is greater than the length the access needs, so the guard was written for a different, longer access. `s[k]` with a constant k needs k + 1, and any other access needs 1. The proved length is b + 1 for `n > b` and `n <= b`, b for `n >= b` and `n < b`, and 1 for every other emptiness test.
  - A statement before the condition's statement has already established at least the needed length. That statement is in the same block or in a block that encloses it, within the same function. It is an `if` with no `else` whose body only leaves (return, throw, break, continue) and whose condition, when false, proves the length.

  This rule does not apply if the value is reassigned anywhere in that function. If the guard proves no more than the access needs, the earlier statement makes the guard dead, and the finding stands.
- **Languages where reading past the end does not fail:** in some languages an out-of-range read gives a missing value instead of failing. For example JavaScript and TypeScript give `undefined`, PHP gives `null` or `''`, Ruby gives `nil`, and Elixir's `Enum.at` and `String.at` give `nil`. In these languages, and for these reads, an uncovered access counts only when the condition uses its result in a way that fails on the missing value:
  - in PHP, only a call through the result (a method call, a static call, or calling it as a function). This includes a call after a chain of property reads, but not one after a nullsafe `?->`;
  - in every other such language, a member access or a call through the result. A null-safe access (for example `?.` in JavaScript and TypeScript, `&.` in Ruby) does not count, because it gives the missing value instead of failing;
  - in JavaScript, TypeScript and Ruby, also an index on the result;
  - in Ruby, also arithmetic or ordering on the result;
  - in Elixir, also any of these on the result: arithmetic, string concatenation (`<>`), list subtraction (`--`), a range, the left side of a list append (`++`), or either side of the text-match operator `=~`.

  In Elixir, equality and ordering on nil do not fail, and indexing nil gives nil.

## Thresholds
- A site with only uncovered accesses and no covered access to the same value gives no finding. It still counts as a site.
- A site with only covered accesses gives no finding and counts as a site.

## Score
Let F be the number of findings and S the number of sites, and let N = max(S, F + 1).

- If F = 0, the score is 10.
- Otherwise, let d = min(F / N, 1).
- isolation = max(0, 1 − d / 0.10)
- headroom = min(max(log10(N) / log10(200), 0), 1)
- ceiling = 6 + 2 × isolation × headroom
- score = 1 + (1 − d) × (ceiling − 1), kept within [1, ceiling] and rounded to 2 decimals.

With any finding the ceiling is at most 8, so the score is at most 8. Before rounding, the score is always below the ceiling. Once findings reach 10 % of N the ceiling is 6, so the score is at most 5.5, and it falls further as findings rise.

## Not measured when
- The production code holds no site and no finding.
- The repository has no production code in a language this dimension applies to.

## What the result is not
- No published score includes it today, because the one existing engine reports it advisory.
- It does not check that every index access is safe. An index access that no test in its own condition guards is not judged.
- It does not prove a crash. A finding means the condition contradicts itself: either the guard is needed and the uncovered access fails on an empty value, or the value cannot be empty and the guard is dead.
- A condition that holds only the broken access, with no correctly guarded access to the same value beside it, is not reported. The standard accepts this loss of recall.
- Apart from the "length already established" rule, nothing outside the condition is read. A guard set up by an earlier statement neither removes a finding nor creates one. An access on the empty side of a statement elsewhere in the function, an access before its guard, and an off-by-one bound are not judged.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Denominator floor:** N = max(S, F + 1).
- **Density at which isolation is gone:** 0.10.
- **Size at which headroom saturates:** 200 sites, on a log10 scale.
- **Ceiling with any finding:** 6, raised by up to 2 for an isolated finding in a large population.
- **Lowest score with findings:** 1.
