# D28: Secrets (history)

**Lens:** securityCompliance · **Scored:** yes

## Property
Whether any secrets were ever committed — scanned across the full git history, not just now.

## Applies to
Any language and any file kind, text or binary. This covers source code, configuration, scripts, data files, and key files stored as bytes (for example a raw private key file, or a key-store container such as a PKCS#12 or Java key store).

## Population
- **Which commits:** every commit that any of the repository's branches, tags or other references can reach, whether or not it is an ancestor of the analysed commit. The files of the analysed commit itself are also read. The commit limit in [people.md](../people.md) does not apply here.
- **Which files:** this dimension does not use production code as [production-code.md](../production-code.md) defines it. It reads every file kind, including configuration and data.
- **Which path decides scope:** a secret is out of scope when the path it had in the commit that holds it is out of scope. It is also out of scope when that same content now sits only at out-of-scope paths. A file that no longer exists is judged by its path in history.
- **Not in scope:**
  - Tests and test support, as [production-code.md](../production-code.md) defines them. This includes test code that sits inside a production file and never ships with it (for example a Rust `#[cfg(test)]` module, or a package recipe's own test block).
  - Examples, samples and demonstrations, and seed or factory data. Unlike [production-code.md](../production-code.md), this dimension leaves these out.
  - Documentation, with one exception. An armoured private key that includes its key body still counts when it appears in documentation the repository's own authors wrote. The other exclusions in this list still apply to it.
  - Placeholder and template configuration that holds no real values (for example `.env.example`), and configuration meant only for a developer's own machine.
  - Lockfiles, build output and copies of build output.
  - Generated and vendored content, but only where the repository itself declares it so (for example in its attributes or editor settings).
  - Paths that the repository's own secret-scanning configuration declares to be reviewed content with no secrets. The result states how many findings this removed.

## Unit and denominator
- **Unit: a secret.** A value that gives whoever reads it access, signing power or decryption power. For example: an API key or access token, a password, a signed token, a private key (as text or as bytes, including one stored in a key-store container), or a password hash in production configuration.
- **Production configuration:** configuration that the shipped product or its deployment loads at run time. Test, example, template and local-developer configuration is not production configuration.
- **Not a secret:** a value that is public by design or grants nothing. For example: a public key or the public half of a key pair, a search-only key, a captcha site key, an unsigned token, a fingerprint, a checksum or content digest, a ciphertext that only a hosted service can decrypt, an identifier that only looks like a key, or a published example value. A key store that holds only trusted certificates holds no secret.
- **Reported but not counted:**
  - an access key ID with no secret key beside it;
  - a key in a format that secret keys also use, where the file uses it only to search;
  - a password hash outside production configuration.
- **One secret per value per file.** A value counts once for each file that held it. It does not matter how many commits held it, or whether the analysed commit still holds it. A file that was renamed or moved is the same file, so its value counts once, at the file's latest path. The same value in two different files counts twice.
- **Denominator:** none. The score uses the absolute count over the whole history.

## Thresholds
- An armoured private key in the authors' documentation counts only if it includes a key body. A header wrapped around a placeholder does not count.
- A password hash counts only in production configuration.
- Every other secret in scope counts as soon as one commit holds it.

## Score
- n is the number of counted secrets.
- score = max(0, 10 − n)
- Each counted secret costs 1 point. A history with no secrets scores 10. A history with 10 or more secrets scores 0.

## Not measured when
- The history, or the files of the analysed commit, could not be read in full.
- The repository has no history to read.

## What the result is not
- It does not prove that no secret was ever committed. A secret in a format nobody has described yet is not found.
- It does not say whether a secret is still live. A secret that was rotated, expired or revoked still counts, because every clone still holds it.
- It does not cover commits that are no longer in the repository, for example history that was rewritten.
- It does not grade severity. A cloud root key and a minor service token each cost 1 point.
- It is not a check of the current files alone. Deleting a file does not remove its secret from the score.
