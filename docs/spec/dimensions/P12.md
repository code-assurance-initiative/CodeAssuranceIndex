# P12: CI test-gate honesty

**Lens:** productionReadiness · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property

Whether the CI gate executes the test inventory it appears to have: excluded suites, skipped tests, and coverage collected without a threshold.

## Applies to

Any language and any CI system. The dimension reads two things:

- the CI pipeline definitions committed to the repository (for example workflow files of a hosted CI service);
- the test inventory those pipelines are meant to run: the tests, the test projects and the test runner configuration, in any language.

It also reads the committed coverage configuration (for example a coverage tool's settings file or a test runner's configuration).

## Population

- **Pipelines:** every CI pipeline definition committed to the repository. A pipeline that exists only in a hosting service's settings, and not in the repository, is out of scope.
- **Test inventory:** the repository's tests and test support, meaning the code that [production-code.md](../production-code.md) excludes from production code as tests and test support. A test project or package that belongs to the repository's own suite is in scope. Test code kept as test data, a fixture or a sample, and not meant to be run by the pipeline, is out of scope.
- **What counts as a test, a skip or a sleep:** only code that compiles. Text inside a comment or a string literal is not a test, a skip or a sleep. Examples are commented-out code and source text held as a test fixture.
- **Merge gate:** a CI run that runs on a change before it merges and fails on that change. Examples: a run triggered by a pull or merge request, a merge queue, or a push to any branch. These are not merge gates: a run triggered only by a schedule, a run triggered only by a push to the default or release branches, and a run that happens only under a condition that is false on pull requests. A step or job that is allowed to fail is not a merge gate either.

## Unit and denominator

The unit is a **finding**: one site in the repository where the merge gate does not run the inventory, or does not fail when the inventory fails. Where one line causes the finding, the finding is placed at that line. Each site gives at most one finding. There is no denominator.

The findings and their levels:

| Finding | Level |
|---|---|
| A test command's failure does not fail the gate (its exit status is thrown away, or its step or job is allowed to fail) | Warning |
| A gating filter or selection drops tests that no other merge gate runs | Warning; Info when the repository documents the dropped suites as opt-in |
| Tests run only outside the merge gate | Warning |
| Every test-running pipeline runs only after the merge (none runs before a merge) | Warning |
| A test-running pipeline whose branch filter names no branch the repository has, so its tests never run on the default branch or on its pull requests | Warning |
| A test project or workspace package with tests that no CI command runs | Warning |
| Test sources removed from their project's build, or test files excluded by a runner configuration, where no other runner or command runs them | Warning |
| A shard or split matrix that runs only some of its parts | Warning |
| A gating selection that matches no test yet passes, or that selects only the tests of uncommitted changes | Warning |
| A merge-gate test command whose target holds no test, run by a test runner that passes when it finds none | Warning |
| A pull-request path filter, or a changed-file allow-list, that skips the gate for source the tests are built from or depend on | Warning |
| A coverage upload whose job produces no report | Warning |
| Coverage is collected, but no committed floor fails the build when coverage drops | Warning (one per repository) |
| Coverage is uploaded, or a coverage floor is enforced, only outside the merge gate, and no gating run enforces a floor | Warning |
| A pipeline that re-runs itself when the gate fails, until a run is green | Warning |
| Tests marked skipped in code, counted across the inventory | Info (one per repository, with the count) |
| Sleep-based synchronisation in test code, counted across the inventory | Recommendation (one per repository, with the count) |

A **coverage floor** is any committed setting or step that fails the build when coverage falls below a value. Examples: a coverage tool's minimum-threshold option, a coverage service's required status target, or a step that compares the coverage number and exits with failure.

A **sleep** is a call in test code that waits a fixed time to synchronise with other work. These are not sleeps:

- a wait inside a loop whose condition tests something (polling with a deadline);
- a wait that never runs out;
- the timeout side of a race against a completion signal.

## Thresholds

- **Sleep-based synchronisation:** reported when the inventory holds 5 or more sleeps.
- **Skipped tests:** reported when the inventory holds 1 or more skipped tests.
- **Shard or split matrix:** checked when the matrix declares a total of 2 or more parts. It is reported when at least one part from 1 to the total is not run.
- **Every other finding:** reported at 1 site.

## Score

No score curve is defined: the one existing engine reports findings only, with no 0-10 reading.

## Not measured when

- The repository commits no CI pipeline definition. The result is "no CI workflow".
- Some findings compare the gate with the inventory. Such a finding is not made when the repository does not show what a CI command runs, for example a command whose targets or wrapper scripts cannot be followed, or a target folder that is not in the repository. In that case the absence of the finding means "not judged", not "clean".

## What the result is not

- It is not a judgement of test quality, test coverage or test count. Other dimensions read the test code itself.
- An exclusion the repository documents as opt-in is still reported, at Info. The gap between the gate and the inventory is real even when it is intended.
- A coverage floor set only in a coverage service's web settings, and not in a committed file, is not seen. So "coverage collected but not gated" can be reported for a repository that does have such a floor.
- No findings does not prove the gate is honest. It means that none of these sites was found.
- A skip is counted, not judged. Whether each skip's reason is acceptable belongs to another dimension.

- **Sleep-based synchronisation:** the threshold of 5 sleeps is a parameter of the existing reading's model. A later decision under decision 0013 will replace it with a threshold on the property.
