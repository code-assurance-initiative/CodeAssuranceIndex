# D14: License Compliance

**Lens:** productionReadiness · **Scored:** yes

## Property
Whether the licenses of third-party packages are compatible with your policy.

## Applies to
Any language. The dimension covers the third-party packages a repository depends on, as its package manifests and lockfiles declare them (for example NuGet, npm, PyPI, RubyGems, crates.io, Hex, Maven, Go modules, SwiftPM, pub, Packagist). It also covers third-party code the repository ships with no manifest entry. The dimension does not judge the repository's own source files.

## Population
The population is the third-party code that ships with what the repository delivers to its users:

- **Shipped dependencies:** the packages that a person using the repository installs. These are the production (runtime) dependencies the repository declares, any optional or peer dependencies that person installs, and everything those bring in, direct and transitive. Each is taken at the version the repository resolves.
- **Third-party packages from a source repository:** a third-party package taken from a public source repository URL rather than from a registry (for example a SwiftPM package or a Go module) is in scope. Its licence is the one its source repository declares.
- **Shipped undeclared third-party code:** third-party code inside the repository that no manifest names. Examples are a library copied or vendored into the tree, a package a bundler inlined into committed build output, and a compiled module built from another project's source. [production-code.md](../production-code.md) does not count this code as production code. It is in scope here because it ships under its upstream licence.

Out of scope:

- Development, test, build-only and tool-only dependencies, and every package that only they bring in. Examples are `devDependencies`, a development gem group, test-scoped Maven artifacts, a Go module that only a declared Go tool requires, and a Swift package that only test, plugin or macro targets use.
- The repository's own packages and its organisation's internal packages, for example a private registry scope or a package internal to the workspace.
- The repository's own licence. The authors choose it, and this dimension does not judge it.

## Unit and denominator
The unit is a **banned third-party package**: one distinct package or component in the population whose licence is in the banned set (see Thresholds). Each package counts once, however many manifests, versions or copies bring it in.

A package's licence is the licence it publishes for the version the repository uses. A package may publish several licences. The user may then choose among them, so they are read as if joined with `OR`.

There is no denominator. The score depends only on how many banned packages there are, not on how many packages there are in total.

## Thresholds
- **Banned set.** The banned set is GPL-2.0, GPL-3.0, AGPL-3.0 and LGPL-3.0, in every variant of each (for example `-only`, `-or-later`, `+`). Matching ignores case and starts at a token boundary, so `LGPL-2.0-only` does not match `GPL-2.0`. Every other licence is permitted, including LGPL-2.1, MPL and every permissive licence. A score computed with any other banned set is not a CAI D14 score.
- **Common spellings.** A common non-SPDX spelling of a versioned GPL, LGPL or AGPL licence means that licence (for example `GPLv3`, `GPL v3`, `AGPLv3`, `LGPL v2.1`, `GPL-2+`, `GPLv3 or later`). A version with no minor part means `.0`. A GPL name with no version stays as written and is not banned.
- **Licence expressions** are read as SPDX expressions:
  - `A OR B` is a choice. It is banned only when every branch is banned.
  - `A AND B` applies every operand. It is banned when any operand is banned.
  - `A WITH exception` is judged on `A` alone. An exception never makes a licence banned.
  - An expression that is not valid SPDX is banned when a banned licence appears anywhere in it, under the matching rule above.
- **No licence.** A package that publishes no licence is treated as missing data. Examples are a licence field that is absent or says `UNLICENSED`, and a package whose licence its place of publication does not supply (for example a package on a private feed). It is not banned and does not count. The result names it.

## Score
`score = clamp(10 - 2 × banned, 0, 10)`, where `banned` is the number of banned third-party packages.

| Banned packages | Score |
|---|---|
| 0 | 10 |
| 1 | 8 |
| 2 | 6 |
| 3 | 4 |
| 4 | 2 |
| 5 or more | 0 |

## Not measured when
- **Nothing to grade.** The repository declares no third-party dependency that ships, and it ships no third-party code. The result is "not applicable", not a 10.
- **Unknown packages or licences.** The repository declares dependencies in an ecosystem where its packages or their licences cannot be established.
- **Licence source unreachable.** The place where a package publishes its licence could not be reached, so it is not known whether that package publishes a licence. No verdict is given on the rest of the set. A package whose place of publication was reached and that publishes no licence is a different case: it is left out of the count (see Thresholds). The NuGet cap under Pending re-definition is the only case where part of the set is scored.
- **Unclear whether it ships.** A package with a banned licence is found, but it cannot be established whether it ships or is reached only through development, test or tool dependencies.
- **Set too large.** The Python dependency set is larger than the cap under Pending re-definition.

## What the result is not
- It is not legal advice or a licence audit. The banned set is a policy, not the law. A licence banned here may be acceptable in some uses, for example an unmodified LGPL-3.0 library installed as a separate package. Such a finding is an exception to record, and not always a defect to fix.
- It does not check that a declared licence is correct. It trusts what the package publishes. A package with no declared licence passes with no deduction.
- It does not check other licence duties, such as attribution and notice requirements. It does not check for conflicts between the licences of different dependencies.
- It does not judge the repository's own licence.
- A 10 does not mean every dependency's licence is known. Packages that publish no licence are not counted, and neither are the repository's own or its organisation's internal packages.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **NuGet dependency set:** this applies when the shipped NuGet dependencies are found by following each package's own dependencies, rather than taken whole from a lockfile. Every package the repository declares or locks is graded, even when there are more than 250. Packages that are reached only through other packages' dependencies are added one level at a time (breadth-first, starting from the declared and locked packages) until 250 distinct packages are known in total. Packages reached after that point are not graded, and the score is given on the set reached.
- **Python dependency set:** a shipped Python dependency set of more than 500 packages is not scored.
