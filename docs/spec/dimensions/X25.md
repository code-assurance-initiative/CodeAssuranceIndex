# X25: Inert configuration knob

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property

Whether a value the caller is invited to supply is the value the type actually uses: a constructor parameter stored in a private field that nothing reads, while the default it was given is written out again where the field should have been read; a lookup by key that falls back to a different setting than the one its key names, while elsewhere the same type falls back to the matching setting for that same key; or a culture-sensitive parse given no culture by a type that passes its own settable culture to the same kind of parse elsewhere. In each case a value someone supplies is silently replaced by another.

## Applies to

This applies to any language that has types holding private state or looking up settings by key. The third case (culture) applies only where a parse of numbers or dates can take a culture or locale as an argument (for example C#, or Java with its `Locale`). It does not apply where a parse takes no culture or locale at all (for example JavaScript's `Number`).

## Population

The population is production code as [production-code.md](../production-code.md) defines it. Nothing beyond that page is excluded.

Three kinds of site are in scope. Each one counts whether or not it is broken:

- **Defaulted knob:** a private, non-static field that a constructor of the same type sets from one of its own parameters, with a fallback default for when the caller supplies none. The default must be a constructed value (a call, a member access, an object creation) or a static or constant value the type itself declares (for example `?? s_defaultOptions`). Each such field is one site.
- **Keyed fallback:** a lookup call that names its key with exactly one string literal and falls back to a member of another value when the lookup gives nothing (for example `Get(args, "max_tokens") ?? settings.MaxTokens`). Each such fallback is one site.
- **Honoured culture knob:** a type that exposes a culture setting callers can change, and that passes this setting to at least one culture-sensitive parse. The setting is either a non-private culture or format-provider property with a setter callers can use, or a non-private field of that kind that is neither read-only nor constant (static is allowed). Each such type is one site.

A culture-sensitive parse is a parse of a date or time value, or of a real number, whose result depends on the culture (for example in C#: `DateTime`, `DateTimeOffset`, `TimeSpan`, `decimal`, `double`, `float`).

## Unit and denominator

**Unit:** an inert-knob finding is one of these:

- **Defaulted knob:** nothing anywhere in the type reads the field (a write that replaces its value is not a read), and the same default expression, ignoring whitespace, appears again in the type outside the constructor that set it. One finding per field.
- **Keyed fallback:** the member it falls back to does not match its key, while another fallback in the same type, for the same key, goes to the matching member. One finding per site that disagrees. "Same type" means the innermost enclosing type. Code outside every type counts as one scope per file.
- **Culture parse:** in a type that has an honoured culture knob, a culture-sensitive parse that is given no culture at all (for example `DateTimeOffset.Parse(s)` or `double.TryParse(s, out v)`). One finding per parse. Parses that always take a culture (for example `ParseExact`) are never findings.

**Denominator:** the number of sites in the population across the repository, summed over the three kinds. Call the findings *n* and the sites *N*.

## Thresholds

- **Keys and members match** when they are equal after both are reduced to their letters and digits in lower case (for example `"max_tokens"` matches `MaxTokens`, and `TopK` matches neither).
- **A disagreeing fallback is not a finding** if either folded name contains the other (for example `"timeout"` falling back to `DefaultTimeout`).
- **A lookup with two or more string-literal arguments** is not in the population, because it is unclear which literal is the key.
- **Integer parses** (for example `int.Parse`) are not culture-sensitive parses here.

## Score

Let *D* = max(*N*, *n* + 1).

- If *n* = 0, the score is 10.
- Otherwise:
  - density *d* = *n* / *D*
  - isolation = max(0, 1 − *d* / 0.10)
  - headroom = min(1, max(0, log10(*D*) / log10(200)))
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − *d*) × (ceiling − 1), clamped to [1, ceiling] and rounded to 2 decimals.

Any finding at all caps the score at 8. The cap is 6 once density reaches 10 %, and also when *D* is 1. As density rises, the score falls towards 1.

## Not measured when

The dimension is not measured when the population is empty: the production code has no defaulted knob, no keyed fallback and no honoured culture knob, and there are no findings. Not measured is not the same as a 10.

## What the result is not

- It is not a dead-code count. A private field that nothing reads, with no second copy of its default, is a site but never a finding.
- It is not a lint for missing cultures. A parse with no culture is a finding only in a type that passes its own settable culture to such a parse elsewhere.
- It does not say which of the two disagreeing spellings the authors meant. It only says the type contradicts itself.
- It does not see a convention that is kept in another type or another file.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Defaults that are bare literals** (for example `?? 0`, `?? ""`, `?? false`) are left out of the defaulted-knob population.
- **Containment between folded names** cancels a disagreeing keyed fallback.
- **Keys are read only from lookups with exactly one string literal.**
- **Integer types are left out** of the culture-sensitive parses.
