# M1: Documentation (README)

**Lens:** maturity · **Scored:** yes

## Property
Whether the repository and its projects have a README, and whether it is substantive.

## Applies to
Any language. The dimension reads documents, not code. A README counts in any of these formats: plain text with no extension, Markdown (`.md`, `.markdown`), text (`.txt`), reStructuredText (`.rst`), AsciiDoc (`.adoc`, `.asciidoc`), Org (`.org`), RDoc (`.rdoc`), HTML (`.html`, `.htm`), PDF (`.pdf`) and Word (`.doc`, `.docx`). In every format, a README's words and headings come from the document's own text. A heading is a heading as the document's format defines it.

## Population
- **The repository README:** a file named `README` in any letter case, in one of the formats above. It must be in the repository root or directly inside one of these top-level folders: `src`, `source`, `docs`, `doc`, `documentation`, `documents`, `.github`. The locations are checked in that order, and the first README found is the repository README. If a repository arrives wrapped in a single top-level folder, that folder is the root.
- **Documents the README links to:** the documents inside the repository that the README links to with relative links. These are inline links, reference links and HTML `href`. Only those links are followed, not links inside the linked documents. A link to a folder reaches that folder's README. A link that leaves the repository (a URL with a scheme, or a protocol-relative URL) reaches nothing. So does a link to an anchor in the same page. A link to the README itself, with or without an anchor, is not a linked document. Each linked document counts once, however many links reach it. A linked document counts only when it is readable text: Markdown, text, reStructuredText, AsciiDoc, Org, diagram text (`.mermaid`, `.mmd`) or HTML.
- **Projects:** every folder below the repository root that holds its own project or package manifest, for example a .NET project file, `Cargo.toml`, `package.json`, `go.mod`, `pom.xml`, `build.gradle`, `pyproject.toml`, `composer.json`, `mix.exs`, `Package.swift`, `pubspec.yaml`, `build.sbt` or `rebar.config`. Some projects are not counted: test projects (tests as [production-code.md](../production-code.md) defines them), vendored code, and build output and tool state.
- **The root folder** is not a project, and a README in the root folder never documents a project. A repository README in one of the listed top-level folders (for example `src/README.md`) is also that folder's README. It documents projects under the rules below like any other README.

## Unit and denominator
- **Words:** the number of whitespace-separated words in the README's text. For HTML, only the visible text counts: tags, scripts, styles and comments do not count, and entities are decoded.
- **Sections:** a newcomer needs three sections. A section is *reached* when the README, or a document it links to, has a heading that names that section's subject:
  - **Run:** installing, building, running or starting to use the project. Headings such as "Getting started", "Quick start", "Usage", "Install", "Build" and "Run" name it.
  - **Test:** the project's tests. Headings such as "Test" and "Tests" name it.
  - **Architecture:** the project's design and layout. Headings such as "Architecture", "Design", "How it works", "Project map", "Structure" and "Layout" name it.

  These headings are examples, not a closed list. A heading names a subject in any word form and any letter case. For example, "Testing" and "Running the tests" reach Test. "Installation", "Building from source" and "Running" reach Run. "Designing" reaches Architecture. A subject word that only appears inside an unrelated longer word does not count. For example, "Latest" does not reach Test and "Runtime" does not reach Run.
- **Routed README:** a README is routed when all three of these hold:
  1. All three sections are reached.
  2. At least one section is reached through a linked document.
  3. The README's words, plus the words of every linked document that reaches at least one section, total 120 or more.
- **Documented project:** a project is documented when its own folder (the folder that holds its manifest) has a README. When the project's parent folder is not the repository root, two more READMEs also count:
  - a README in the parent folder;
  - a README in a sibling folder whose name, followed by `.`, begins the project's folder name. For example, `src/Lobby/README.md` documents `src/Lobby.Contracts` and `src/Lobby.UI`.

  When the parent folder is the repository root, only a README in the project's own folder counts. These rules apply even when the README they find is also the repository README. For example, when the repository README is `src/README.md`, it documents `src/Foo`, and it documents a project whose manifest is in `src` itself.
- **Denominator:** README coverage is the number of documented projects divided by the number of counted projects.

## Thresholds
Routing comes first. A routed README is substantive, whatever its own word count. Any other README is:
- empty at 0 words;
- a stub at 1 to 24 words;
- thin at 25 to 119 words;
- substantive at 120 or more words.

## Score
The score is the sum of three terms. The sum is rounded to one decimal (half to even) and kept between 0 and 10.

1. **Substance:**
   - routed README, at any word count: 6.0
   - otherwise, 120 or more words: 6.0
   - otherwise, 25 to 119 words: 4.0
   - otherwise, 1 to 24 words: 2.0
   - no README, or a README with 0 words: 0.0
2. **Sections:** 2/3 for each of the three sections reached, so 0 to 2.0. This term is 0 when there is no README.
3. **Project coverage:** 2.0 × documented projects / counted projects. This term is 0 when there are no counted projects.

A repository with no counted projects can score at most 8.0. Without a README, substance and sections are both 0, but project coverage can still add up to 2.0.

## Not measured when
None. Every repository is measured.

## What the result is not
- It does not say whether the README is accurate or up to date. A separate dimension judges accuracy.
- It does not judge the quality of the writing. It looks only at whether a README exists, how many words it has and what its headings name. Material under a heading that names none of the three subjects, or under no heading at all, earns no section credit.
- It does not measure how recently the README changed.
- A README that says the project is no longer maintained is not marked down for saying so.
