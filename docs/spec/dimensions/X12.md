# X12: Unreachable branch

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether any branch is dead by construction, that is, can never run whatever the input, from the code alone: a switch label that can never equal the switch's subject because the code converts the subject to one letter case and the label has letters in the other case (for example an upper-case or mixed-case label against a lower-cased subject); or an else-if arm whose condition can be true only when the condition of an earlier arm in the same chain is also true, so every input that would satisfy it is already taken by that earlier arm (for example an earlier test that a string contains "ab" before a later test that it contains "abc"). An arm that only partly overlaps an earlier one is not dead. Not a general dead-code or coverage measure.

## Applies to
Any programming language that has a multi-way branch on one value (for example `switch`, `match`, `case` or `when`) or a chain of `if` and `else if` arms (for example `elif` or `elsif`). Markup (HTML) and styles (CSS) are out of scope.

## Population
Production code as [production-code.md](../production-code.md) defines it. This dimension adds no exclusions of its own. Examples, samples and the authors' own tools are in scope.

## Unit and denominator
- **Unit: a dead branch.** Each of the following counts once:
  - **Case-mismatch label:** a label of a multi-way branch whose subject is a string converted to one letter case (for example `s.ToLower()`, `s.toUpperCase()` or `s.lower()`), where the label is a string literal holding at least one letter of the other case. The branch compares by equality, so the label can never match. Each such label counts once, even when several labels share one arm.
  - **Swallowed else-if arm:** an `else if` arm whose condition implies the condition of an earlier arm in the same chain, under the comparison rule each test uses. Every input that makes it true has already been taken by that earlier arm. Each such arm counts once, even when more than one earlier arm swallows it. For example, with string tests on the same subject:
    - an earlier "contains X" swallows a later "contains Y", "starts with Y" or "ends with Y" when Y contains X;
    - an earlier "starts with X" swallows a later "starts with Y" when Y starts with X;
    - an earlier "ends with X" swallows a later "ends with Y" when Y ends with X.
  - An earlier "starts with" or "ends with" does not swallow a later "contains". An arm that only partly overlaps an earlier arm is not dead.
- **Denominator: branch sites.** Each multi-way branch on a value (statement or expression form) counts once. Each `if` statement that does not itself continue an `else if` chain also counts once. A chain counts once however many arms it has, and an `if` with no `else` counts too.
- **Count used in the score:** when the number of branch sites is smaller than the number of dead branches plus one, it is raised to that number. One chain can hold several dead arms.

## Thresholds
- A label is dead only if it holds an ASCII letter (`A` to `Z` or `a` to `z`) of the opposite case. A label whose only opposite-case letters are outside ASCII does not count.

## Score
Let *n* be the number of dead branches and *P* the number of branch sites, raised to *n* + 1 if it is smaller.

- *n* = 0: the score is **10**.
- *n* > 0:
  - density *d* = min(*n* / *P*, 1)
  - isolation *i* = max(0, 1 − *d* / 0.10)
  - headroom *h* = min(max(log10(*P*) / log10(200), 0), 1)
  - ceiling *c* = 6 + 2 · *i* · *h*
  - score = 1 + (1 − *d*) · (*c* − 1), clamped to between 1 and *c*, rounded to 2 decimals.

So any dead branch caps the score at 8. When density reaches 10 %, or the code has a single branch site, the cap is 6. The score falls toward 1 as density rises.

## Not measured when
- The production code holds no branch site and no dead branch.
- The repository has no production code in a language this dimension applies to (see Applies to).

## What the result is not
- It is not a general dead-code or coverage measure. It does not count unused functions, code after a `return`, or arms that tests never reach.
- It says nothing about arms that only partly overlap earlier arms.
- A 10 does not show that every branch is reachable. It shows only that no branch is dead in either of the two ways defined here.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Density at which isolation ends:** 10 % (0.10).
- **Branch-site count at which headroom saturates:** 200.
- **Ceiling for any dead branch:** 6, rising by up to 2 (to 8) with isolation and headroom.
- **Floor of the score when there are dead branches:** 1.
- **Denominator floor:** branch sites raised to dead branches plus one.
- **Letters that decide a case mismatch:** ASCII letters only.
