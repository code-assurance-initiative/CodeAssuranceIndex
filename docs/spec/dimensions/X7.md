# X7: Silent fallback defaults

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether parse/lookup failure paths return hard-coded constants with no logging or throw — failures that convert data errors into silent behavior changes.

## Applies to
- **Silent fallback functions:** any programming language that has functions and some way for an operation to fail, for example a caught exception, an error value, a failed parse result or an empty lookup result.
- **Pending-state components and views:**
  - UI components written in single-file component languages or in script files (for example React, Vue or Svelte components);
  - views and components that a web framework renders (for example Razor views and Razor components).

## Population
This dimension reads production code as [production-code.md](../production-code.md) defines it, with one addition. For the pending-state rule only (see Unit and denominator), it also reads views that a web framework renders on the server (for example Razor views), which [production-code.md](../production-code.md) excludes as server-side templates. All of [production-code.md](../production-code.md)'s other exclusions still apply to those views, including tests, generated code, vendored code and build output. This dimension makes no further exclusions. The limits on how many components and views are read are under Pending re-definition.

## Unit and denominator
**Unit: a silent fallback function.** A function is any named callable with a body, as the language defines it. Each getter of a property or indexer is also a function. A nested or anonymous function belongs to the function that encloses it.

A function is a silent fallback function when all of the following hold:

1. **It has a failure path.** Some branch runs only because reading or looking up a value failed. Examples: a handler for a caught exception, the branch taken when a parse or match reports failure, an error result turned into a value, or the default arm of a decode.
2. **The failure path answers with a constant.** On that path the function's answer is a hard-coded value written in the source. Examples are a number, a string, `true` or `false`, an empty collection, or the type's default value. A named constant (for example a constant field or an enum member) is also a hard-coded value. A value computed at run time is not. The caller cannot tell the constant from a value that was really read.
3. **It leaves no trail.** Nowhere in the function does the failure become visible:
   - nothing throws, raises, panics or exits;
   - nothing logs or writes to standard error;
   - no error is returned or passed on (for example to a rejection or error callback);
   - nothing is added to an errors, warnings or diagnostics collection the caller sees.

These do not make a function a silent fallback:

- **The honest "no value".** The failure answers with the language's own absence value, for example `null`, `None`, `nil`, `undefined`, an empty optional or the unit value. One exception: where the language lets a handler catch every failure, `null` from such a catch-all handler does count.
- **An honest "not found".** The function asks whether something exists or where it is (a probe or a find). On a miss it answers with the type's empty or not-found value, because absence is the expected answer to that question. A lookup that is expected to succeed and answers its failure with a constant does count.
- **The answer is the result.** Examples:
  - a predicate that tries an operation and answers `true` or `false` to "can this be done?";
  - a function whose every other answer is also a literal, so the failure answer is one of its normal outcomes;
  - the try convention, where a boolean result tells the caller whether an accompanying out value can be trusted;
  - a function whose name says it returns a default on failure (for example `ReadOrDefault`).
- **Failure is reported in the value.** A constant whose text says the operation failed (for example `"Could not load map"`), or a symbol that names the failure.
- **The default is documented.** A comment at the failure handler, or the function's own documentation, says the constant is the intended answer to the failure or names it as what a failure returns. A comment that only describes the function or names the failure does not count.
- **The language's platform contract defines the value as a failure signal**, for example PHP's `false` on failure.
- **Cancellation.** A handler for a requested cancellation is not a failure path.
- **The callers make it visible.** The function is called at least once, and every caller passes the value it got back into a throw or a log. A caller that only logs something else does not count.

**Unit: a pending-state component or view.** A UI component or view counts as one unit when all of the following hold:

1. It shows a loading state.
2. The loading state waits on a value delivered later by something that can fail (for example an asynchronous load, a promise, or a message the component waits for).
3. The failure of that value is visible nowhere. The component or view draws no failure state for it, and it does not:
   - raise a notification (for example a toast, a snackbar or an alert) when the load fails;
   - pass the error to a parent's failure handler or emit it to the parent;
   - rethrow the error or send it to an error boundary (for example by telling the data library to throw on failure).

   Writing the error only to the developer console does not make it visible. Neither does a failure handler that only resets the value to empty or clears the loading flag.

When the value fails to arrive, the component keeps showing "still loading", so the failure looks like a wait that never ends. These are not counted:

- a loading state over a value that cannot fail to arrive, for example a "Loading…" shown during a one-shot synchronous load;
- a busy state that only marks an action in progress, for example one that also disables the control that started the action. If the action fails, the control comes back.

**What is counted:** the number of silent fallback functions plus the number of pending-state components and views. A function counts once, however many silent fallback paths it has. A component or view counts once, however many unreported loading states it shows.

**Denominator:** none. The result is a count of findings.

## Thresholds
None. Each condition above is a yes or no question, so no number decides when something counts. The limits on how many components and views are read are under Pending re-definition.

## Score
No score curve is defined: the one existing engine reports findings only, with no 0-10 reading.

## Not measured when
- The production code has no function, component or view in a language the measuring engine reads. That gives no result, which is not the same as a clean result.
- An engine does not count functions, components or views in languages it does not read. The result names the languages it covers.

## What the result is not
- It does not say that a constant is wrong. A default the author meant but did not document still counts.
- It is not a check of error handling in general. A failure that is swallowed with no value given back is not a fallback and is not counted.
- A log call or a throw anywhere in a function clears every path in it, even a path that the log or throw does not cover.
- It is not a count of defects that users can see. A silent fallback changes behaviour only when the data really is malformed.

## Pending re-definition
These are parameters of the existing reading's model. Today's findings depend on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- Status: the catalog does not declare it advisory, yet no score curve exists; a decision either declares it advisory or sets its curve.
- **Components read:** at most 5,000 component files per repository, and none larger than 1,000,000 bytes.
- **Views read:** at most 500 server-rendered view files (for example Razor views and components) per repository, and none larger than 2,000,000 bytes.
