# X23: Unguarded diagnostic materialisation

**Lens:** codeHealth · **Scored:** yes

## Property

Whether, in production code (tests excluded), the work a diagnostic log line costs is paid only when that line is wanted: where a call's arguments are evaluated before the call, a trace, debug or verbose message whose arguments do work that scales with a collection (for example joining, projecting or serialising it) is built in full every time the call runs, and then discarded by a level the shipped configuration leaves switched off, unless the work is deferred into a function the logger calls only when the level is on, or a check of the log level, a build switch or conditional compilation keeps it from running.

## Applies to

Any language that evaluates a call's arguments before it enters the call. Examples are C#, F#, Visual Basic .NET, Java, Kotlin, Scala, JavaScript, TypeScript, Python, Ruby, PHP, Dart, Rust, Go, Swift and Elixir, and the script parts of single-file components. A language that evaluates arguments lazily is out of scope, because the cost the property describes cannot arise there.

## Population

The population is production code as [production-code.md](../production-code.md) defines it. This dimension adds nothing to that definition. Code that only a debug build compiles stays in the population and is handled as guarded (see Thresholds).

Within that code, the population is every **diagnostic log call**: a call to a logger at a diagnostic level. The diagnostic levels are trace, debug and verbose, plus a language's or logging library's own names for the same levels (for example Java's `fine`, `finer` and `finest`, or `silly` in some JavaScript loggers). The level counts whether the method's name carries it (for example `LogTrace`, `logger.debug`) or an argument passes it (for example `Log(LogLevel.Trace, …)`).

Out of scope:

- Log calls at information, warning, error, critical or fatal level. Their message is written, so the work is not wasted.
- Writes that no level switches off (for example a console write that always prints). Nothing is built only to be thrown away.

## Unit and denominator

- **Unit:** an unguarded diagnostic log call. This is a diagnostic log call where both of these hold:
  1. At least one argument does work that scales with the size of a collection while it is evaluated before the call. Examples are a projection, filter, sort, grouping, set operation or aggregation over a sequence; copying a sequence into a list, array, set, map or lookup; joining a sequence into a string; and serialising a value. The work counts whether it is written in the argument or done by a function the argument calls.
  2. Nothing keeps that work from running when the level is off (see Thresholds).
- Each call counts at most once, however many arguments do such work.
- Work whose cost does not depend on a collection's size is not counted, however expensive it is. Examples are interpolating a few locals or fields, joining two path segments, serialising a literal the line spells out in full, and concatenating two strings.
- **Denominator:** the number of diagnostic log calls in the population, guarded or not.

## Thresholds

A call is **guarded**, and so not counted, when one of these holds:

- **Deferred work:** the costly work sits inside a function, closure, block or lazy value that is passed to the logger, and the logger calls it only when the level is on.
- **Level check:** a condition that is true only when a diagnostic level is on decides, before the call, whether the call runs. Examples are the logger's own enabled test for that level, or the program's own debug flag. This covers:
  - the call is in the then-branch of an `if` on that condition;
  - the call is the right operand of a logical "and" on that condition;
  - the call is the true branch of a conditional expression on that condition;
  - an earlier statement in the same block returns, throws, breaks or continues when the condition is false.

  A test that names a level the shipped configuration leaves on (information, warning, error and higher) is not a level check. The else-branch of a level check is not guarded.
- **Build switch or conditional compilation:** the call sits in a region that only a debug or diagnostic build compiles (for example `#if DEBUG`), or behind a build-time switch that a production build removes (for example a development-mode environment check).

Passing the collection itself to the logger as a placeholder argument is not work in the argument, so such a call is not counted.

No other threshold applies.

## Score

Let *n* be the number of unguarded diagnostic log calls and *p* the number of diagnostic log calls.

- If *n* = 0, the score is **10**.
- Otherwise:
  - *D* = max(*p*, *n* + 1)
  - *d* = *n* / *D*
  - isolation = max(0, 1 − *d* / 0.10)
  - headroom = min(1, log₁₀(*D*) / log₁₀(200))
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − *d*) × (ceiling − 1), rounded to two decimals

A repository with any unguarded call scores at most 8. It falls to 6 or below once a tenth of its diagnostic log calls are unguarded, and towards 1 as nearly all of them are. Two examples: one call of one (*p* = 1, *n* = 1) scores 3.5, and one call of ten scores 5.5.

## Not measured when

- The production code holds no diagnostic log call (*p* = 0). That is "not applicable", not a 10.
- The repository's production code is in languages the engine does not read, under the 95 % rule in [production-code.md](../production-code.md).

## What the result is not

- It is not a measure of logging performance overall. Expensive work that does not scale with a collection (for example a hash, a database round-trip, or rendering a large object as text) is out of scope.
- It does not say the cost matters at runtime. A call that runs once at start-up counts the same as one inside a hot loop.
- It does not judge the levels the shipped configuration leaves on, or whether a message is useful.
- A guard is judged by what the condition tests, not by whether the configuration in use actually switches the level off.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Ceiling with any unguarded call:** 6, raised by up to 2 (to at most 8).
- **Density at which the raise is gone:** 0.10 (a tenth of diagnostic log calls unguarded).
- **Population at which the raise is full:** 200 diagnostic log calls, on a log₁₀ scale.
- **Floor of the curve:** 1.
- **Denominator floor:** *n* + 1, so the share of unguarded calls never reaches 1.
