# X20: Mistyped argument guard

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether an argument guard throws the exception its own condition describes: a guard that rejects a value for being empty and reports it as a null argument (for example ArgumentNullException in .NET, or a type derived from it) tells the caller a parameter was null when it provably was not.

## Applies to
This dimension applies to languages that report a null argument in a way that differs from how they report an invalid argument in general. In .NET and on the JVM, a null argument has its own exception type. In Dart, it has its own constructor.

| Language | Null argument | Out of range | General |
|---|---|---|---|
| .NET (C#, Visual Basic .NET, F#) | `ArgumentNullException` (F# `nullArg`) | `ArgumentOutOfRangeException`, `IndexOutOfRangeException` | `ArgumentException` (F# `invalidArg`) |
| Java, Kotlin, Scala | `NullPointerException` (and Kotlin's `KotlinNullPointerException`) | `IndexOutOfBoundsException` | `IllegalArgumentException` |
| Dart | the `ArgumentError.notNull` constructor | `RangeError` | `ArgumentError` |

In .NET and on the JVM, a type the repository derives from one of these types counts as that kind. In Dart, `ArgumentError.notNull` builds a plain `ArgumentError`, and `RangeError` is a subtype of `ArgumentError`. So in Dart a null-argument report is recognised by the constructor that built it, not by its type.

Some languages have no such distinction, for example Python, PHP, Ruby, JavaScript, TypeScript, Go, Rust and Swift. They have nothing to mistype, so the dimension does not apply to them.

## Population
Production code as [production-code.md](../production-code.md) defines it, in the languages above.

## Unit and denominator
**Unit: an argument guard.** An argument guard is a throw that names a parameter and that a condition controls. A throw can name its parameter with `nameof(p)`, for example, or with the literal `"p"` as the exception's parameter-name argument. A condition controls a throw in three places:

- the branch of an `if` taken when the condition is true (the true side), or the branch taken when it is false (the false side);
- the true arm or the false arm of a conditional expression;
- the right side of `p ?? throw`.

Some throws run only on some other event, for example a throw inside a loop, a lambda, a local function or a `catch`. The condition does not control them. A JVM `NullPointerException` names nothing. Its subject is a parameter of the enclosing method, but only when the condition tests that parameter and no other. A library call that tests and throws in one step (for example `ArgumentNullException.ThrowIfNull(p)`) is not counted as a guard.

There are two kinds of guard:

- **Null guard:** a guard that reports a null argument, on either side of its condition.
- **Range guard:** one of these two:
  - a throw on the true side of its condition that throws an out-of-range exception or the general exception, where the condition compares the named parameter with a bound using `<`, `<=`, `>` or `>=`;
  - a throw of an out-of-range exception, on either side, that only a null value of the parameter can reach (case 2).

**Denominator:** every argument guard in the population, each counted once.

**A finding** is any one of the cases below. Each finding counts once in *v*.

1. **Null exception, non-null value.** A null guard that a non-null value of the named parameter can reach.
   - **True side, disjunction.** One disjunct of the condition is true of a non-null value. Because `||` short-circuits, that disjunct decides on its own. These tests are true of a non-null value:
     - an emptiness test, for example `p.Count == 0`, `p.Length < 1`, `!p.Any()`, `p.Count() == 0`, `string.IsNullOrEmpty(p)` or `string.IsNullOrWhiteSpace(p)`;
     - an inverted test, `p != null` or `p is not null`;
     - a test that always reads a member or element of `p`, for example `p.Customer == null` or `p[0] == 0`. Two kinds of read do not count. The first is a member that is itself null-safe, for example `HasValue`. The second is a read that runs only sometimes: after `?.`, behind `?:`, on the right of `&&`, `||` or `??`, or inside a lambda;
     - a comparison of `p` with a bound or with a non-null value, for example `p > 1400` or `p == ""`.
   - **True side, conjunction.** A conjunction is a finding when all three of these hold:
     - one conjunct is a test from the list above;
     - no conjunct is a test that only a null `p` satisfies (for example `p == null` or `p is null`). A non-null assertion is allowed, for example `p != null && p.Count == 0`;
     - the conjuncts can all be true at once. The other conjuncts only narrow which values reach the throw. For example `strict && p.Count == 0` is a finding. `p.Count == 0 && p.Count > 5` is not, because it can never be true.
   - **False side.** A non-null value of `p` can make the condition false. This happens when the condition is exactly `p == null`. It also happens when one conjunct about `p` is false for some non-null value (for example `p.Length > 0` is false for `""`) and no conjunct is a test that only a null `p` satisfies.
2. **Out-of-range exception, null value.** A guard throws an out-of-range exception, and only a null `p` can reach it. For example, every disjunct is `p == null` or `p is null`, or the throw is on the false side of `p != null`, or the guard is `p ?? throw`.
3. **Range that rejects nothing.** A range guard on the true side where, in one disjunct, no value of `p`'s type satisfies all the bounds that disjunct sets on `p`. Examples are `p < 0 && p > 12`, and `p < 1 && p > 0` for an integer `p`. A size (`C.Count`, `C.Length`) is never below 0, so `p < 0 && p >= C.Length` also leaves no value.
4. **Range that lets the past-the-end index through.** A range guard on the true side where one disjunct is `p > C.Count` or `p > C.Length`, so `p == C.Count` passes. A later statement in the guard's own block must then use `p` as an index that has to be below the count. It can do so directly (`C[p]`, `C.RemoveAt(p)`, `C.ElementAt(p)`) or by passing `p` to a method of the same type that does. No statement in between may test `p` again or assign to it.
5. **Repeated null check.** A block null-checks `p`, and an earlier statement in the same block already null-checked `p`, with no assignment to `p` in between. A null check here is one of two things:
   - an `if (p == null)` or `if (p is null)` with no else, whose only statement reports a null argument;
   - for this case only, a one-step library null check such as `ThrowIfNull(p)`.

   What matters is the `p` that is tested, whichever parameter the exception names. A repeated `if (p == null) throw` counts as a guard and is also a finding. A repeated library call is a finding but not a guard.

A range guard gives at most one finding, and case 3 is checked before case 4.

**Subject match.** A test proves something only about the parameter it tests. Some guards decide on a test about a different argument from the one the exception names. They are not findings under cases 1 to 4, but they still count as guards. A null guard that tests only nullness is correct. The general exception may report any argument failure, so a guard that throws it can be a finding only under cases 3 and 4.

## Thresholds
- A size counts as empty when it is `== 0`, `< 1` or `<= 0`, with the operands in either order.
- A range leaves no value when no value of the parameter's type satisfies all of its bounds.
- Only a strict `>` against a size lets the past-the-end index through.

## Score
*v* is the number of findings. *n* is the larger of two numbers: the number of guards, or *v* + 1.

- If *v* = 0, the score is 10.
- Otherwise:
  - *d* = min(*v* / *n*, 1)
  - isolation = max(0, 1 − *d* / 0.10)
  - headroom = min(max(log10(*n*) / log10(200), 0), 1)
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − *d*) × (ceiling − 1), clamped to [1, ceiling] and rounded to 2 decimals

Any finding caps the score at 8. Once *d* reaches 0.10 the cap is 6, and the score falls toward 1 as *d* approaches 1.

## Not measured when
- The repository has no production code in a language this dimension applies to. The result is then "not applicable".
- The code was read and holds no argument guard and no finding. The result is then "not applicable", not a 10.
- No source file in an applicable language could be read. The result is then "could not read", never "not applicable". If only some files could not be read, the score is computed from the files that were read, and the result names the files that were not.

## What the result is not
- It does not judge whether parameters are guarded at all, or how an exception message is worded.
- It does not judge a range guard's bounds beyond the two shapes in cases 3 and 4.
- It does not judge a guard whose exception names no parameter, or whose deciding test is about a different argument.
- It is not an analysis of the whole program. It reads only each guard's own condition and exception, and the statements after the guard in its own block.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Density threshold:** 0.10. Once findings make up this share or more, any finding caps the score at 6.
- **Population saturation:** 200 guards. At this many guards, an isolated finding's cap gets its full lift.
- **Ceilings and floor:** the cap is 6 and can rise by up to 2, to 8. The floor is 1.
- **Denominator floor:** *n* is at least *v* + 1, because a finding can come from a library call that is not a guard.
