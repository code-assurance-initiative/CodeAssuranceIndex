# X1: Async correctness

**Lens:** codeHealth · **Scored:** yes

## Property
Whether the code avoids sync-over-async (deadlock-prone blocking on tasks) and async void.

## Applies to
C#, JavaScript, TypeScript, Python, Dart, Ruby, Scala, Rust and Kotlin. For C#, this includes the C# code blocks of Razor component and view files. For JavaScript and TypeScript, it includes the script blocks of single-file components (for example Vue or Svelte).

## Population
The population is production code as [production-code.md](../production-code.md) defines it, in the languages above. Every listed language goes into one count. This dimension also reads one thing that page excludes: the C# code blocks inside Razor files. It does not read their markup.

## Unit and denominator
The unit is a **violation**: one place in the code that does one of the three things below. Each place counts once. A violation does not have to sit inside a member of the denominator.

1. **Blocking on asynchronous work from synchronous code (C#).** The code waits synchronously for a task that is still pending, for example with `.Wait(...)`, `.Result`, `.GetAwaiter().GetResult()`, `Task.WaitAll` or `Task.WaitAny`. A **bridge** is a synchronous function of the repository that blocks on a task passed to it as a parameter. Each call that hands a bridge a pending task is a violation. The bridge's own wait counts only when nothing in the repository calls the bridge (for example a library's public synchronous wrapper). Outside an asynchronous function, this is the only blocking that counts. Sleeps, waits on other synchronisation objects and synchronous I/O there do not count. In the other languages, running asynchronous work to completion from synchronous code is how the language enters asynchronous code (for example `asyncio.run`, `block_on` or `runBlocking`), so it is not a violation there. In JavaScript and TypeScript a thread cannot block on a promise at all.
2. **Blocking the thread inside an asynchronous function or coroutine.** When the nearest enclosing function is asynchronous, any call that holds the thread until something finishes is a violation. For example:
   - a synchronous sleep (`Thread.Sleep`, `time.sleep`, `std::thread::sleep`);
   - a wait on a pending task or on a threading primitive (for example a `SemaphoreSlim` acquired with `Wait()`);
   - synchronous I/O where a non-blocking form exists (for example `File.ReadAllText` when `ReadAllTextAsync` exists, or a blocking file or socket read in an `async def`);
   - starting a nested event loop or running a future to completion (`asyncio.run`, `run_until_complete`, `block_on`, `runBlocking`);
   - a call to one of the repository's own synchronous helpers that does any of these.
3. **Starting asynchronous work whose result and failure nobody can observe.** This counts wherever the work is started, inside or outside an asynchronous function. For example:
   - a C# `async` function that returns `void`;
   - an `async` function handed to a caller that ignores what it returns (for example a `forEach` callback, a `new Promise(...)` executor, React's effect hooks, or Flutter's `setState`);
   - a promise, task, future or `Deferred` that the code starts and then drops: it is not awaited, returned, stored, or given a failure handler.

   This does not count when the work is **contained**, meaning it cannot fail unobserved: its whole body is one `try` whose `catch` handles every failure and neither rethrows nor returns a failure. An optional `finally` is allowed.

These do not count:

- a wait on a task that is already complete at the point where it is read (for example one awaited earlier, checked complete first, or created complete);
- the process entry point (C# `Main` or top-level statements) blocking on its own work;
- a wait on a delay task (a timer) outside an asynchronous function. That wait is a sleep, and a sleep outside an asynchronous function is not a violation.

The denominator is the **population** N: the number of asynchronous functions in the population code. In a language that has no asynchronous functions, N counts each place where asynchronous work is started.

- **C#:** every function declared `async` (a method, local function or anonymous function).
- **JavaScript, TypeScript:** every `async` function in any form (declaration, expression, arrow function or method).
- **Python:** every `async def`.
- **Dart:** every `async` or `async*` function body.
- **Rust:** every `async fn` body and every `async` block.
- **Kotlin:** every `suspend fun` with a body, plus every `GlobalScope.async` start.
- **Ruby, Scala:** every future started (for example a concurrent-ruby future or a `scala.concurrent.Future`).

## Thresholds
- A wait on a task, promise or future counts only while that work is still pending.
- Density 10 %: at this share of violations to population, or above, the cap on the score reaches its lowest point (see Score).
- Population 200: below this population, the cap on the score is lowered (see Score).

## Score
Let v be the number of violations and N the population. Let P = max(N, v + 1).

- If v = 0, the score is 10.
- Otherwise:
  - density d = v / P, clamped to [0, 1];
  - isolation i = max(0, 1 − d / 0.10);
  - headroom h = log10(P) / log10(200), clamped to [0, 1];
  - ceiling c = 6 + 2 · i · h;
  - score = 1 + (1 − d) · (c − 1), clamped to [1, c], rounded to 2 decimals.

Any violation caps the score at 8. The cap falls toward 6 as density nears 10 %, and also when the population is small. Widespread violations take the score toward 1.

## Not measured when
- The population code has no asynchronous function or start (N = 0) and has no violation.
- The repository holds none of the languages above.
- Source files in scope exist, but none could be read.

## What the result is not
- It is not proof that the code never deadlocks. Blocking hidden behind an indirection the code does not show (for example a delegate, an interface or another repository's code) is not counted.
- It does not measure how much asynchronous code there is, or whether cancellation is passed through it.
- A bridge kept on purpose is not excused. Each call that hands it a pending task still counts, and its own wait also counts when nothing in the repository calls it.
