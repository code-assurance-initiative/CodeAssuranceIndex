# D17: Explicit Debt

**Lens:** codeHealth · **Scored:** yes

## Property
Acknowledged debt left in the code — TODOs, dead code, suppressed warnings.

## Applies to
- **Task tags:** any language. A task tag is a comment, and a comment means the same thing in every language.
- **All other marker kinds** (see the table below): C# and Visual Basic .NET source. These kinds also apply to the files that configure the compiler and analyzers for that source. Those files are project files, the shared build property files that project files import, and analyzer configuration files (for example `.editorconfig` or a global analyzer config).
- **UI markup and server-side component files that hold C#** (for example XAML or Razor components): task tags in their comments. C# inside a component's own code block is read as C#.
- **YAML configuration that the repository's authors maintain** (for example CI workflows, container composition or deployment settings): configuration that has been commented out counts as commented-out code. This applies in any repository.
- **Dead symbols:** C#.

## Population
This dimension reads production code as [production-code.md](../production-code.md) defines it. It also reads the added files below, but only to find markers:

- **Compiler and analyzer configuration**, named under Applies to. A file of this kind is in scope when it configures production code. That means it is the project file of a production project, or it is a build property file or analyzer configuration whose settings reach at least one production project.
- **YAML configuration** is in scope when the repository's authors wrote it, whatever it configures (for example CI workflows, container composition files, deployment or chart values). This holds even inside a hidden folder (for example CI workflow files under `.github`).
- **UI markup and server-side component files that hold C#** are in scope when they belong to a production project. This includes server-side component files that [production-code.md](../production-code.md) otherwise excludes as server-side templates.

These added files are out of scope:

- the project file of a test project;
- a build property file or analyzer configuration whose settings reach only test projects;
- vendored or generated configuration, and configuration in build output;
- configuration that version control ignores.

The added files add no lines to the denominator.

A file that a tool writes and people do not edit is never dead code.

## Unit and denominator
**Unit:** a debt marker. A debt marker is a place where the code itself records a known shortfall that was left unfixed. Each marker has a kind and a weight (see Score).

| Kind | What it is |
|---|---|
| Task tag | A comment that marks unfinished work with TODO, FIXME, HACK (or HACKY) or XXX. A comment that only mentions such a tag, or uses XXX as a placeholder, is not a task tag. Each tagged comment line is one marker. |
| Commented-out code | A comment block that holds disabled code: code switched off by commenting it out, not prose that quotes or illustrates code. Each such block is one marker, whatever its length. In YAML (see Applies to), each configuration entry or block that has been commented out is one marker. |
| Dead preprocessor branch | An `#if` on a symbol that no build configuration of the repository can define. |
| Obsolete member | A member marked obsolete. Its weight depends on whether code still calls it. |
| Rule suppression | An attribute that suppresses an analyzer rule on one declaration (for example `[SuppressMessage]`). |
| Coverage exclusion | An attribute that removes production code from test coverage (for example `[ExcludeFromCodeCoverage]`). |
| Scoped pragma disable | A warning disable that a matching restore later in the same file closes. |
| File-scoped pragma disable | A warning disable with no matching restore in the file. |
| Project suppression | One warning code in a project's list of suppressed warnings (for example `<NoWarn>`). Each code is one marker. |
| Vulnerability-alert suppression | A project suppression of the dependency audit's warnings about known vulnerabilities. |
| Rule switched off by configuration | A rule set to severity none in analyzer configuration. This includes a bulk setting that turns off all rules or a whole category. |
| Analyzers switched off | A project setting, applied in every build configuration, that stops analyzers from running. |
| Warnings-as-errors demoted | Treat-warnings-as-errors set to false where a setting that reaches the project had set it to true. |
| Swallowed failure | An empty catch block, or a Visual Basic `On Error Resume Next` with no reset or error check after it. |
| Code that provably does nothing | One of these forms: guard code that has no effect or is inverted (an existence check that makes the guarded call a no-op, or a branch that uses a value the guard just proved null); a discarded result of a string method; a loop accumulator reset to a constant before every check; a private field that is written but never read. |
| Dead symbol | A type or method that nothing in the repository refers to and that nothing outside the repository can reach. This covers private and internal symbols, and the public types of an application that no library user can see. These are not dead: entry points, overrides, interface implementations, members that a framework calls by convention or by reflection, and members that markup binds to. |

**Justified markers do not count.** A suppression that states its reason in the code is not debt. The reason can be a justification argument, or a comment beside or above the suppression. A placeholder such as `<Pending>` is not a reason, and neither is a copy of the rule's own title. An empty catch that catches a narrow type, has a filter or carries a comment is intentional and does not count. A commented-out setting that a comment presents as an available option, or whose key is also set live in the same block, is documentation and does not count.

**Denominator L:** all production lines of the repository, as [production-code.md](../production-code.md) counts them, whether or not a file holds a marker. The added files under Population add no lines.

## Thresholds
- **Justification:** a written justification of at least 10 characters is a reason. A shorter one is a reason only when it states a verdict (for example "By design").
- **Trimming suppressions:** a suppression that only tells the trimmer or ahead-of-time compiler that a use is safe (for example `[UnconditionalSuppressMessage]`) is justified by any non-empty justification, or by a trimming annotation on the same member.
- **Score-neutral markers** (weight 0) are listed but take nothing off the score:
  - a disable directly followed by its restore;
  - the same warning code suppressed twice in one project;
  - a warnings-as-errors entry that the same project also suppresses;
  - a severity setting that a later line in the same section overrides or repeats.

## Score
Weights per marker:

| Weight | Kinds |
|---|---|
| 2.0 | Vulnerability-alert suppression |
| 1.0 | Project suppression; rule switched off by configuration (single or bulk); analyzers switched off; warnings-as-errors demoted; swallowed failure; code that provably does nothing (each form) |
| 0.75 | File-scoped pragma disable |
| 0.5 | Rule suppression; coverage exclusion; scoped pragma disable; obsolete member that still has callers |
| 0.25 | Commented-out code (per block); dead preprocessor branch; obsolete member with no callers; dead symbol |
| 0.1 | Task tag |

**Weighted debt W** is the sum of the weights of all counted markers and dead symbols, with one exception. Within each file:

1. Take only the rule suppressions, scoped pragma disables and file-scoped pragma disables. Call their count n.
2. Order them heaviest first.
3. The first min(n, 5) count at full weight.
4. When n > 5, add log2(n − 5 + 1) × (the mean weight of all n). That is everything else these markers add for the file.

All other kinds, coverage exclusions included, are added at full weight.

**Density:** D = W / ((L + 2000) / 1000).

**Score:** S = clamp(10 − 2 × D, 0, 10).

The score is 10 when there is no debt, and 0 at a density of 5 or more. Example: 5,000 production lines with 12 task tags, 2 empty catches and 1 project suppression give W = 4.2 and D = 0.6, so S = 8.8.

A repository with no C# or Visual Basic .NET source is scored only on task tags and commented-out YAML configuration, over its production lines, and the result says so. When the repository's C# code does not build cleanly, dead symbols are left out of W, and the result says so.

## Not measured when
- The repository holds no production code that this dimension reads.
- None of the production source files that this dimension reads can be read.
- The repository has C# or Visual Basic projects, but none of them can be opened as a project (for example a custom build that the standard project format does not describe).

## What the result is not
- It does not measure all technical debt. It counts only debt that the code writes down or shows by its own form. Debt that nobody marked is invisible by design.
- It does not grade what each piece of debt costs. A weight reflects the kind of act and how far it reaches, not its consequence.
- A justified suppression is not debt here. The result does not judge whether the stated reason is right.
- A dead symbol means "no reference found in the repository". It does not prove that nothing calls the symbol, because callers that find it by name at run time cannot be seen.

## Pending re-definition
These are parameters of the existing reading's model, and today's scores depend on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Smoothing:** 2,000 lines are added to L in the density denominator.
- **Suppression walls:** in each file, up to 5 rule suppressions and pragma disables count at full weight. Above 5, the file's total for these follows step 4 of Score: log2(n − 5 + 1) × the mean weight. Coverage exclusions are not part of this cap.
- **Justification length:** 10 characters.
