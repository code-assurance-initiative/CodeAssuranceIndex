# D7: Architectural Integrity

**Lens:** architecture · **Scored:** yes

## Property
Whether the code respects its intended layering / architecture rules.

## Applies to
- **Decision records:** the repository's architecture decision records, in any prose markup (for example Markdown).
- **Rule conformance:** code in any language, where a live decision record states a dependency rule between two paths.
- **Project cycles:** repositories whose build declares references from one of their own projects to another (for
  example .NET project files that reference other projects in the same repository).

## Population
- **Decision records:** documents in the repository that each record one architecture decision. These are not:
  templates for new records, folder indexes and readme files, decision records that are input data for the product or
  its tests (for example a fixture corpus of sample records), and, in a log whose records are numbered, a document
  without a number (for example a schema or guide beside the records). Decision records are documentation, so they are
  not production code. This dimension reads them anyway, as the statement of the rules.
- **Live records:** a record is live unless its status says it is superseded, rejected, deprecated, withdrawn,
  obsolete, proposed, draft or abandoned. A record with no status is live.
- **Code checked against a rule:** production code as [production-code.md](../production-code.md) defines it, inside the path the rule
  constrains. A file inside the forbidden path itself is not checked against that rule.
- **Projects:** the repository's own build projects and the references they declare to each other.

## Unit and denominator
Three things are counted.

1. **Enforcement rung of each record.** A record's rung is what the repository states about how the decision is enforced:
   - **Prevented:** the record declares it is enforced by an analyzer, a compiler check or another mechanical check
     that blocks a violation. A record with no declaration is also at this rung when an analyzer in the repository
     states that it enforces that record.
   - **Verified:** the record declares it is enforced by a test. A record with no declaration is also at this rung
     when a test in the repository states that it checks that record.
   - **Documented:** the record declares it is enforced only by prose, judgement, review or process.
   - **Not applicable:** the record declares there is nothing to enforce.

   The **scored set** S is every record, whatever its status, that is at Prevented or Verified, or that declares
   analyzer or test enforcement. Records declared prose or not applicable, and undeclared records that no analyzer or
   test enforces, are not in S. Denominator: |S|.
2. **Violated rules (V).** A rule is one sentence of a live record saying that code under one repository path must not
   depend on (import, reference, use, include, require, access) a second repository path. Each path names a location
   in the repository, not a bare name. A rule is violated when at least one checked file under the first path has a
   dependency reference (an import, include, using or require line, or the language's equivalent) that resolves into
   the second path. V counts rules, not files or sites. A rule whose first path does not exist in the repository is
   not violated.
3. **Project cycles (C).** A cycle is a group of two or more projects in which each project reaches every other
   through declared project references, or one project that references itself. Each group counts once, however many
   projects or loops it contains.

## Thresholds
- **Dominant rung multiplier m:** 1.0 when S holds at least one Prevented record; otherwise 0.8 when S holds at least
  one Verified record; otherwise 0.6 (this includes an empty S).
- **Penalty per project cycle:** 2 points.
- **Penalty per violated rule:** 2 points.
- **Prose fraction p:** the number of Documented records in S divided by |S|, or 0 when S is empty.
- **Enforcement coverage k:** the number of Prevented and Verified records in S divided by |S|, or 1 when S is empty.

As S is defined above, every record in S is at Prevented or Verified, so today p = 0 and k = 1 on every repository.
Both terms are kept because they are part of today's formula.

## Score
```
base  = clamp(10 − 10·p − 2·C − 2·V, 0, 10)
score = clamp(base × m × k, 0, 10)
```
Examples: one analyzer-enforced record and no cycle or violated rule gives 10. Records that are all prose or
undeclared, with no cycle and no violated rule, give 10 × 0.6 = 6.0. One test-enforced record, one project cycle and
one violated rule give (10 − 2 − 2) × 0.8 = 4.8. No decision records and two project cycles give (10 − 4) × 0.6 = 3.6.

## Not measured when
The repository has no decision records and no project cycles. This includes a repository with no decision records
whose build declares no project references, where there is nothing to read for cycles.

## What the result is not
- It does not credit a layering that is followed but not written down as a decision record. An unwritten convention
  earns nothing.
- It does not check whether a declared analyzer or test actually holds the rule. A record is credited at the rung it
  declares.
- It checks the code only against rules a record states as "path A must not depend on path B". Rules stated in other
  terms (layers by name, types, patterns) are not compared with the code.
- It reads project cycles between build projects, not import cycles between modules or files inside one project.
- It is not a measure of design quality. A repository with good architecture and no decision records scores 6.0 at
  most, or is not measured.
