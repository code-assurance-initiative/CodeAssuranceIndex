# D1: Cyclomatic Complexity

**Lens:** codeHealth · **Scored:** yes

## Property
How tangled the control flow is — methods with many branches are hard to test and change.

## Applies to
Any programming language on the production-lines list in [production-code.md](../production-code.md). This includes the script parts of single-file components (for example Vue or Svelte). HTML and CSS have no functions, so the dimension does not read them.

## Population
The functions in production code, as [production-code.md](../production-code.md) defines it. In addition to that page's exclusions, D1 also leaves out:

- **Examples, samples and demonstrations:** the authors' own example, sample, demonstration and proof-of-concept code (for example an `examples` app that shows how to use a library).
- **Benchmarks:** code that exists only to measure performance, whether or not it is a separate project.
- **Scaffolding templates:** starter projects that a generator copies into new projects for its users.
- **Flat dispatchers:** a function whose cyclomatic complexity is over the threshold only because it chooses among many independent cases with almost no nesting (for example a long `switch` or `match`, or an `if`/`else if` ladder, that maps each input to one action). The rule under Thresholds decides which functions count as flat dispatchers. A function left out this way is not in the score in any way.

A function with no body (abstract, interface or extern declarations) is not in the population.

## Unit and denominator
**Unit:** one function's cyclomatic complexity. This is 1 plus one for each decision point in the function's own body, as the language defines its decision points. A decision point is each conditional branch (`if`, `else if`, each conditional `case` or match arm, each guard on an arm), each loop, each exception handler, each conditional expression, and each short-circuit boolean operator (`&&`, `||` and their equivalents).

**A function** is any named or anonymous callable with a body, as the language defines it. Methods, constructors, property and event accessors, operators, free functions and named nested functions are all functions. An anonymous function (a lambda, closure or function literal) belongs to the function that encloses it, and its decision points add to that function. A named function declared inside another function is a function of its own, and its decision points do not add to the function around it.

**Denominator:** every function in the population, each counted once.

## Thresholds
- **Threshold:** 15. A function is **over** the threshold when its cyclomatic complexity is greater than 15. A function at exactly 15 is not over.
- **Flat dispatcher:** a function is a flat dispatcher, and is left out, when all three of these hold:
  1. its cyclomatic complexity is over 15;
  2. its cognitive complexity (the unit of D2) is 8 or less, or its cognitive complexity without the increments for sequences of boolean operators is 4 or less;
  3. at most 15 of its decision points come from guards on switch or match arms (for example `when` clauses).

## Score
With n functions in the population:

- **p95** is the 95th percentile of the functions' cyclomatic complexities, taken by nearest rank. Sort the values in ascending order and take the value at position ⌈0.95 · n⌉, counting from 1.
- **max** is the highest cyclomatic complexity in the population.
- **over** is the number of functions over the threshold.

Density term:

`p95Score = clamp(10 − max(0, (p95 − 15) / 5), 0, 10)`

Worst-offender cap:

- If max ≤ 15, the cap is 10.
- Otherwise:
  - `grip = clamp((over / n) / 0.08, 0.30, 1.0)`
  - `worstCap = clamp(10 − 3.5 · ln(max / 15) · grip − 0.08 · min(over, 25), 2.0, 10)`

Dimension score:

`score = min(p95Score, worstCap)`, rounded to 2 decimals.

So a repository with no function over 15 scores 10. The cap term never goes below 2.0, but the score can still fall to 0 through the density term, which reaches 0 at p95 = 65.

## Not measured when
- The production code has no function with a body (for example only type, interface, enum or constant declarations), or it has no production code at all.
- Every function read falls outside the population (for example every function is in examples, tests, vendored or generated code, or is a flat dispatcher).

A result that is not measured is not a score, and in particular it is not a 10.

## What the result is not
- It is not a judgement of whether the branches are tested or correct. It counts decision points and nothing else.
- It says nothing about complexity in test code, examples or flat dispatchers, because they are outside the population. A complex shared test helper is measured nowhere.
- It is not a measure of readability. Nesting and tangling are D2's property, and D1 uses D2's unit only to recognise flat dispatchers.
- A low score does not say the whole codebase is complex. The worst function and the number of functions over 15 can hold the score down while most functions are simple.
- It is not a size measure. A long function with few decision points scores as simple.

## Pending re-definition
These are parameters of the existing reading's model. Today's scores depend on them, and a later decision under decision 0013 will replace each one with a threshold on the property.

- **Grip of the worst offender:** the worst-function penalty is weighted by the share of functions over the threshold. It reaches full weight at 8 % of functions over, and it never falls below 30 % of full weight.
- **Curve constants:** 5 complexity points per density point above the threshold; 3.5 points per natural-log multiple of the threshold for the worst function; 0.08 points per function over the threshold, counting at most 25 such functions; and a floor of 2.0 on the cap term.
- **Flat-dispatcher gates:** a cognitive complexity of 8 or less, or 4 or less without the boolean-sequence increments.
