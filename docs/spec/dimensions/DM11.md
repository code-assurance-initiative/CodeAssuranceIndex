# DM11: Constructible invalid state

**Lens:** domainModelling · **Scored:** yes

## Property

Whether an aggregate can be constructed in a state its own rules forbid — a public constructor that takes a raw primitive, stores it, and validates nothing, with no factory beside it. A constructor taking only value objects is not counted: each parameter has already validated itself.

## Applies to

Any language in which the code declares aggregates or entities.

Only a public constructor or a public initialiser (below) can make an entity count. Some languages have no constructors, and a value is built by a literal that sets its fields, for example a Go or Rust struct. An entity in such a language stays in the population and counts as clean.

The open-initialiser rule under Unit applies only where the language lets a caller set public properties as part of construction, for example the C# object initialiser.

## Population

The population is production code as [production-code.md](../production-code.md) defines it. In addition:

- **In scope:** every concrete (non-abstract) type that is an aggregate or an entity. This page calls each such type an entity. A type is one when any of these holds:
  - The code declares it an aggregate root or an entity. For example, it derives from an aggregate-root or entity base type, implements an aggregate-root interface, or carries an aggregate or entity annotation. A type declared only as an entity also needs an identity, for example an `Id` property or a property of a strongly typed identifier.
  - The code maps it to persistence as an entity. Examples are a class annotated as a persistence entity, an ORM model class, a struct mapped to a table, or a persistence schema module (for example an Elixir schema).
  - It has the shape of an aggregate in the domain code. It has an identity, it keeps its state from being set from outside (for example behind private setters or private fields), and it has public operations that change that state.
- **Out of scope:**
  - Abstract types, value objects, domain events and every other type.
  - An event-sourced state: a type whose state is rebuilt from domain events by a function that returns the next state for each event, rather than by its own constructor. It stays in scope when it is also declared as an entity with an identity. A type that applies events to itself through its own instance methods (for example an `Apply` or `When` method for each event) is an aggregate and stays in scope.
  - An aggregate written as a module of behaviour and a fold rather than as a type, for example in F# or Elixir.


## Unit and denominator

**Raw primitive:** a parameter or property whose declared type is a text string or a number (integers, decimals and floating-point numbers). For example `string`, `int`, `long`, `decimal`, `double` or `float` in C#, and `string`, `number` or `bigint` in TypeScript. A parameter or property with no declared type is not a raw primitive. Some types have no invalid value worth guarding, so they are not raw primitives either: dates and times, booleans, globally unique identifiers, single bytes and single characters. A value object is not a raw primitive, and neither is any other type the code declares.

**Validates:** contains code that can refuse an invalid value. For example, it throws an exception, or it calls a guard or assertion that throws on an invalid argument. Choosing a value is not refusing one, for example picking a default for a missing value. A refusal counts wherever it sits in the code the constructor, setter or static method runs.

**Unit:** an entity that can be constructed in an invalid state. An entity counts once, however many ways in it has. It counts when either of these is true:

1. **Open constructor.** The entity has a public constructor that:
   - has at least one raw-primitive parameter; and
   - does not validate.

   "With no factory beside it" means the factory is the only way in. A static factory next to an open constructor does not make the entity safe, because a caller can skip the factory. A constructor whose parameters are all value objects or other non-primitive types does not count.
2. **Open initialiser.** The entity has no open constructor, and all three of these hold:
   - It has a public parameterless constructor, written out or implicit.
   - It has at least one public settable raw-primitive property whose setter does not validate. An automatic property never validates.
   - It also declares a validating way in. This is either a constructor with parameters that validates, or a static method that validates and returns the type, directly or wrapped (for example as a result of the type).

   If the type declares no validating way in, its open setters do not count here.

A parameterless constructor with no public raw-primitive setter behind it does not count. Such a constructor typically exists so that a persistence framework can rebuild the object. Non-public constructors do not count.

**Clean entity:** an entity in the population that does not count.

**Denominator:** the number of entities in the population.

## Thresholds

- One open constructor or one open initialiser is enough to count the entity.
- One raw-primitive parameter is enough to make an unvalidated public constructor open.

## Score

Let *f* = clean entities / entities.

score = 3 + 7 × *f*, rounded to two decimals.

When every entity is clean, the score is 10. When every entity counts, the score is 3, the lowest score this dimension gives.

## Not measured when

- **The repository has no entity.** Domain Modelling is a conditional lens: it counts only where the repository models a business domain, as the evidence for the repository states (the scoring specification's applicability of lenses). Within it, the dimension is not measured when the population above holds no entity or aggregate root that is not abstract.
- **The population is empty:** the production code holds no concrete aggregate or entity.

## What the result is not

- It does not check that a constructor's validation is correct or complete. Any refusal clears the constructor, even one that guards a different parameter.
- It does not cover state that becomes invalid after construction, for example through public setters on a type with no validating way in. That is publicly mutable state, which is a different dimension.
- It does not cover entities built by literals in languages without constructors. Those entities count as clean.
- It does not check the value objects themselves. A constructor that takes only value objects is trusted to receive valid values.
- It does not count dates, booleans, identifiers or parameters with no declared type, even where a domain rule forbids some of their values.
- It is not a count of open constructors. An entity with several open ways in counts once.
