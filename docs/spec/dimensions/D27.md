# D27: Navigability

**Lens:** architecture · **Scored:** yes

## Property
How far you must trace to follow a call — low indirection and co-located slices read easier.

## Applies to
This dimension applies to any programming language in which functions call one another. Code that a language does not place in a named namespace, package or module is in the unnamed (global) namespace. Markup (HTML) and styles (CSS) have no calls, so this dimension does not read them.

## Population
The population is production code as [production-code.md](../production-code.md) defines it. This dimension adds no exclusions of its own. Examples, samples and the authors' own tools are production code here.

**Build unit.** A build unit is a unit that the language's build or package tooling compiles or ships as one. Examples are a .NET project or assembly, a Maven or Gradle module, a Go module, and a Python distribution package. A single source file is not a build unit unless it is the whole unit.

Two samples are taken from that population. Their sizes are listed under Pending re-definition.

- **Function sample:** the first 400 functions, taken one build unit at a time. Within a build unit, files are taken in path order and functions in source order within each file.
- **Type sample:** the first 400 types, taken one build unit at a time. Within a build unit, types are taken in order of fully qualified name.

## Unit and denominator
**A function.** A function is a named callable that a type, namespace, package or module declares, as the language defines it. Methods of a type and free-standing (top-level) functions both count. Constructors, property and event accessors, and operators are not functions here. An anonymous function or a local (nested) function is not a function of its own. It belongs to the function that encloses it, and its calls are that function's calls. A function's namespace is the namespace, package or module where it is declared, or the unnamed namespace if it has none. Every function in the sample fills one of the 400 places, even if it has no body (for example an abstract or interface member) or makes no call.

**An invocation.** An invocation is any call to a function or method written in a sampled function's body. Creating an object (a constructor call) is not an invocation.

**A counted call.** A counted call is an invocation whose callee is declared in the repository's own code. A call into the standard library or a dependency is not a step a reader traces through this code, so it is not a counted call.

Two fractions are taken over the counted calls. In both, the denominator is the number of counted calls.

- **Interface fraction (I):** the share of counted calls whose callee is declared on an interface, as the language defines it (for example a C# or Java interface, a Go interface or a Swift protocol). To follow such a call, a reader must find which implementation runs. A language without such a construct has no interface calls.
- **Cross-namespace fraction (X):** the share of counted calls where the callee's namespace differs from the caller's namespace. The two full namespace names are compared exactly. The unnamed (global) namespace counts as a namespace of its own. So in code that uses no named namespaces, X is 0.

**Locality (L).** Locality is measured over the collaborator references of each sampled type. Each of these is one reference to the type it names:

- each field's type;
- each property's type;
- each method's or constructor's return type, where it has one;
- each parameter's type.

A collaborator named twice counts twice. For example, `Foo f(Foo a, Foo b)` gives three references. Only collaborators declared in the same build unit as the type count. Arrays and type parameters name no collaborator.

A reference is **co-located** when the collaborator's feature equals the type's feature. A type's feature is the first two segments of its namespace, or the whole namespace if it has fewer than two segments. Types in the unnamed namespace share one feature. L is the number of co-located references divided by the number of all references, across all sampled types. When no reference is counted, L is 1.

**Size (N).** N is the repository's production lines, as [production-code.md](../production-code.md) defines them.

## Thresholds
- **Size bands:**
  - small: N below 10,000
  - medium: N from 10,000 up to but not including 50,000
  - large: N of 50,000 or more
- **Size factor s:**
  - small: 0.5
  - medium: 1.0
  - large: 1.5
- **Callee shortfall:** 0.5 (see Not measured when).

## Score
```
score = clamp( 10 − 10·s·I − 10·s·X·(1 − L), 0, 10 )
```

A call through an interface always lowers the score. A call that crosses a namespace lowers it only to the extent that collaborators are scattered: when L = 1, cross-namespace calls cost nothing. Larger codebases pay more for the same indirection.

## Not measured when
- There is no counted call: the sampled functions never call a function declared in the repository.
- The callee cannot be determined from the code for half (0.5) or more of all invocations in the sampled functions. The total is every invocation, including calls into the standard library and dependencies. Only invocations whose callee cannot be determined count toward the half. If the callee of an invocation is known to be in a library, it counts as determined.

## What the result is not
- It is not the depth of a call chain at run time. Each call is counted once, whatever lies behind it.
- It does not judge whether an interface is justified. A call through an interface with one implementation costs the same as a call through an interface with many.
- It does not count other indirection: calls through function values, callbacks, events, reflection, dependency-injection configuration, or overridable methods on classes.
- It is not file distance. Co-location is read from namespaces, not from folders or files.
- It is not a verdict on architectural style. It reads how much tracing the code asks for at its size.

## Pending re-definition
These are parameters of the existing reading's model, and today's score depends on each one. A later decision under decision 0013 will replace each with a threshold on the property.

- **Function sample:** the first 400 functions, one build unit at a time. Within a build unit, files are in path order and functions in source order.
- **Type sample:** the first 400 types, one build unit at a time. Within a build unit, types are in order of fully qualified name.
- **Feature:** the first two segments of a namespace define the slice that co-location is judged against.
- **Callee shortfall:** the dimension is not measured when the callee of 0.5 or more of the invocations cannot be determined.
