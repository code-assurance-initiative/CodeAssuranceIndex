# D10: Test Quality

**Lens:** productionReadiness · **Scored:** yes

## Property
Whether the tests truly assert behaviour rather than just running the code.

## Applies to
Test code in any programming language that declares test cases to a test framework. Examples are xUnit or NUnit in C#, JUnit in Java or Kotlin, PHPUnit, pytest, XCTest or Swift Testing, and Jest or Vitest in JavaScript and TypeScript. Markup (HTML) and styles (CSS) have no test cases, so this dimension does not apply to them.

## Population
This dimension reads the code that [production-code.md](../production-code.md) classes as **tests and test support**. That is the opposite of the production-code population. Only test cases count. Test helpers, fixtures and test data are read only when a test case calls them (see Unit).

- **In scope:** every test case the repository's own tests declare, whether it runs or is skipped.
- **Also in scope:** test cases in a test file that the file's own build project leaves out of compilation (for example a project that removes the file from its compile list). These tests never run, and nothing reports them as skipped.
- **Out of scope:** test code that is generated, vendored, or in build output, as [production-code.md](../production-code.md) defines those categories for any file.

## Unit and denominator
**Unit: a test case.** A test case is a method, function or callback that the test framework runs as one test, as the language and framework define it. Examples are a method with a test attribute, or the callback given to `it(...)` or `test(...)`. A parametrised test counts once.

Each test case falls into exactly one of these groups:

- **Skipped:** the code switches the test off so the runner does not run it. Examples are a skip or ignore attribute, a skip modifier such as `it.skip` or `xit`, a conditional skip, or a guarded bail-out at run time. A skipped test is never judged for assertions.
- **Compile-excluded:** a test case in a file that its build project leaves out of compilation. It is never judged for assertions and is not a skip.
- **Template stub:** a live test whose body holds only the placeholder comment from the test template that generated it. It is not judged.
- **Live:** every other test case.

**Assertion.** An assertion is a check that fails the test when the behaviour is wrong. Examples:

- a test framework's assertion calls;
- fluent or matcher assertions (`should...`, `expect(...)`, `assertThat`);
- a check that an expected exception was thrown;
- a check that a test double was called;
- snapshot or approval checks.

An assertion counts for a test when it sits in the test's body, or in a test or test-support helper that the test calls. This includes a helper that throws when its check fails. A harness that asserts on the test's behalf also counts as asserting. Examples are an analyzer-test builder, a verifier call, expected-diagnostic markup in the test source, and behaviour-driven step definitions in other files.

**Assertion-free.** A live test is assertion-free when it makes no assertion. A test whose only assertions cannot fail is also assertion-free. An assertion cannot fail when it compares values fixed before the code under test runs. Examples are a literal passing verdict such as `Assert.True(true)`, two equal constants, the same plain expression on both sides, and a local that the test sets once, from a literal or a newly created object, and never changes. Checking that a newly created object is not null also cannot fail. A comparison with a value the code under test produced can fail. So can a literal failing verdict such as `Assert.True(false)`.

**Denominator:** the number of test cases. That is all live, skipped, template-stub and compile-excluded tests. The denominator is never taken below 8 (see Pending re-definition).

## Thresholds
- **Documented skip.** A skip is documented, and does not count against the score, when its reason gives one of these:
  - an environment precondition or an explicit opt-in (for example "requires DATABASE_URL", "only on Linux", "manual benchmark");
  - a tracked defect: an issue or pull-request link, an issue number such as `#412`, or a tracker key such as `PRINT-88`;
  - a tag followed by a colon and an explanation, where the tag is one of BUG, ENV, FLAKY, TODO, WONTFIX, BLOCKED, KNOWN, DEFERRED, ISSUE or PENDING;
  - any other written reason of at least 16 characters that contains a space.

  A condition the code itself declares (for example `skipIf(condition)`) is a documented reason. These skips are **undocumented**:
  - a skip with no reason, or a skip mechanism that cannot carry one (for example `it.skip`);
  - a reason made only of debt words and filler (for example "todo", "flaky", "wip", "broken", "TODO: fix", "temporarily disabled");
  - any skipped test whose body is token-identical to a live test in the same class, whatever its reason says.

  The reason rules apply in this order. First, a tracked defect makes a skip documented even when debt words sit beside it (for example "flaky, see #412"). Otherwise, a reason made only of debt words and filler is undocumented, even when it starts with a tag (for example "TODO: fix"). After that come the precondition or opt-in rule, then the tag rule, then the written-reason rule.
- **Heavy assertion-free tests** are weighted 30. A test is heavy when its body is empty, or when its body holds commented-out assertion calls and no live assertion.
- **Light assertion-free tests** are weighted 15. These are all other assertion-free tests.
- **Exempt assertion-free tests** are left out of every penalty:
  - **Declared waiver:** the test framework's own declaration that the test performs no assertions (for example PHPUnit's `#[DoesNotPerformAssertions]`). This does not apply when the body is empty or holds commented-out assertions.
  - **Harness-style project:** a test project with at least 4 live tests, of which more than half are assertion-free. Three kinds of test do not count toward that "more than half", because they show the project is not a harness: tests with commented-out assertions, tests whose assertions cannot fail, and tests with an empty body. In such a project the assertion-free tests are exempt, except those with commented-out assertions or assertions that cannot fail.
  - **Visual test scene:** a test in a visual or manual test scene that a person checks by watching (for example a class run as an interactive test scene). The same two exceptions apply.

## Score
Let N = max(number of test cases, 8). The number of test cases includes the compile-excluded tests. Then:

```
score = clamp( 10
             − 20 × (undocumented skips / N)
             − 30 × (heavy assertion-free tests / N)
             − 15 × (light assertion-free tests / N)
             − 30 × (compile-excluded tests / N), 0, 10 )
```

Exempt tests, documented skips, template stubs and declared waivers stay in N and take nothing off the score. Compile-excluded tests are in N, and each also takes the weight of 30. A compile-excluded test is not a skip, so it never also takes the weight of 20. A suite whose tests all assert, with no undocumented skips and no compile-excluded tests, scores 10.

## Not measured when
The repository declares no test cases. Having no tests does not give a test-quality score of 10 or 0. The dimension is not scored at all.

## What the result is not
- It checks that an assertion is present, not that it is adequate. One trivial assertion is enough for a test to count as asserting.
- It does not check whether an assertion's failure reaches the runner. A test whose assertions sit inside a catch-all that discards failures counts as asserting.
- These do not change the score: fixed sleeps, dependence on a live external host, wall-clock races, snapshot suites that approve automatically, heavy use of test doubles, and references to mocking frameworks.
- It is not coverage (D8) and not reliability (D11).
- An exempt harness-style project may be a project of runnable samples that really checks nothing. The exemption follows the ratio, not proof that a harness exists.

## Pending re-definition
These are parameters of the existing reading's model. Today's scores depend on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Denominator floor:** the number of test cases is never taken below 8.
- **Harness-style project:** at least 4 live tests, and more than 50 % of them assertion-free.
- **Written skip reason:** at least 16 characters and containing a space.
- **Weights:** 20 for an undocumented skip, 30 for a heavy assertion-free test, 15 for a light one, and 30 for a compile-excluded test.
