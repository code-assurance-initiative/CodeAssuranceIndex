# X32: Type resolved by simple name across every loaded assembly

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether a plugin lookup names the type it means: searching the types of every assembly loaded into the process for one whose simple name (without its namespace) equals a string supplied at run time, and taking the first one found, is decided by the order the assemblies were loaded rather than by the source, so the same name can resolve to a different type on the next run. A lookup that requires exactly one match, or that requires the full name (with its namespace) to match as well as the simple name, is not this; one that accepts either name still is.

## Applies to
Languages that run on .NET and can ask the process for its loaded assemblies, for example C#, Visual Basic .NET and F#. The property cannot occur in other languages, so the dimension does not apply to them.

## Population
Production code as [production-code.md](../production-code.md) defines it, limited to the .NET languages above. This dimension adds no exclusions of its own.

## Unit and denominator
**Site (the denominator).** A site is one expression or statement that goes through the types of every assembly loaded into the process. That means the process's full list of assemblies and the types of each assembly in it. Both parts can be in one expression, or the sequence of types can be stored in a variable and used later. A site is one of these:

- **A pick:** taking one type out of that sequence, either the first match or the only match (for example `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`), however the sequence is narrowed.
- **A registry:** building a map from that sequence, keyed by a value taken from each type (for example `ToDictionary(t => ...)`).
- **A loop:** a loop over the types of every loaded assembly. It can be one loop, or a loop over the assemblies with a loop over each assembly's types inside it.

A sequence that goes on from the types to their members (methods, properties, fields, events, constructors), their parameters or their attribute instances is not a site, because a name there is not a type's name. A sequence that goes on to other types (for example each type's interfaces or nested types) is still a site. A search over the types of one named assembly is not a site either, because the author chose that scope in the source. Each site counts once, however many calls it chains.

**Finding (what is counted).** A site is a finding when load order decides which type a simple name resolves to:

- **A pick** that takes the first match, where the narrowing compares a candidate type's simple name with a value that is not a literal. Any equality test counts, for example `==` or a string-equality call with or without a comparison option, with the operands in either order.
- **A registry** where load order decides which of several types with the same simple name the map holds. For example, it groups the types by simple name and keeps the first type of each group, or a later entry with the same simple name replaces an earlier one.
- **A loop** whose body leaves the loop (for example by returning or breaking) at the first type whose simple name matches a value that is not a literal. A loop is also a finding when it writes map entries keyed by the type's simple name in a way where load order decides which type the map keeps: the first one written is kept (for example `TryAdd`), or a later write replaces an earlier one (for example assigning through the indexer).

Every finding is also a site, so a repository with `v` findings over `p` sites has `v ≤ p`.

## Thresholds
- One finding is enough to count. There is no minimum size.
- A pick that requires exactly one match is a site but never a finding.
- A map that fails to build, or a map write that fails, when two types share a simple name is a site but not a finding. It reports the ambiguity instead of resolving it by load order, as a pick that requires exactly one match does. A map that keeps every type with the same simple name (for example a group mapped to a list) is also a site but not a finding.
- Comparing the simple name with a literal is not a finding, because the author wrote that name into the source.
- A simple-name test joined by "and" to a test on the same candidate's full name (with namespace, or assembly-qualified) is not a finding. Joined by "or", it still is. A first-match search goes through the assemblies in load order before it looks within one assembly, so a simple-name match in an earlier assembly beats a full-name match in a later one.

## Score
Let `v` be the number of findings and `p` the number of sites in the repository.

- If `v = 0`, the score is 10.
- Otherwise let `n = max(p, v + 1)` and `d = min(v / n, 1)`. Then:
  - `isolation = max(0, 1 − d / 0.10)`
  - `headroom = clamp(log10(n) / log10(200), 0, 1)`
  - `ceiling = 6 + 2 × isolation × headroom`
  - `score = 1 + (1 − d) × (ceiling − 1)`, clamped to the range 1 to `ceiling` and rounded to 2 decimals.

So any finding caps the score at 8. A score near 8 needs a single finding among many sites. The score falls toward 1 as findings make up more of the sites.

## Not measured when
- The repository has no .NET production code. The dimension does not apply.
- The .NET production code was read and contains no site. Nothing was examined, so the result is not a 10.
- An engine cannot read part of the repository's .NET production code. It does not report this dimension for that repository, because scoring only the part it read would present a partial reading as the whole.

## What the result is not
- It does not check other ways of finding a type by name, for example loading a type from a full-name string or searching one named assembly.
- It does not check whether two loaded types actually share a simple name in a given deployment.
- It does not judge whether reflection-based plugin discovery is a good design.
- No published score includes it today because the engine reports it advisory.

## Pending re-definition
These are parameters of the existing reading's model, and today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Rot density:** 0.10. When findings make up this share of the sites or more, isolation is 0.
- **Population saturation:** 200 sites. Headroom stops growing at this point.
- **Ceiling band:** a base ceiling of 6 and a maximum of 8 for any repository with a finding. The floor is 1.
- **Denominator floor:** `n = max(p, v + 1)`, so the density stays below 1 even when every site is a finding.
