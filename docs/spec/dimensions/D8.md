# D8: Code Coverage

**Lens:** productionReadiness · **Scored:** yes

## Property
How much of the code is actually exercised by tests.

## Applies to
Any programming language whose tests can be run with line coverage recorded. Web markup (HTML) and styles (CSS) hold no executable lines and are outside the coverage figure.

## Population
Production code as [production-code.md](../production-code.md) defines it, with these differences:

- **Only languages whose tests were run.** The figure covers the production code of the languages whose test suites were run on the analysed commit. In such a language, a production file that no test executes is in the denominator with 0 covered lines.
- **Files with no logic are left out:**
  - a file that declares no function or method (for example a positional record, a value object, a view model, or a file of type declarations);
  - a file with fewer than 5 coverable lines;
  - a file whose only bodies are forwarding constructors. A forwarding constructor has an empty body, is not static, and only passes its own parameters or constants, unchanged, to a base or sibling constructor.
- **Lines with no logic are left out.** In any other file, uncovered lines inside forwarding constructors are not coverable lines.
- **Glue components are left out.** A UI component's code file (for example a Blazor `.razor.cs` code-behind) is left out when no function in it has a branch (every function has a cyclomatic complexity of 1).
- **Top-level statements are not a function.** A program's top-level statements (start-up code that no unit test calls) do not make a file non-trivial.
- **Code whose tests did not run to the end in this run is left out.** A production file is left out when a test that reaches it:
  - skipped itself while running, although its declaration does not skip it (for example it needs a database that is not available);
  - failed;
  - is in a test file that could not be loaded.

  This applies whatever coverage the file shows. A test that its own declaration skips does not cause this.

Test lines (used only by the floor under Score) are the non-blank, non-comment lines of tests and test support, counted the same way as production lines.

## Unit and denominator
- **Unit:** a covered line. This is a coverable line of production code in scope that the repository's tests executed while running on the analysed commit. A coverable line is a line that holds executable code, as the language's coverage defines it. Declarations, blank lines and comments are not coverable.
- **Runs:** the suite is run once. When the suite is also run repeatedly to check test reliability (D11), it is run 3 times, and a line counts as covered only when all 3 runs executed it.
- **Denominator:** all coverable lines of the production files in scope.
- **Line coverage:** c = covered lines ÷ coverable lines, summed over all files in scope. The figure is weighted by lines, not averaged per file.
- **Where the figure comes from:** only a run of the suite on the analysed commit. A coverage report committed to the repository is never read as a measurement.

## Thresholds
- **Trivial file:** fewer than 5 coverable lines, or no function or method.
- **Glue component:** every function has cyclomatic complexity 1 or less.
- **Placeholder report:** fewer than 10 coverable lines in total across the files in scope. The dimension is not measured.
- **Impossible report:** line coverage of 1 % or less while branch coverage is more than 5 percentage points above it. The dimension is not measured.
- **Material unmeasured language:** a language that holds at least 15 % of production lines (see Not measured when).

## Score
Let c be line coverage (0 to 1), T the test lines and P the production lines.

- **Coverage score:** `coverageScore = 10 · (1 − (1 − c)^2.86)`. For example: 20 % → 4.7, 50 % → 8.6, 80 % → 9.9, 100 % → 10.
- **Test-volume floor:**
  - when T = 0: `locScore = 0`;
  - when T > 0 and P > 0: `locScore = clamp(5 · T / P, 1, 5)`;
  - when T > 0 and P = 0: `locScore = 5`.
- **Measured score:** `score = max(locScore, coverageScore)`. The floor applies only when coverage was measured. It is never more than 5, and the coverage score passes 5 at about 21.5 % line coverage, so from there on measured coverage sets the score.
- **No tests:** a repository with no test code at all, and no project that declares itself a test project, scores 0. This is a full-confidence result.

## Not measured when
- No run of the suite produced a coverage figure. For example:
  - the suite did not build;
  - every test failed;
  - the run was stopped before it finished;
  - no coverage collector is set up;
  - the suite ran but recorded no coverage;
  - the tests run only on a platform the analysis cannot run (for example .NET Framework only).
- The run produced a placeholder report or an impossible report (see Thresholds).
- A language that holds at least 15 % of production lines has its own tests, and they were not run. A figure over one part is not published as the whole.
- No test code was found, but the absence of tests is not confirmed. For example, test projects exist outside the analysed solution, or the tests are in a language that was not read.
- The repository declares itself a template, kata or sample with no tests of its own. Its tests belong to the application built from it.

A dimension that is not measured publishes no score. It is not a score of 0.

## What the result is not
- It does not measure test quality. A covered line counts whether or not any test checks what it does. Assertion strength belongs to D10.
- It does not measure branch or path coverage. A line with two branches is covered when either one runs.
- It is not coverage on a machine with every external service available. Code reached only by tests that skipped, failed or did not load here is left out of the figure, not counted as untested.
- The test-volume floor does not measure coverage. It only stops a repository with substantial test code from scoring below 5 when measured coverage is low.
- Per-file low-coverage notes (below 50 %) and change-risk notes (complexity against coverage) are advice. They do not change the score.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on each of them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Curve exponent:** 2.86.
- **Test-volume floor:** factor 5 on the test-to-production line ratio, with bounds 1 and 5, and 5 when there are no production lines.
- **Trivial file:** fewer than 5 coverable lines.
- **Placeholder report:** fewer than 10 coverable lines in total.
- **Impossible report:** line coverage of 1 % or less with branch coverage more than 5 points above it.
- **Material unmeasured language:** 15 % of production lines.
- **Repeated runs:** 3 runs, each of which must execute a line for it to count as covered, when the suite is also run to check test reliability.
