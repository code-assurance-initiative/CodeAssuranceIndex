# R2: Cyclomatic Complexity

**Lens:** codeHealth · **Scored:** yes

## Property

Per-function complexity of the frontend code, counted from each function's actual branching: cyclomatic complexity, one plus each decision point (a condition, a loop, a case label or a short-circuit boolean operator); and cognitive complexity, one increment for each if, else-if, else, conditional expression, switch, loop, catch, labelled jump, recursive call and run of the same boolean operator, plus, for the structures that nest (conditionals, conditional expressions, switches, loops and catches), one more for each level of nesting they sit in.

## Applies to

The JavaScript family:

- JavaScript and TypeScript, including their JSX and module variants (for example `.js`, `.mjs`, `.cjs`, `.jsx`, `.ts`, `.mts`, `.cts`, `.tsx`).
- The script blocks of single-file components (for example Vue and Svelte). Their markup and styles are not read.

Here "frontend code" means all code in these languages, whether it runs in a browser or on a server. This dimension does not read script inside HTML pages.

## Population

The population is production code as [production-code.md](../production-code.md) defines it, limited to the languages above. That page already leaves out TypeScript declaration files.

This dimension differs from [production-code.md](../production-code.md) in one way:

- **Examples, samples, demonstrations and playgrounds:** the authors' own examples, samples, demonstrations and playgrounds are left out unless the product's own code imports them.

The authors' own developer scripts and tools stay in the population and are scored like any other production code. They are also part of one rule under Not measured when.

## Unit and denominator

**Unit: a function.** A function is any named or anonymous callable with a body, as the language defines it. This includes function declarations and expressions, arrow functions, methods, getters and setters, constructors, and functions assigned to class fields or object properties. Each function is its own unit, including nested and anonymous ones. A decision point counts only in the innermost function that contains it, so a nested function's branching never counts in the function around it.

**Unit: a file's top-level code.** The code in a file that sits outside every function is one more unit for that file, when it is more than 50 tokens long. Top-level code of 50 tokens or fewer adds no unit. A token is a lexical token of the language: a keyword, name, literal, operator or punctuation mark. Comments are not tokens. See Pending re-definition.

**Cyclomatic complexity of a unit** is 1 plus one for each of these in the unit:

- each `if`. An `else if` counts once, for its `if`. A plain `else` does not count.
- each loop: `for` in all its forms (including `for...in` and `for...of`), `while`, and `do...while`. Each loop counts once.
- each `case` label. `default` does not count.
- each `catch`.
- each short-circuit operator: `&&`, `||`, `??`.
- each conditional expression (`a ? b : c`). A TypeScript optional marker (`x?: T`) is not a conditional expression.

**Cognitive complexity of a unit** is counted as the Property defines it. It is reported for each function. It does not enter the score.

**Denominator:** all units in the population, across the whole repository.

## Thresholds

- **P95 bar: 5.** The score starts to lose points when the 95th percentile of cyclomatic complexity is above 5.
- **Over-20 count:** units whose cyclomatic complexity is greater than 20 (that is, 21 or more).
- **Report bar: 10.** Functions whose cyclomatic complexity is greater than 10 are listed as findings. Functions whose cognitive complexity is 8 or less are left off this list, because they are flat tables of independent arms. The list does not change the score.
- **Minimum files: 5.** See Not measured when.

## Score

Let:

- `n` = the number of units.
- `P95` = the nearest-rank 95th percentile of the units' cyclomatic complexity. Sort the values in ascending order and take the value at position `ceil(0.95 × n)`, counting from 1. `P95` is 0 when `n` is 0.
- `N20` = the number of units with cyclomatic complexity greater than 20.

```
p95_penalty    = max(0, P95 − 5)
over20_penalty = min(0.1 × N20, 2.0)
score          = clamp(10 − p95_penalty − over20_penalty, 0, 10)
```

- The P95 penalty has no cap. The score drops 1 point for each point of P95 above 5, so a P95 of 15 or more gives a score of 0 by itself.
- Each unit over 20 costs 0.1 point, up to 2 points in total. The cap is reached at 20 such units.
- When the population has files but no units, the score is 10.

## Not measured when

- The repository has fewer than 5 files in the languages above. Production code counts, and so do tests and test support. Examples, samples, demonstrations and playgrounds that this dimension leaves out (see Population) do not count toward the 5 files. Files left out of production code for any other reason (for example generated or vendored files) do not count either. See Pending re-definition.
- None of those files is production code, for example because every one is a test or test support.
- The repository declares no JavaScript package (for example it has no `package.json`), and all of its production code in these languages is the authors' own developer scripts and tools. In that case nothing installs, builds or serves the code.

## What the result is not

- It is not a judgement of the whole codebase. It reads only the JavaScript family. A repository with little such code is scored on that code alone.
- It is not cognitive complexity. Cognitive complexity is reported for each function, but only cyclomatic complexity moves the score.
- It is not a count of bad functions. The score depends on the 95th percentile and on the number of units over 20. Many functions between 11 and 20 lower the score only through the percentile.
- It does not see behaviour assembled at run time. Code built from strings, handlers composed at run time and tables of functions are counted as written, not as they run.
- A flat table of independent arms (for example a `switch` that maps each value to a constant) counts every arm as a decision point in the score, even though such a table is easy to read.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Top-level unit size:** a file's top-level code is scored as a unit only when it is more than 50 tokens long.
- **Minimum population:** the dimension is measured only when the repository has at least 5 files in the languages above, and at least one of those files is production code. Tests and test support count toward the 5 files along with production code. Examples, samples, demonstrations and playgrounds that this dimension leaves out do not count.
