# X13: Undrained process stream

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property

Whether a child process with BOTH standard streams redirected drains both — reading one to the end while the other is never read deadlocks once the child fills the unread pipe.

## Applies to

This dimension applies to any language whose standard library or common process library lets a program start a child process and pipe that child's standard output and standard error back to the parent. Examples are C#, Visual Basic .NET, Java, Kotlin, Scala, JavaScript and TypeScript, Python, Ruby, Go, Rust, Swift, Dart, Elixir and Erlang.

Languages differ in what "redirected" means, and that difference is part of the property:

- **Both streams piped by default:** some launch calls pipe both streams unless told otherwise (for example Dart's `Process.start`, Ruby's `Open3.popen3`, Node's `spawn` with no `stdio` option). A child started that way has both streams redirected.
- **Streams collected by the launch call:** some launch calls collect both streams themselves (for example Python's `communicate()`, Rust's `output()`, Ruby's `Open3.capture3`). A child started that way drains both.
- **Output delivered as messages:** some runtimes read the child's standard output for the parent and deliver it as messages (for example an Elixir or Erlang port that carries only standard output). That child has a single redirected stream and is not counted. It is still a child-process start.

## Population

Production code as [production-code.md](../production-code.md) defines it. This dimension has no exclusions of its own.

## Unit and denominator

- **Unit (what is counted):** an undrained child. This is a child process with both standard streams redirected, where the parent blocks on the child while one of the redirected streams is not drained. The parent blocks in either of two ways:
  - it reads the other stream to its end, or
  - it waits for the child to exit with no time limit.

  A stream counts as drained in either of two cases:
  - A read of it starts before the parent blocks and keeps running while the parent is blocked. Examples are an event-driven or background read, a read on another thread or task, or handing the stream to code that reads it.
  - It has already been read to its end before the parent blocks.

  A read that starts only after the blocking point does not drain the stream, and neither does reading only part of it before that point. Each child counts once.
- **Denominator (over what):** the child-process starts in the population. Every place the code starts a child process counts once, whether or not it redirects any stream. Settings that are created but never used to start a child do not count.

## Thresholds

- **Read to the end:** a read counts as reading to the end in either of two cases:
  - a call that returns only at end of stream, and the code waits on it;
  - a line or block read repeated in a loop that has no exit before end of stream.

  A single read, or a loop the code can leave early, is a partial read.
- **Unbounded wait:** a wait for the child's exit counts only when it has no timeout, or has an infinite one. A wait with a timeout or a cancellation is not a blocking point.
- **Ended child:** once the code kills the child, nothing after that point counts as blocking.
- **One finding is enough:** a single undrained child lowers the score. There is no minimum count.

## Score

Let `n` be the number of undrained children and `N` the number of child-process starts. Let `D = max(N, n + 1)`.

- If `n = 0`, the score is 10.
- Otherwise:
  - density `d = n / D`
  - isolation `i = max(0, 1 − d / 0.10)`
  - headroom `h = min(1, max(0, log10(D) / log10(200)))`
  - ceiling `c = 6 + 2 · i · h`
  - score `= 1 + (1 − d) · (c − 1)`, clamped to the range [1, c] and rounded to two decimals.

So any undrained child holds the score at 8 or below. Once undrained children make up 10 % or more of the starts, the score is at most 6.

## Not measured when

- The production code contains no child-process start. Nothing was examined, so the result is not a 10.
- The repository holds no production code in a language the reading covers for this dimension.

## What the result is not

- It is not a test that the program deadlocks. A child whose output always fits in the pipe never blocks, but the code still counts.
- It does not judge a stream that is redirected on its own. A parent that reads its only redirected stream is not counted.
- It does not judge other child-process risks, such as standard input left open, leaked processes, or exit codes nobody checks.
- No published score includes it today, because the one existing engine reports it advisory.

## Pending re-definition

These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Density cut-off:** at 10 % density, isolation reaches 0 and the ceiling falls to 6.
- **Population saturation:** headroom reaches 1 at 200 starts.
- **Ceiling range:** for any non-zero count, the ceiling runs from 6 to 8 and the floor is 1.
- **Denominator floor:** the denominator is at least `n + 1`, so the density never reaches 1.
