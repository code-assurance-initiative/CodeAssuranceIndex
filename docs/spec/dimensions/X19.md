# X19: Unrestored process-global state

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether a method that temporarily changes state belonging to the whole process — the working directory, an environment variable — puts it back on EVERY path: a restore reached only when nothing throws leaks the change to the rest of the process.

## Applies to
Any programming language in which code can change state that the whole running process shares. Markup (HTML) and styles (CSS) are not read.

Process-global state is state that the language, its runtime or its standard platform defines as one setting for the whole process. A change to it is seen by every thread and every later call. Which settings exist depends on the language:

- **In every language that has them:** the process working directory and each environment variable of the process. Each environment variable is its own global. The working directory is one global.
- **Where the runtime has them:** other settings the runtime keeps once per process. Examples are the standard output, error and input streams, the default locale and default time zone, the runtime's system property store (each property is its own global and the whole store is one more), the file-creation mask, how the process handles one signal (each signal is its own global), the panic or crash hook, the level of the process-wide logger, and a runtime's process-wide override hooks for file or network access.
- **Not process-global:**
  - The program's own static fields, module-level variables and singletons, even when every thread shares them. They belong to the application, not to the process.
  - State kept per thread (for example the current thread's culture or a thread-local value).
  - A change written to a persistent per-user or per-machine store rather than to the running process (for example an environment variable set for the user or the machine).
  - A value given only to a child process (for example a child process's working directory or environment), including a write that runs inside the child after it starts.

## Population
Production code as [production-code.md](../production-code.md) defines it, with this difference:

- **Left out:** examples, samples and demonstrations, the authors' own scripts and developer tools that are not published, and code that is part of the documentation.

Within that code, the population is every **body** that writes at least one process-global value.

A body is a function, method, constructor, property or event accessor, local function, anonymous function or lambda, as the language defines it. A function nested inside another is its own body, because its statements do not run on the enclosing body's path. A class body, a field initialiser and a program's or module's top-level statements are not bodies and are not in the population.

## Unit and denominator
**Unit:** a body in the population that leaves a scoped change unrestored on some way out. The body counts once, whether it leaves one global unrestored or several. A body counts when all of these hold for at least one global:

1. The body writes that global at least twice. The first write is the **change** and the last write is the **restore**.
2. The restore puts back the value the global held before the change. It writes back a value the body read from that same global, removes an environment variable or property that the change gave a value, or steps a counter back the way the change stepped it (for example an increment undone by a decrement). The change does not itself write that same saved value.
3. The restore follows the change on the body's normal path. A change and a restore that sit in two branches of one conditional do not count.
4. None of the body's writes to that global sit in an exception handler, or in a construct the language runs on every exit from the body. Such constructs are a `finally` block, a `defer` statement (for example Go's `defer os.Chdir(wd)`), a callback registered to run when the body exits, and a destructor or guard that restores the value when it goes out of scope.
5. At least one **way out** lies between the change and the restore. A way out is any exit from the body that skips the restore:
   - **In a language with exceptions:** a statement that can throw, an early `return`, or a `break` or `continue` that leaves past the restore. A window that holds no such statement, or holds only code wrapped in a handler that catches every exception and carries on, cannot leak.
   - **In a language without exceptions** (for example Go or Rust): an early `return`, a `break` or `continue`, error propagation (for example Rust's `?`), or an operation that stops the body by design, for example a forced unwrap, an assertion or an explicit panic. An ordinary call does not count as a way out.

**Denominator:** n, the number of bodies in the population. The score uses N = the larger of n and v + 1, where v is the number of counted bodies.

## Thresholds
- A global counts as changed and restored only when the body writes it **2 or more** times. A body with a single write makes a deliberate, permanent change and is not counted.
- Density: d = v / N.
- Isolation density: **0.10**. At or above this density, a non-zero count scores at most 6.0.
- Population saturation: **200** bodies. Below this, a single finding lifts the ceiling by less than the full amount.

## Score
- v = 0: the score is **10**.
- v > 0:
  - d = v / N, with N = max(n, v + 1)
  - isolation = max(0, 1 − d / 0.10)
  - headroom = clamp(log10(N) / log10(200), 0, 1)
  - ceiling = 6.0 + 2.0 × isolation × headroom
  - score = 1.0 + (1 − d) × (ceiling − 1.0), clamped to [1.0, ceiling] and rounded to 2 decimals

A non-zero count scores at most 8.0 and at least 1.0. For example, 1 counted body among 200 scores 7.87. Any population in which 10 % or more of the bodies are counted scores 6.0 or less.

## Not measured when
- No body in the population writes process-global state (n = 0 and v = 0). The result is then not measured, not 10.
- The repository has no production code in a programming language.

## What the result is not
- No published score includes this dimension today, because the one existing engine reports it advisory.
- It does not claim a race between threads. Another thread or callback may see the changed value during the window, but the source does not show whether another thread runs then.
- It does not judge a change that is never restored. A single write is taken as intended.
- It does not judge a change made in a class body, a field initialiser or top-level code, or in tests.
- It does not judge save-and-restore of the program's own static values.
- It does not show that a correctly restored change is good design. Passing the value to the operation that needs it (for example a child process's working directory or environment) avoids the change entirely.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Base ceiling:** 6.0, the highest score a non-zero count can reach with no lift.
- **Ceiling lift:** up to 2.0, so a non-zero count scores at most 8.0.
- **Isolation density:** 0.10. At or above it, the lift is 0.
- **Population saturation:** 200 bodies, where the lift reaches its full size.
