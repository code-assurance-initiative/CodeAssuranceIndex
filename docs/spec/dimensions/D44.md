# D44: Platform End-of-Life

**Lens:** securityCompliance · **Scored:** yes

## Property
Whether anyone still ships security patches for the platform this repository RUNS ON — the runtime it pins and the framework majors its own constraints hold it to. Separate from D12 because the question differs: a current Django on an end-of-life Python is perfectly up to date and completely unsupported, and the fix is a migration rather than a version bump. What the repository says it merely SUPPORTS is never charged.

## Applies to
This dimension applies to any language whose runtime or framework is listed under Thresholds. It reads declarations, not source code. A declaration is where a repository states its platform, for example in project files, package and build manifests, runtime version files and container build files.

- **Runtimes:** .NET and .NET Framework (C#, F#, Visual Basic .NET), Python, Node.js (JavaScript, TypeScript), PHP, Go, Java (and other languages that pin a JDK), Ruby, Elixir, Erlang/OTP, Dart, Scala and Rust. A Rust compiler counts as a runtime because its standard library is compiled into every binary it builds.
- **Frameworks:** Vue, AngularJS, Angular, Django, Rails, Laravel, Symfony and Spring Boot.

Some frameworks have no published vendor support policy (for example React, Flask, Express). They have no end date to cite, so they are not charged. A runtime or framework that is not listed here is out of scope.

## Population
The population is the declaration files of the repository's production code, as [production-code.md](../production-code.md) defines it. One difference: this dimension reads manifests, project files, runtime version files and container build files, although [production-code.md](../production-code.md) does not count them as source files. A declaration file is in the population when it belongs to production code. It is left out when it sits where [production-code.md](../production-code.md) excludes files, for example tests and test data, vendored code and installed dependency folders, generated code, build output and hidden folders. Declarations in the authors' own examples, samples, demonstrations, scripts and tools are in the population.

This dimension also leaves out:

- **Development-only dependencies,** and any dependency file that exists only to run the tests against several framework versions (a test matrix).
- **Floors.** A floor gives the oldest release the project still accepts. It states what the project supports, not what it runs on. For example: `requires-python = ">=3.8"`, `"engines": {"node": ">=14"}`, Cargo's `rust-version`, the `go` directive in `go.mod`, a Java bytecode or source level, `minimum_otp_vsn`, and a `mix.exs` `elixir: "~> 1.12"`.
- **Multi-target declarations with a supported target.** Some declarations offer several targets, for example `net6.0;net8.0`, a classic .NET project whose level differs by configuration, or a Scala build that cross-builds for several versions. Such a declaration counts only when every target has ended. It then counts as whichever of its targets lost vendor support last. For example, `net6.0;net7.0` counts as .NET 6, because .NET 6 support ended after .NET 7 support.

## Unit and denominator
There are two counts. Neither has a denominator.

- **R, ended runtimes:** the number of distinct ended runtime releases the repository pins. A release is one support line, numbered the way its vendor numbers it. For example: a .NET target such as `net6.0`, a Python minor (3.8), a Node.js major (16), a Go minor (1.21) or a Java feature release (19). A declaration pins a runtime in one of two ways: it makes a build or toolchain select that release, or it caps the project so that no supported release is admitted. For example:
  - A runtime version file (`.nvmrc`, `.python-version`, `.go-version`, `.java-version`, `.ruby-version`), the first entry per tool in `.tool-versions`, and `.sdkmanrc`.
  - A .NET target framework or classic framework level. A container image built `FROM` a .NET runtime, ASP.NET Core or SDK image, in every build stage.
  - A Rust toolchain file that names a numbered release. A Gradle Java toolchain. A Gemfile `ruby` directive that is exact or `~> x.y.z`. A `mix.exs` Elixir requirement that is exact or `~> x.y.z`. A `build.sbt` `scalaVersion`.
  - A cap. `requires-python = "==3.8.*"` or `"<3.9"` pins the highest minor it admits. A Dart SDK constraint capped below a supported release also counts. A Dart constraint `<3.0.0` with a lower bound of 2.12 or later is not a cap, because Dart 3 reads it as `<4.0.0`.
  - An `engines.node` range. It pins a release only when it admits no supported major. For this test, every Node.js major up to the newest ended even-numbered major on the list (today 20) has ended, including majors that are not on the list, such as 8, 11 and 13. The range counts as the newest admitted major that is on the list. For example, `<14` counts as Node.js 12. A range that admits no listed major is not charged. A range with one alternative that is open above is a floor.
- **F, ended framework majors:** the number of distinct ended framework majors that the repository's production dependency declarations hold it to. A declaration holds the repository to a major when its constraint cannot admit another major. Examples are an exact version, a caret, a tilde, an `x` or `*` range within one major (`2.*`), and a `~>` with at least two segments. Where a lockfile resolves the version, the resolved version decides. These do not hold a major: a constraint that admits more than one major, for example a bare comparator (`>=2.0`), an alternative (`^1 || ^2`), a range whose bounds span majors (`>=2,<4`) or a bare `*`. A framework family counts once per major. For example, Spring Boot counts once whether it comes through its parent, BOM, starters or plugin.

A release or major counts once, however many declarations or projects name it, because fixing it is one migration.

## Thresholds
The list below is closed. Only these releases count as ended today. The one exception is the Node.js range test under Unit and denominator. No other release counts, even when its support has also ended, for example Node.js 8, 11 and 13 in a version file, Python 2.6, PHP 5.3, Go 1.10 and 1.24, Ruby 1.9 and 3.2, Angular 11 and 18, or Django 4. The list holds only releases whose vendor security support ended before the freeze date and that had no supported track still getting fixes. Releases on the boundary were left off.

- **.NET:** .NET Core 1.0 to 3.1, and .NET 5, 6 and 7. .NET Framework 4.0, 4.5, 4.5.1, 4.5.2, 4.6 and 4.6.1. `netstandard` is a specification, not a runtime, and never counts.
- **Python:** 2.7 and 3.0 to 3.9.
- **Node.js:** 10, 12, 14 to 21, and 23.
- **PHP:** 5.4 to 8.1.
- **Go:** 1.11 to 1.23.
- **Java:** the non-LTS releases 9, 10, 12, 14, 16, 18, 19, 20, 22, 23 and 24.
- **Ruby:** 2.0 to 3.1.
- **Elixir:** 1.0 to 1.15.
- **Erlang/OTP:** 17 to 26.
- **Dart:** 2.0 to 2.19 (there was no 2.11 release) and 3.0 to 3.12.
- **Scala:** 2.11, 3.0, 3.1, 3.2 and 3.4 to 3.8.
- **Rust:** 1.0 to 1.97, the stable releases that a later stable release had replaced before the freeze date. The `stable` and `beta` channels and nightly builds never count.
- **Frameworks:** Vue 2, AngularJS 1, Angular 12 to 17, Django 1 to 3, Rails 4 to 6, Laravel 8 to 10, Symfony 3 and 4, and Spring Boot 1 and 2.

## Score
score = max(0, 10 - min(4.0 × R, 8.0) - min(1.5 × F, 4.5))

A runtime costs more than a framework. When a runtime is unsupported, nothing in the process gets security patches, including dependencies that are otherwise current. Examples:

- One ended runtime scores 6.0. Two or more score 2.0.
- One ended framework major scores 8.5. Two score 7.0. Three or more score 5.5.
- One runtime and one framework score 4.5.
- Two runtimes and two frameworks score 0.

## Not measured when
The repository declares no runtime listed under Applies to (no pin, cap or floor, whether supported or not) and declares no production dependency in an ecosystem where a listed framework is published (npm, Python packages, Composer, Maven or Gradle, RubyGems). Then nothing about the platform is known. The result is "not measured", never 10. For example, a Rust crate with Cargo dependencies but no Rust toolchain declaration is not measured.

## What the result is not
- It is not dependency currency. Whether a dependency is behind its latest release is D12.
- It is not the operating-system layer of a container image (D31). It is not the toolchain a CI workflow installs (D29).
- It is not a warning that support ends soon. A release that is not on the list scores clean, however close its end date.
- It says nothing about frameworks with no published support policy. A framework that is not charged is not thereby shown to be supported.
- A 10 means no listed runtime release or framework major was pinned. It does not mean every part of the platform is patched.

## Pending re-definition
These are parameters of the existing reading's model, and today's scores depend on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **The frozen list of ended releases:** the closed list under Thresholds, dated 2026-09-17 (the freeze date). A release can be on it only if its support ended before this date. A release whose support ended later is not charged until the list changes.
- **Files read per kind:** at most 200 files of each kind are read, for example 200 .NET project files, 200 `package.json` files, 200 Gradle build files and 200 container build files. Further files of that kind are not read.
- **File size:** a declaration file larger than 4 MiB is not read.
