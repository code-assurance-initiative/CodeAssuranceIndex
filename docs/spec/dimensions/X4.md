# X4: Structured logging

**Lens:** codeHealth · **Scored:** yes

## Property

Whether log calls use message templates (queryable) rather than interpolated strings.

## Applies to

This dimension applies to any programming language whose code logs through a logger that can keep a message's values apart from its text. Markup (HTML) and styles (CSS) are not in scope. A project whose only loggers take one finished message contributes no log calls (see Population).

## Population

Production code as [production-code.md](../production-code.md) defines it. This dimension adds the following.

- **Field-carrying loggers only.** A log call is in scope only when the project or package that owns it has a field-carrying logger available, either as a dependency or as its own logging API. A field-carrying logger accepts one of two forms:
  - a message template plus the values that fill it;
  - a constant message plus values as named fields or attributes.

  Examples:
  - .NET: Microsoft.Extensions.Logging, Serilog, NLog or ZLogger.
  - Java: SLF4J or log4j 2.
  - JavaScript: pino, winston or bunyan.
  - Python: the standard `logging` module, or structlog.
  - PHP: a PSR-3 logger.
  - Rust: `tracing`, or the `log` crate with its key-value feature turned on.
  - Go: log/slog, zap or zerolog.
  - Swift: swift-log.
  - Erlang: OTP's logger.
- **Calls through such a project's own logging code count.** This includes the project's own wrapper that takes one finished string. The fix there is to give the wrapper a template overload.
- **Out of scope:**
  - Log calls in a project that has no field-carrying logger. Examples:
    - a project that logs only through log4net, log4js, loglevel, Ruby's standard Logger, Rust's `log` crate without its key-value feature, Go's standard `log`, or Dart's `package:logging`;
    - console output;
    - a hand-written logger that takes one string.
  - Inside a project that is in scope, calls through a third-party logging API that has no template or field form. Examples: a game engine's debug console, or a build tool's task logger that takes only one finished or positionally formatted string.
  - Calls through a logger that takes an interpolated message apart into a template and arguments by itself. Examples: scala-logging, or Swift's `os.Logger` interpolation.
- **Not log calls:** methods that only share a logger's name, for example a logarithm (`Math.Log10`).

## Unit and denominator

- **Unit:** an interpolated log call.
  - **Log call:** a call that passes a message to a logger at a level, or opens a logging scope.
  - **Message argument:** the template. This is the first argument that carries the message text, after any exception, event id, level name or fields argument.
  - **Interpolated log call:** a log call in scope whose message argument is not a constant template. Its text is a finished string built from runtime values, either at the call or before it (for example in a local variable, or by a helper that returns the finished text).
- **A finished string built from runtime values** is any of these:
  - an interpolated string with at least one hole that is not a compile-time constant;
  - a concatenation with an operand that is not constant;
  - a formatting call applied before the logger sees the message (for example `String.format`, `fmt.Sprintf`, `sprintf`, `io_lib:format`);
  - an exception's own message text used as the template;
  - a variable or a call result that holds any of the above.
- **Examples by language:**
  - C#: `$"..."`
  - JavaScript and TypeScript: `` `${x}` ``
  - Python: f-strings
  - PHP: double-quoted strings with variables
  - Ruby: `#{}`
  - Kotlin: `$x`
  - Scala: `s"..."`
  - Swift: `\(x)`
  - Rust: a logging macro's format string with `{}` values
- **Not interpolated:**
  - a literal or named-constant template whose values are passed as separate arguments;
  - an interpolation whose every hole is a compile-time constant (for example `$"{nameof(X)} failed"`);
  - an interpolation whose every hole is a value that the same call also carries as a field;
  - a variable or call result that holds only a constant template.
- **Denominator:** N, the number of log calls in scope across the whole repository.

## Thresholds

- A log call counts as interpolated when its message argument is a finished string built from runtime values, as defined under Unit and denominator.
  - For an interpolated string, at least one hole must not be a compile-time constant.
  - That hole must also not be a value that the same call carries as a field.
- There are no other thresholds on the property.

## Score

Let v be the number of interpolated log calls, and let P = max(N, v + 1).

- **v = 0:** the score is 10.
- **v > 0:**
  - density d = v / P
  - isolation = max(0, 1 − d / 0.10)
  - headroom = clamp(log10(P) / log10(200), 0, 1)
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − d) × (ceiling − 1), clamped to [1, ceiling] and rounded to 2 decimals.

How the score behaves:

- Any interpolated call caps the score at 8.
- A density of 10 % or more caps the score at 6.
- In a small population the ceiling stays close to 6. The ceiling reaches 8 only for a population of 200 or more with a density near 0.
- The score falls toward 1 as the density approaches 1.

## Not measured when

- The production code holds no log call in scope (N = 0 and v = 0). The dimension is then not applicable. This happens when the code makes no log calls, or logs only through loggers that cannot carry fields.
- The repository has no production code.

## What the result is not

- It does not measure how much is logged, at which levels, or whether the right events are logged.
- It does not say whether the logger's configured output is structured. Text output from a field-carrying logger still scores.
- It is not a check for sensitive data in log messages.
- It does not judge logging done through loggers that cannot carry fields. A 10 never means that such logging is structured.

## Pending re-definition

These are parameters of the existing reading's model, and today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Ceiling for any violation:** 6. It rises by up to 2, to 8, for an isolated violation in a large population.
- **Isolation density:** 0.10. At or above this density the extra headroom is 0.
- **Population saturation:** 200 log calls. Headroom grows with log10 of the population, up to 200 calls.
- **Floor:** 1, the lowest score any non-zero count can reach.
- **Denominator floor:** P = max(N, v + 1), so the density never reaches 1.
