# D4: Code Duplication

**Lens:** codeHealth · **Scored:** yes

## Property
How much of the production code is copy-pasted: the share of production lines inside a reported copy (every copy of a duplicated block or of an edited member, each line once), 10 at none and 0 at a quarter of the lines.

## Applies to
This dimension compares code in every general-purpose programming language on the production-lines list in [production-code.md](../production-code.md), except JavaScript, TypeScript and single-file components (for example Vue or Svelte). HTML and CSS are not compared either. A separate dimension, R10, Code Duplication in front-end code, measures duplication in JavaScript, TypeScript and the web front end (see its page). Those files are still part of the denominator below.

## Population
Copies are looked for in production code as [production-code.md](../production-code.md) defines it, in the languages above. Examples, samples and the authors' own tools are production code here and count.

Tests and test support are not compared at all, because repeated test setup is not a defect. For example, the specimen code that a static-analysis rule is tested on is left out. So a production stretch whose only counterpart is test code is not a reported copy.

Vendored and generated code are compared, but none of their lines count. A copy in production code counts even when the code it was copied from is vendored or generated. Only the lines of the production copy count. A group whose copies all lie in vendored or generated code adds nothing.

**Constant data is not code.** A stretch made only of literals and punctuation, apart from a name it is bound to, is a data table and not a copied block. A function that is almost all literals is also a data table, and none of its lines can be part of any kind of copy. The numbers are under Pending re-definition.

A group of copies is left out, so none of its lines count, when the whole group meets one of the cases below. Every copy must meet the same case, or every pair of copies must meet it where the case is stated for pairs. A group whose copies meet different cases stays in.

- **Shape without shared data:** the copies repeat only the shape of simple statements, and each copy carries its own data. The kinds are statement runs, record literals, string payloads, lookup tables and skeletons. One kind must hold for the whole group. The criteria are under Pending re-definition.
- **Deliberate separate variants:** every pair of files in the group is a pair the repository keeps twice on purpose. Examples:
  - one source shipped once per module format or runtime
  - the locale variants of one table
  - sibling deliverables that must each stand alone (quickstarts, starters, templates, skills)
  - one asset served from two web roots

  A group with two copies in one file is never such a pair.
- **Separate project templates:** every copy sits in a project template, and the copies are in two or more different templates.

Copies inside one template stay in, and so does any group that does not meet one case as a whole. Copies the repository declares acceptable also stay in and count toward the score.

## Unit and denominator
**Token.** A token is one token of the language: a keyword, name, operator, punctuation mark or literal. Comments and layout are not tokens. A **working token** is any token that is not punctuation and not a literal.

**Same tokens.** Two stretches of code are the same if their tokens match in the same order. The copies may differ in the names of local variables and parameters, and in the values of numeric and character literals. String literals must match by their content, except that two stretches may differ in at most 1 string literal position when every other token matches (see Pending re-definition). Names of types, functions and members must match.

**Function.** A function is any named or anonymous callable with a body, as the language defines it, for example a method, constructor, accessor or local function.

**Same types.** This applies in languages where a function declares its parameter types and return type (for example C# or Java). Two functions work on the same types when they have the same parameter types and the same return type. They also work on the same types when both override or implement one shared contract (the same base or interface member, as it is declared there). A constructor has no return type, so only its parameter types count.

**A reported copy** is one of the following. Its counterparts may be anywhere in the compared code, which includes vendored and generated code but not tests. Only copies in the population count.

- **Duplicated block:** a stretch of code whose tokens appear at least twice in the compared code, in the same file or in different files. Every place the stretch appears is a copy, and all of them form one group.
  - A block is built from matching stretches of 60 tokens. Once a stretch repeats back to back at a fixed distance, a further copy at that distance joins the block when it matches over at least 30 tokens and spans at least 5 lines (see Pending re-definition).
  - In a language that declares types, two matching stretches are copies only when the functions that hold them work on the same types. The exception is a stretch that itself names enough distinct types, functions or members (see Pending re-definition).
  - A stretch of 60 tokens that is constant data is not a match. A block's lines count only where a matching stretch that is not constant data covers them.
  - Two blocks over the same copies are one block when, in every copy, both lie inside one function and only lines that read the same in every copy (blank lines aside) lie between them. The lines between them belong to the block.
- **Copied function:** a whole function body that appears whole as another function's body. The other function must be in a different file, or the body must appear 4 or more times in one file. In a language that declares types, the functions must work on the same types. Every copy is the whole function, and all copies of one body form one group.
  - A **renamed body** also counts. This is a body that matches another only after some of its names are changed. It must be in a different file and meet the rules under Pending re-definition.
- **Copied file:** a file with at least two non-empty function bodies, each of which also appears, with the same signature, in another file. Each body is matched to its own counterpart, so two identical bodies need two counterparts. The copies in one group are:
  - the contained file, from its first function body to its last
  - each file that contains it, from its own first function body to its last, so all of its functions count, not only the matched ones

  A copied file counts only when none of its copies overlaps a duplicated block or a copied function.
- **Edited copy of a function:** two functions where one is a copy of the other with some statements inserted, removed or changed. Each function counts as a whole copy. The criteria are under Pending re-definition. The groups are:
  - **Pairs found by chained runs** (second set of criteria): each pair is a group of two. A pair stops counting as an edited copy when a near-duplicate pair or a family of copied functions takes its place (see Pending re-definition). Then only its duplicated blocks count.
  - **Pairs found by shared share** (first set of criteria): when neither function has another edited partner, the two form a group of two. Functions with several edited partners are grouped as follows. Every two functions in a group must be edited copies of each other. The largest group is formed first, up to the group limit under Pending re-definition. When two possible groups are the same size, the one whose pairs share more tokens comes first. That group's functions are removed, and the next largest group is formed from the rest. This repeats until no two remaining functions are edited copies. A function that ends up in no group of two or more is not an edited copy.

**Unit: a copied line.** A copied line is a production line, as [production-code.md](../production-code.md) defines it, that lies inside a reported copy in the population. Every copy counts, the original as much as the paste, because nothing shows which came first. A line inside several copies counts once.

**Cap:** each copy is cut to the number of physical lines the shortest copy in its group spans, blank and comment lines included. The cut starts at the copy's own first line, and only the production lines inside the cut count. The cap applies to every kind of copy, with the groups defined above.

**Denominator:** all production lines of the repository as [production-code.md](../production-code.md) defines them, in every language on its list. This includes the JavaScript, TypeScript, single-file component, HTML and CSS lines this dimension does not compare.

## Thresholds
- **Duplicated block:** the repeated stretch is at least 60 tokens long, and every copy spans at least 5 lines.
- **Copied function:** every copy spans at least 5 lines. The other thresholds are under Pending re-definition.
- **Copied file:** the contained file's function bodies hold at least 30 tokens in total, and every copy spans at least 5 lines.
- **Compared share:** when no copy is found, the score is published only if the languages this dimension compares hold at least half of the repository's production lines (see Not measured when).
- **Differing string literals, constant data, different types, edited copies and their groups, near-duplicate pairs and families, left-out groups and the comparison limit:** see Pending re-definition.

## Score
- `p` = 100 × copied lines ÷ production lines, capped at 100. With no copied lines, `p` is 0.
- `score = clamp(10 − 0.4 × p, 0, 10)`.

The score falls in a straight line from 10, when no line is copied, to 0, when a quarter or more of the production lines are copied. The number of duplicated block groups is published beside the score but does not change it.

## Not measured when
- No copy is found, and the languages this dimension compares hold less than half of the repository's production lines. This includes a repository with no production code in those languages. Where the rest is JavaScript, TypeScript or other front-end code, R10 measures its duplication instead. For example, a repository that is 70 % TypeScript and 30 % C# with no copy found is not measured here.
- The comparison stopped at its limit (see Pending re-definition) before covering the whole population and found no copy. In that case, finding no copy proves nothing.

## What the result is not
- It is not a count of copy-paste events. A file copied into three places gives four copies, and all four count.
- It does not see copies below the thresholds, or copies of constant data.
- It does not see copies that differ in more than one string literal.
- It does not see identical code in functions that work on different types, unless the code names enough types, functions or members.
- It does not see copies across languages, for example the same logic written in C# and in Python.
- It does not see a production copy whose only counterpart is in a test.
- It does not see copies in JavaScript, TypeScript or the web front end, although their lines are in the denominator. By this page's definition, when the score is published (copies were found, or the compared languages hold at least half of the production lines), a repository with much front-end code therefore scores higher here than its compared code alone would.
- An edited copy counts its whole function, edited lines included, up to the cap. A copied file counts every function of each containing file between its first and last, up to the cap.
- It does not say which copy is the original, or whether the duplication should be removed.
- It counts copies the repository declares acceptable.
- The score is still published when the comparison stopped at its limit but found copies. The copied share is then a lower bound, because code that was never compared cannot add copies. The true score may be lower.

## Pending re-definition
These are parameters of the existing reading's model, and today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

**Back-to-back copies:** a further back-to-back copy of a block already found needs only 30 matching tokens, not 60.

**Comparison limit:** the comparison covers at most 12,000,000 stretches of 60 tokens, where one stretch starts at each token of the code compared. Code beyond that limit is not compared.

**Compared share:** with no copy found, the score is withheld when the compared languages hold less than 50 % of the repository's production lines.

**Differing string literals:** two stretches that match in every other token may differ in at most 1 string literal position.

**Different types:** a stretch of 60 tokens in functions that work on different types counts as a duplicated block only when it names at least 7 distinct types, functions or members (for example properties, fields or events). Local variables and parameters do not count as names here.

**Constant data:**
- A stretch of 60 tokens with at most 2 working tokens is constant data. It is not a match and adds no line to any duplicated block.
- A function of at least 60 tokens in which fewer than 10 % of the tokens are working tokens is constant data. None of its lines can be part of any kind of copy.

**Copied function:**
- **Size:** the body has at least 30 tokens.
- **Renamed, size bands:** a renamed body counts only when it has at least 30 and fewer than 60 tokens, or at least 150 tokens.
- **Renamed, which names:** a renamed body counts in either of two cases:
  - its changed names follow one consistent substitution (for example `Command` to `Event` throughout)
  - fewer than half of its distinct names are changed
- **Renamed, under 60 tokens:** two more rules apply to these bodies. They use three terms:
  - A **swap** is one changed name together with its replacement, in either direction.
  - A swap is **unrelated** when the two names share fewer than 3 characters of prefix plus suffix.
  - A **common word** is a name that appears in 8 or more functions of the repository.

  The two rules:
  - An unrelated swap is allowed only when both of its names are common words. Otherwise the pair does not count.
  - A swap **recurs** when the same two names are swapped in at least 2 different sets of short bodies that match each other after renaming. Each set counts once. When a pair makes 2 or more different unrelated swaps and at least one of them does not recur, the pair does not count.
- **One file:** copies inside one file count only when the same body appears there 4 or more times.

**Left-out groups.** One of these kinds must hold for every copy, or for every pair of copies where the kind is stated for pairs:
- **Statement runs:** each copy is a run of at least 3 statements. Each statement is an assignment or a single call with no operator and no control flow. No two copies share any assigned name, argument or literal.
- **Record literals:** the copies set the same fields in the same order, and fewer than half of those fields hold the same value in every copy.
- **String payloads:** each copy holds at least 2 string literals, and at least 0.10 string literals per word. A word is a name or a number outside the string literals; text inside strings does not count. For every pair of copies, the shared share of string literals is below 0.30. The share counts repeats and is taken over all the string literals of the pair.
- **Lookup tables:** each copy is a switch or match with at least 3 keyed arms. Each arm only maps its key to constants; a default arm may do anything. For every pair, fewer than half of the smaller table's arms map a key that the other table also maps to the same values.
- **Skeletons:** each copy has at most 1 line that makes a decision or a computation. For every pair, the shared share of their own names and literal values (counted with repeats) is below 0.5.

An edited copy is a pair of functions that meets either set of criteria below.

**Edited copy, first set (shared share):**
- **Size:** each function has at least 30 tokens, or at least 60 tokens when both are in the same file. The smaller function has at least 70 % of the larger one's tokens.
- **Shared tokens:** the tokens the two functions share in the same order make up at least 80 % of the smaller function and at least 70 % of the larger. When the smaller function has fewer than 60 tokens, the share for the smaller one is 90 %.
- **Shared run:** the two functions share at least one unbroken run of 20 identical tokens. A run that appears in more than 8 functions is common phrasing and does not count as this evidence.
- **Untouched statements:** on each side, count only the statements of two or more tokens that hold at least one shared token. A statement inserted or removed whole is not counted.
  - Of the counted statements on each side, at least 60 % must hold no unshared token.
  - When the smaller function has fewer than 60 tokens, at most 1 counted statement on each side may hold an unshared token.
- **Untouched statements, size limit:** when (tokens of one function + 1) × (tokens of the other + 1) is more than 8,000,000, the untouched-statements test is not applied. The pair then counts if it meets the size and shared-token tests.
- **Not already shown:** the pair is not added when one other reported copy covers 90 % or more of both functions' lines. It is also not added when either function has 90 % or more of its lines covered by other copies, unless the copies that link the two functions together cover 90 % or more of one of them. For this test, a function in a near-duplicate pair or a family of copied functions counts as fully covered by that pair or family.
- **Group limit:** a group of edited copies holds at most 12 functions.

**Edited copy, second set (chained runs):**
- **Linked:** the two functions already share a duplicated block.
- **Size:** each function has at least 120 tokens.
- **Runs:** the two functions share at least 2 unbroken runs of at least 20 identical tokens each, in the same order on both sides. No single run spans the whole correspondence, which is what sets this apart from a duplicated block.
- **One stretch:** on each side, the runs together cover one unbroken stretch of tokens. Each run starts no later than the token right after the previous run ends, so no token between the first run and the last is left uncovered. Runs may overlap on one side, and that overlap is where an edit sits. For example, `return nil, err` against `return nil, nil, err`: the inserted tokens repeat their neighbours, so one side's runs overlap and the other side's runs meet end to end. On the side where the stretch is shorter, it holds at least 120 tokens, counting each token once.
- **Not already shown:** the pair is not added when other duplicated blocks linking the two already cover 90 % or more of either function's lines.

**Near-duplicate pairs and families of copied functions.** These are not reported copies and add no lines of their own. A chained-run pair stops counting as an edited copy, and only its duplicated blocks count, in any of these cases:
- **Near-duplicate pair:** the two functions share duplicated blocks in at least 3 separate places (separate runs of lines on each side), and those blocks cover at least 20 % of each function's lines.
- **Family by one block:** 3 or more functions are joined, directly or through each other, by near-duplicate pairs or chained-run pairs, and one group of duplicated blocks has a copy inside every one of them. Every pair inside the family stops counting.
- **Family by two blocks:** in 4 or more functions, at least two groups of duplicated blocks each have a copy inside every one of them. Those copies lie in at least 2 separate places in each function and cover at least 20 % of each function's lines. Every pair with both functions in the family stops counting.
- **Family by common run:** 4 or more functions are joined, directly or through each other, by duplicated blocks whose copies overlap. All of them hold one common unbroken run of at least 50 identical tokens, and at least one of them is not already in a near-duplicate pair or family above. Every pair with both functions in the family stops counting.
