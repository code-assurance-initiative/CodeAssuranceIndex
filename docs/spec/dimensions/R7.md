# R7: Dead Code

**Lens:** codeHealth · **Scored:** yes

## Property
Dead code: files that cannot be reached by following imports, directly or through other files, from any entry point (an application start file, a tooling or configuration file, or a test), and exports that no file in the repository imports. Tests count as entry points, not as candidates. A file loaded only by a framework convention rather than an import (for example a route file found by its folder) can appear here, so a finding is not proof that the file is unused.

## Applies to
JavaScript and TypeScript in their module file kinds (`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`), and Vue, Svelte and Astro single-file components (`.vue`, `.svelte`, `.astro`).

## Population
- **Files read:** production code as [production-code.md](../production-code.md) defines it, in this dimension's file kinds. Some other files of the same kinds are also read: tests and test support, generated code, TypeScript declaration files and tool configuration files. These extra files only act as entry points or add lines to the denominator. They are never candidates.
- **Left out, unlike [production-code.md](../production-code.md):** the authors' examples, samples and demonstrations (for example a demo app, a playground, a quickstart or a proof of concept), load or performance test scripts, and email-template generators. These files are not read at all, and they do not count toward whether the dimension is measured.
- **Entry points:** every application start file, every tooling or configuration file, and every test. Application start files include, for example, a file a package manifest declares as its main, module, exports, types or browser target, a conventional start file such as `src/index.ts`, and a script a web page loads.
- **Not candidates for a dead file.** Their lines still count in the denominator:
  - entry points themselves;
  - TypeScript declaration files, and TypeScript files that only declare global types (no import, no export);
  - generated code;
  - every file of a package that has no application entry point;
  - every file of a package whose application entry points import a relative module that is missing from the repository (for example build output that is not committed).

  Only application entry points count for the last two rules. Tooling and test entry points do not.
- **Not candidates for an unused export:**
  - entry points of any kind;
  - tests and test support;
  - generated code;
  - modules that a dynamic import loads whole without naming what it takes, and every module such a module re-exports;
  - bindings a package publishes through its declared public entry, directly or through a chain of re-exports. A star re-export publishes the whole module.
- **Not candidates for an unused declaration:** tests and test support (including test inputs and fixture data), dead files (the dead-file count already covers them), generated code and TypeScript declaration files.
- Benchmark scripts are not among the files read. They count only as unwired benchmark scripts (below).

## Unit and denominator
- **Lines of a file:** the lines from the file's first line to its last line that holds code. Blank and comment lines before that last line count. A file with no code counts 0. For a single-file component, the count runs to the last line of its script.
- **Dead file:** a file in the population that no entry point reaches by following imports, directly or through other files. A type-only import (`import type`) also reaches its target.
- **Dead share:** the lines of all dead files, divided by the lines of every file read. The denominator includes tests, generated code, declaration files, tool configuration files, and files in packages without an application entry point.
- **Unused export:** a binding that a reachable file exports (by name, as its default, or through the module's export object) and that nothing consumes. There are two kinds:
  - A **value export** (a function, class, constant or variable) is consumed only by a runtime import. A value export that only type-only imports use counts as unused.
  - A **type export** (an interface or a type alias) is consumed by any import that names it, including a type-only import.
  - An export that its own module uses at runtime is not unused.
  - An import consumes a binding by naming it.
  - An import that takes the whole module as a namespace consumes every binding, unless every use of the namespace reads `ns.member`. In that case it consumes only those members.
  - A re-export consumes its target's binding only when something consumes its own re-exported name.
- **Unused declaration:** a class-private member, or a declaration local to a module, that no code in the repository references, as the language defines a reference. A use in a component's markup counts as a reference.
- **Unregistered command:** a command that an editor extension's manifest contributes but that no source file registers.
- **Stale build artefact:** a committed source map in a project's declared compiler output folder, where every source the map records is missing from the repository and at least one other map in the same folder records only sources that exist. A map with any source that still exists is not stale. Each map counts once. The compiled file beside it does not count separately.
- **Unwired benchmark script:** a benchmark script that imports the product but that nothing runs or references. No package script, workflow, build recipe or other file names it.
- **Unresolved import share:** the imports that resolve to nothing known, divided by those imports plus every import that resolves to a file. "Nothing known" means not a file in the repository, not a package and not a built-in module.

## Thresholds
- A file is dead when no path reaches it. One path from any entry point keeps it alive.
- An export is unused when nothing consumes it, as the unit above defines for values and types.
- When the unresolved import share is above 10 %, the dead-file penalty is halved (see Pending re-definition).

## Score
```
dead_penalty   = dead_share × 40 × h        h = 0.5 if unresolved import share > 0.10, else 1
other_penalty  = min(2.0, 0.05 × unused exports
                        + 0.05 × unused declarations
                        + 0.05 × stale build artefacts
                        + 0.05 × unwired benchmark scripts
                        + 0.5  × unregistered commands)
score          = clamp(10 − dead_penalty − other_penalty, 0, 10)
```
Without halving, a dead share of 25 % or more takes the score to 0 from the dead-file term alone. The other findings together never take away more than 2 points.

## Not measured when
- The repository has no files of this dimension's file kinds, or none could be read.
- The repository has fewer than 5 readable files of this dimension's file kinds, counting tests and the other files read (see Pending re-definition).
- None of the files of this dimension's file kinds is production code (for example every one is a test, test support or a demonstration).
- The repository declares no JavaScript package (it has no package manifest anywhere), and all of its production code in these file kinds is the authors' own developer tooling: for example local scripts a developer runs by hand, which nothing installs, builds, bundles or serves.
- No entry point exists: no application, tooling or test entry point. Without one, no file can be shown to be reachable or unreachable, so the score is not 10.

## What the result is not
- It does not prove a file is unused. A file can count as dead when something other than an import loads it: a framework convention, a path built at runtime, or a configuration string.
- It does not cover packages without an application entry point. Their files never count as dead.
- It does not cover dead code inside a live file, such as unreachable branches or unused parameters. It counts only whole files, exports, and private or module-local declarations.
- It does not cover the authors' examples, samples, demonstrations or load test scripts.
- It does not measure dead code in other languages.
- It can count an export as unused when only code outside the repository uses it and the package does not publish it through its declared entry.

## Pending re-definition
These are parameters of the existing reading's model. Today's scores depend on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Minimum files:** a repository with fewer than 5 readable files of this dimension's file kinds is not measured.
- **File size:** a file larger than 1,000,000 bytes is not read and does not count toward the minimum of 5 files.
- **Import resolution confidence:** when more than 10 % of imports resolve to nothing known, the dead-file penalty is multiplied by 0.5.
- **Unused declarations in Astro components:** for unused declarations, at most the first 2,000 Astro components per package are read, in file-path order.
- **Compiler output read for stale artefacts:** a declared output folder that holds more than 300 source maps is not read at all and adds no stale build artefacts. A source map larger than 4 MB is not read.
