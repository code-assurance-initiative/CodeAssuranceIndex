# X5: Nullable reference types

**Lens:** codeHealth · **Scored:** yes

## Property
Whether C# nullable reference types (the compiler's checks that a reference may be null) are enabled for the code (for example by a project setting or a `#nullable enable` directive), and not undermined by heavy use of the null-forgiving operator (`!`), which silences those checks.

## Applies to
C#.

## Population
Production code as [production-code.md](../production-code.md) defines it, in C# only. In addition:

- **Projects:** the C# projects of the repository that compile production C# code, as [production-code.md](../production-code.md) defines it. A project with no production C# files is not counted. For example, a project holding only tests, benchmarks, generated code or vendored code is left out.
- **Only where the feature exists:** a project counts only if nullable reference types are available to it. That means it compiles as C# 8 or later and none of its target frameworks predates nullable reference types (.NET Framework, .NET Standard 2.0 or earlier, .NET Core 2.x or earlier). A project that enables the setting counts whatever it targets.
- **One project, one count:** a project built for several target frameworks counts once. Each file counts once, however many targets compile it.
- **Without project files:** if the repository commits no project file for its C# production code, each production C# file stands in for a project. Examples are a Unity package, a game engine's script folder, or loose scripts.

## Unit and denominator
The score has two parts.

**Adoption ratio** = enabled units / eligible units.

- **With project files,** the unit is an eligible project. It counts as **enabled** when the project's own nullable setting is `enable` or `annotations`. A `warnings` or `disable` setting, or no setting, counts as not enabled. `#nullable` directives inside its files do not change how the project counts.
- **Without project files,** the unit is a production C# file. It counts as **enabled** when nullable annotations or nullable warnings are on at the start of the file, or after any of its own `#nullable` directives. Three things can switch the context on:
  - the file's own directives;
  - the compiler options committed for its assembly (for example a Unity `csc.rsp` with `-nullable:enable`);
  - the file-based app default: a file run directly with `#:` directives is enabled unless its own `#:property Nullable` says otherwise.

  Anything else counts as disabled.

**Suppression density** = null-forgiving operators per 1,000 syntax nodes.

- **Counted:** each postfix null-forgiving operator `!` (for example `name!` or `default!`) in production C# code, at a position where nullable warnings are on. A `!` where warnings are off suppresses nothing and is not counted. Warnings are off in a project that only enables annotations and in a region under `#nullable disable`. Logical negation `!x` is a different operator and is not counted.
- **Over:** the syntax nodes of production C# code at positions where nullable warnings are on. This includes code in a project that does not count as enabled, for example one whose setting is `warnings`. A syntax node is a node of the file's C# syntax tree as the language grammar describes it: declarations, statements, expressions, names, types and clauses. Tokens, comments and whitespace are not nodes, and neither is the file as a whole.
- Generated code adds neither its `!` nor its nodes. This includes a declaration marked as generated (for example with `[GeneratedCode]`) inside a hand-written file.
- The density is 0 when no code has nullable warnings on.

## Thresholds
- **Full suppression penalty:** a density of 5 or more `!` per 1,000 syntax nodes.
- **Eligibility:** C# 8 or later, and no target framework that predates nullable reference types (see Population).

## Score
Let r be the adoption ratio and d the suppression density.

- adoption = round(2 + 8 × r, 2), with r between 0 and 1
- penalty = min(1, d / 5)
- **score = round(adoption × (1 − 0.4 × penalty), 2)**

Every unit enabled with no counted `!` scores 10. If no unit is enabled, the score is at most 2, and exactly 2 when no `!` is counted. The `!` penalty takes away at most 40 % of the adoption score.

The lowest possible score is 1.2. It needs no unit enabled and a density of at least 5 at the same time. That can only happen with project files, where nullable warnings are on in code whose project does not count as enabled. Two examples are a project whose setting is `warnings`, and a `#nullable enable` or `#nullable enable warnings` region inside a project that is not enabled. Without project files, a file with warnings on anywhere counts as enabled, so no unit enabled means a density of 0 and a score of 2.

## Not measured when
- The repository has no C# production code that could be read. The dimension does not apply.
- There is C# production code but no eligible unit, because every project targets a framework or language version that predates nullable reference types. No score is given.

## What the result is not
- It is not a count of null dereference defects. A high score does not mean the code never dereferences null, and a low score does not mean it does.
- It does not judge each `!` on its own. Many are correct. The density only says how often the checks were overridden.
- It does not weigh units by size. A small project counts as much as a large one.
- An enabled project counts as enabled even if many of its files turn the checks off with `#nullable disable`. Only the `!` density reflects that, and only through the code that still has warnings on.
- It does not read nullable warnings that are reported and left unfixed.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Density scale:** suppression is measured per 1,000 syntax nodes of code with warnings on, and the penalty reaches its maximum at 5 per 1,000.
- **Curve shape:** the adoption floor of 2 and the maximum suppression weight of 0.4.
