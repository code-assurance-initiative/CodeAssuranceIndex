# D2: Cognitive Complexity

**Lens:** codeHealth · **Scored:** yes

## Property
How hard the code is for a person to follow, beyond raw branching.

## Applies to
This dimension applies to any programming language on the production-lines list in [production-code.md](../production-code.md). For a single-file component (for example Vue or Svelte), only its script part counts. Markup (HTML) and styles (CSS) contain no functions, so this dimension does not read them.

## Population
The population is the functions in production code, as [production-code.md](../production-code.md) defines it. This dimension also leaves out some code that the shared page includes:

- **Examples, samples and demonstrations:** for example an example app, a sample project, a demo or a proof of concept that the authors ship next to the product.
- **Benchmark code:** code that exists only to measure performance.

Test code, test doubles and test helpers are out, as they are for production code. A shared assertion helper is therefore measured nowhere.

## Unit and denominator
**Unit:** one function's cognitive complexity, a whole number.

A function is any named or anonymous callable with a body, as the language defines it. This includes methods, constructors, property and event accessors, and operators. A function defined inside another function's body belongs to the function that encloses it, whether it has a name or not (for example a lambda, a closure or a local function). Its increments count in the enclosing function, and it raises the nesting level of the code inside it. A declaration without a body (abstract, interface or external) is not a function here.

A function's cognitive complexity is the sum of these increments:

- **Nesting structures, +1 plus the current nesting level:** each `if`, each conditional expression (a ternary), each `switch` or `match` (once per statement, not per case), each loop (`for`, `for each`, `while`, `do while`), and each `catch`.
- **Flat, +1:** each `else if` and each `else`.
- **Jumps, +1:** each `goto`, and each `break` or `continue` that jumps to a label.
- **Boolean runs, +1 each:** each run of the same logical operator in any expression, not only in a condition. For example, `return a && b && c` is one run and `x = a && b || c` is two.

The nesting level is the number of nesting structures and enclosed functions that surround the construct. At the top level of a function body it is 0. Each language's own equivalents of these constructs count the same way (for example `elif`, `unless`, a pattern-matching `case`, or `rescue`).

**Denominator:** every function in the population. N is the number of functions.

## Thresholds
- **Over the threshold:** a function whose cognitive complexity is strictly greater than **15**. A function at exactly 15 is not over.

## Score
Let T = 15. Let *over* be the number of functions over T, and *max* the highest cognitive complexity of any function.

Let *p95* be the 95th percentile by nearest rank. Sort the values from lowest to highest, and take the value at position ⌈0.95 · N⌉, counting from 1.

1. **Percentile term:** `p95Score = clamp(10 − max(0, (p95 − T) / 5), 0, 10)`
2. **Worst-offender cap:**
   - If *max* ≤ T: `worstCap = 10`
   - Otherwise: `worstCap = clamp(10 − 3.5 · ln(max / T) · grip − 0.08 · min(over, 25), 2.0, 10)`, where `grip = clamp((over / N) / 0.08, 0.30, 1.0)`
3. **Score:** `min(p95Score, worstCap)`, rounded to 2 decimals.

A score of 10 means no function is over 15. The score cannot fall below 2.0 unless the 95th percentile is itself far over the threshold. It reaches 0 when *p95* ≥ 65.

## Not measured when
- The production code holds no function with a body. Examples are a repository with no source code, or one whose source declares only types, interfaces, abstract members, enums, records or constants.
- Every function in production code is in code this dimension leaves out (examples, samples, demonstrations, benchmarks).

## What the result is not
- It does not say whether code is correct, tested or fast. It also does not judge names, comments or how a function fits the rest of the design.
- It is not complexity across functions. Code split into many small functions that call each other scores well, even when the overall flow is hard to follow.
- The threshold of 15 is the same number used for cyclomatic complexity (D1). Cognitive values usually run lower than cyclomatic ones, so a bar set for cognitive complexity would be lower.
- One function far over the threshold can lower the score of a codebase that is otherwise clean. The effect is weaker when such functions are rare.
- Complexity in test code is never counted, however high it is.

## Pending re-definition
These numbers are parameters of the existing reading's model. Today's score depends on them. A later decision under decision 0013 will replace each one with a threshold on the property.

- **Percentile and slope:** the 95th percentile, and 1 point lost per 5 points of *p95* over the threshold.
- **Worst-offender weight:** 3.5 points per natural-log multiple of *max* over the threshold.
- **Grip:** the full worst-offender penalty applies when 8 % or more of functions are over the threshold. Below 8 % it scales down in proportion, but never below 30 % of the penalty.
- **Breadth:** 0.08 points per function over the threshold, counting at most 25 functions.
- **Floor of the cap:** 2.0.
