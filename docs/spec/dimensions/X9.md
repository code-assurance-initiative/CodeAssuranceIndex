# X9: Subsumed condition operand

**Lens:** codeHealth · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property

Whether, in a chain of conditions joined by logical or (`||`) or logical and (`&&`), one operand logically implies another, so one of them can never change the chain's value (under or, the operand that implies the other adds nothing; under and, the implied one restricts nothing): the condition tests less than it reads, which usually means a different condition was intended.

## Applies to

Any language that has a short-circuit logical or and logical and. The language may write them as symbols (`||`, `&&`) or as words (for example `or` and `and` in Python, `orelse` and `andalso` in Erlang).

## Population

Production code as [production-code.md](../production-code.md) defines it. Within it, every chain of operands joined by one logical operator: one or more `||` in a row, or one or more `&&` in a row. Parentheses that only group the same operator are ignored. A chain nested inside another operator is a chain of its own (for example an `&&` chain that is one operand of an `||` chain).

Two operands are compared only when they test the same value, and evaluating that value again gives the same result with no side effect. A local variable or a parameter is an example of such a value. A call that may return something new each time is an example of a value that is not.

This dimension adds no exclusions of its own.

## Unit and denominator

**Unit:** a subsumed operand. This is an operand of a chain that cannot change the chain's value because it implies a sibling operand in the same chain, or a sibling implies it:

- **Under or:** the operand that implies a sibling is subsumed. Every value that satisfies it also satisfies the sibling, so the sibling already decides the chain. For example, in `n.Contains("sbom") || n.Contains("bom")` the first operand is subsumed.
- **Under and:** the operand that a sibling implies is subsumed, because the sibling already forces it. For example, in `x > 10 && x > 5` the second operand is subsumed.
- **Two equivalent operands:** when two operands are the same test, or are true on exactly the same values, the later one is subsumed.

Implication means logical implication over the values the tested value can take. It covers string tests (substring, prefix, suffix, equality) where one literal contains the other. It covers numeric comparisons where one range lies inside another, and tests of a value's possible states (for example enum members, or null and not null). It also covers an operand repeated word for word.

**Not subsumed:** an earlier operand that stops a later operand from failing on the value it tests (for example `s != null && s.Length > 0`). Removing it would turn an answer into an error, so it can change the outcome.

Each subsumed operand counts once, however many siblings it implies or is implied by.

**Denominator:** none. The result is the count of subsumed operands in the repository's production code.

## Thresholds

None. An operand either is subsumed or it is not. No size or count decides when it starts to count.

## Score

No score curve is defined: the one existing engine reports findings only, with no 0-10 reading.

## Not measured when

- The repository has no production code in a language that has logical or and logical and.
- None of the production files in scope could be read. The result is then "could not read", not a clean result. If some files could not be read but others could, the unread files are listed with the result.

## What the result is not

- It is not a check of every condition. Subsumption split across two separate conditions is out of scope (for example an `if` and the `else if` after it). So is an implication hidden behind a named predicate, meaning a function or property whose body holds the test.
- It is not a bug report. A subsumed operand is always redundant, but only the author's intent decides whether the redundant operand or the surviving one is the mistake.
- It is not a measure of how complex conditions are, or of duplication across files.
- A count of zero does not prove that no condition in the repository is subsumed. It says only that none was proved.
