# D13: Secret Scanning

**Lens:** productionReadiness · **Scored:** yes

## Property
Whether any secrets (keys, tokens, passwords) have leaked into the code.

## Applies to
Any language. This dimension also reads these file kinds, which are not production code:

- configuration files (for example JSON, YAML, XML, INI, TOML, properties and `.conf` files, and `.env` files and their variants such as `.env.production`);
- shell, PowerShell and batch scripts, and build scripts;
- project and solution files;
- SQL;
- plain text files and files with no extension;
- key, certificate and key-store files (text or binary);
- committed HTTP request files.

It reads documentation in prose markup for private keys only.

## Population
The files of the analysed commit's working tree. History is not read here; D28 reads it.

The base is production code as [production-code.md](../production-code.md) defines it. This dimension differs from that base as follows.

**Also read here (not production code, but in scope for this dimension):**

- The file kinds listed under Applies to. Lockfiles stay excluded.
- Hidden folders (for example `.github`), tool configuration files (for example `vite.config.ts`), server-side view templates, TypeScript declaration files, and any file that is the repository's own key material.
- An application's environment configuration file, even when it is named after the test environment (for example a framework's `config/test` settings file).
- **Private keys only:** documentation in prose markup (for example Markdown, reStructuredText, AsciiDoc), wherever it sits; editor and IDE folders (for example `.vscode` or `.idea`); and a file in a build-output folder that is itself a private key.

**Also excluded here (production code, but out of scope for this dimension):**

- Examples, samples and demos.
- Copy-me templates and project scaffolds: files meant to be copied and filled in (for example `config.example.json` or `.env.example`). Server-side view templates are still read.
- Seed, factory, fake and mock data, and key material made for tests (for example a test certificate authority).
- Configuration that only a test run reads (for example a test runner's configuration file).
- Published API specifications, and copies of third-party standards (for example an RFC kept as reference).
- The repository's own allowlist or suppression files for credential scanning, and the paths those files declare as reviewed.
- Binary files, except files that hold private key material.
- Files over the size caps under Pending re-definition.

Every other exclusion in [production-code.md](../production-code.md) still applies: tests and test support, generated and vendored code, build output and installed dependencies, lockfiles, linked copies, files the version control ignores, and files the repository marks as generated or vendored.

## Unit and denominator
**Unit:** a leaked secret. A secret is a literal value in the code that gives access to something, and that an issuer created and could revoke. For example:

- a private key in any encoding, or a key store that holds one;
- an access key or token for a cloud, a service or an API;
- a signing key;
- a password, or a connection string that contains a literal password;
- a file whose whole content is a credential.

These are **not** leaked secrets:

- A reference to a secret rather than its value (for example reading an environment variable, a variable or a call).
- A public key, or a key that its vendor publishes as public (for example a publishable key, a browser-side Firebase or Maps key, or a search-only key).
- An encrypted value (for example a sealed or vault-encrypted secret).
- A password hash. It is listed for checking but not counted.
- An access key identifier with no matching secret key next to it. It is listed for checking but not counted.
- A value that says it is fake, a placeholder, masked or an example; a well-known example credential from documentation; or a trivial default password (for example `admin123`, or a password that equals the user name next to it).
- A value that is a name, phrase, pattern or identifier rather than a random value (for example a configuration key name, a locale code or a regular expression).
- A value printed as the output of a documented example, or a value that the comment above it says is not secret.
- A value that the authors mark as allowed on its own line (for example with `gitleaks:allow`).

**Kind:** what the secret is and, for an issued key or token, who issues it and in what form. For example:

- a private key (the same key in another encoding or in a key store is still a private key);
- one service's access key or token (an AWS secret access key and a GitHub token are two different kinds);
- a password, including the password in a connection string;
- a symmetric signing or encryption key;
- a whole-file credential.

**Counting:** secrets of one kind in one file count as one secret. Secrets of different kinds, or in different files, count separately. The same value in two files counts twice.

**Denominator:** none. The score depends only on the count.

## Thresholds
Every secret counted costs 5 points.

## Score
`score = clamp(10 − 5 × secrets, 0, 10)`

| Secrets counted | Score |
|---|---|
| 0 | 10 |
| 1 | 5 |
| 2 or more | 0 |

## Not measured when
None. Every repository is measured. A repository with nothing in scope scores 10.

## What the result is not
- It is not proof that there are no secrets. A secret in a format the reader does not recognise is not counted.
- It does not read history. A secret that was removed from the tree but is still in an older commit is D28's concern.
- It does not say whether a secret is live, or what it gives access to.
- It does not grow with exposure. A secret of one kind repeated many times in one file costs the same as one.
- Items that are listed but not counted (password hashes, access key identifiers without a secret key, search-only keys) do not change the score.

## Pending re-definition
These are parameters of the existing reading's model. Today's score depends on them, and a later decision under decision 0013 will replace each with a threshold on the property.

- **Size caps:** a file over 1,000,000 bytes is not read. This includes documentation read for private keys. The exception is SQL, `.env` and its variants, INI, TOML, properties, `.conf`, `.config` and YAML files, which are read up to 16,000,000 bytes.
- **One per kind per file:** secrets of one kind in one file count as one. How finely kinds are split decides how many secrets one file holds.
- **Penalty per secret:** 5 points, so two secrets reach 0.
