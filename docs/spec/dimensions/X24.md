# X24: Document value interpolated into markup unescaped

**Lens:** securityCompliance · **Scored:** yes in the standard (the catalog does not declare it advisory); the one existing engine reports it advisory, so no published score includes it

## Property
Whether text read out of the document being converted is escaped before it is written into generated markup — a value the document's author chose, interpolated into an attribute the surrounding literal delimits, can close that attribute and open another.

## Applies to
Any programming language whose code builds markup (HTML, SVG, XML) as strings, from literal text with values inserted into it. The markup is what the code outputs. Markup files and template files are not in scope (see Population).

## Population
Production code as [production-code.md](../production-code.md) defines it, with these additions:

- **Markup a framework escapes is out.** The markup part of a template or single-file component is out of scope, because the framework escapes its placeholders. A Vue or Svelte component's template is one example. Its script part is in scope like any other code.
- **Raw-output directives are out.** A template's raw-output directive (for example `v-html`, `{@html}` or a raw-markup helper in a server-side view) does not build markup from a literal. This property does not cover it.
- **Strings that never become markup are out.** A string the code uses only as plain text is out, for example one assigned to an element's `textContent` or `innerText`. So is a string the code passes whole to a sanitiser right after building it (for example `DOMPurify.sanitize(...)`).

## Unit and denominator
**Markup string.** A string the code builds from literal text and inserted values, where the literal text contains the start of a tag: a `<` followed by a letter or by `/`.

**Hole.** A place in a markup string where a value is inserted, written the way the language writes it. For example:

- an interpolation hole (C# `$"..{x}.."`, a JavaScript template substitution, Ruby `#{x}`, a Python f-string field, Scala `s".."`);
- a format placeholder (Python `%s`, or `{}` with `.format`);
- one value concatenated between two string literals (`"<a href=\"" + x + "\">"`).

**Delimited hole (the denominator).** A hole that meets all of these:

- The inserted value is text (a string). A number, date or other value that the hole formats into digits or fixed characters does not count.
- There is literal text on both sides of the hole. A hole right next to another hole, or at the start or end of the string, does not count.
- The literal text on its two sides marks one of these two positions:
  - **a quoted attribute value:** the text before ends with `="` and the text after starts with `"`, or the same with `'`;
  - **an element's text:** the text before ends with `>` and the text after starts with `<`.

**Document value.** Text the program reads out of a document it has parsed: an attribute's value, or the text or inner markup of an element or node, as the document's interface returns it. For example:

- in .NET, the `Value`, `InnerText` or `InnerXml` of an XML or Office Open XML element or attribute;
- in a browser, the `getAttribute`, `textContent`, `innerText` or `nodeValue` of a DOM node;
- in Java, Python, Ruby or Scala, an attribute or text read from a node of a parsing library.

A member with the same name on the program's own types is not a document value. These interfaces return decoded text, so an entity the author wrote (`&quot;`, `&lt;`) becomes a live character again.

**Convicted hole (the unit).** A delimited hole that a document value can reach with nothing escaping or validating it on the way.

- **Reach.** A value reaches the hole if some path in the code carries it there, whether or not every run takes that path. A path may cross functions and files. Paths run through:
  - local variables, assignments, fields and properties;
  - arguments into parameters, and return values;
  - elements of tuples, records and collections;
  - string composition: concatenation, interpolation, null-coalescing, either branch of a conditional, and a string-returning call on the value (for example `.Trim()`) whose body is not in the repository.
- **Escaped.** A value is escaped when it passes through a function that escapes, encodes or sanitises it for markup, for example `WebUtility.HtmlEncode`, `SecurityElement.Escape`, or the project's own `EscapeXml`. Replacing markup characters with character entities by hand also escapes it.
- **Validated.** A value is validated when one of these holds:
  - the hole is reached only under a condition (`if`, `?:`, `while`) that checks that same value against the shape its position accepts, for example `if (IsHexColor(c))`. A check that only narrows the value (not null, not empty, a length) does not validate it;
  - a conditional passes the value on only after testing it against a fixed set of constants, for example `pos is "r" or "l" ? pos : ""`;
  - the value goes through a function that returns only characters that cannot close the position.
- **No longer text.** A value stops being the document's text once it becomes a number, a boolean or a length, for example through a comparison, arithmetic, `.length` or a number conversion.

Each convicted hole counts once. v is the number of convicted holes. The denominator N is the number of delimited holes, but never less than v + 1: N = max(delimited holes, v + 1).

## Thresholds
- A hole counts only in the two positions above: a quoted attribute value or an element's text.
- One path that reaches the hole is enough to convict it. One escaping or validating step on that path clears it.

## Score
- v = 0: the score is 10.
- v > 0:
  - density d = v / N, kept between 0 and 1
  - isolation = max(0, 1 − d / 0.10)
  - headroom = log10(N) / log10(200), kept between 0 and 1
  - ceiling = 6 + 2 × isolation × headroom
  - score = 1 + (1 − d) × (ceiling − 1), kept between 1 and the ceiling, rounded to 2 decimals.

The ceiling is never above 8, so any convicted hole keeps the unrounded score below 8. From 200 delimited holes up, and while d is at most 0.10, the score is 8 − 27d + 20d². After rounding, the score reaches 8.00 only when convicted holes are very rare: a density of about 0.0185 % or less, which is about one convicted hole per 5,400 or more delimited holes. One convicted hole among 200 delimited holes scores 7.87 (d = 0.005, isolation = 0.95, ceiling = 7.9). From a density of 10 % up, at any number of holes, the ceiling is 6.0 and the score is 1 + (1 − d) × 5. That is at most 5.5 (at 10 %) and falls to 1 at d = 1.

## Not measured when
- The repository's production code has no delimited hole and no convicted hole (N = 0). Code with no such markup does not score 10.

## What the result is not
- No published score includes it today, because the engine reports it advisory.
- It is not proof that an attack works. A convicted hole means a document value can reach the hole, not that it does on every run.
- The property does not cover:
  - values from other untrusted sources, for example request parameters;
  - values written through raw-output sinks or template directives;
  - holes outside the two delimited positions, for example unquoted attributes, URL schemes, or script and style blocks;
  - a raw hole no document value reaches, even where the code escapes the same value in the same position elsewhere.
- It does not judge whether an escaper is the right one for the position.
