# R3: Large Files

**Lens:** codeHealth · **Scored:** yes

## Property
How many source files exceed the large-file threshold.

## Applies to
JavaScript and TypeScript, including their JSX and module variants (for example `.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`,
`.tsx`), and single-file components (Vue and Svelte), each counted as a whole file. HTML, CSS and every other language
are out of scope for this dimension.

## Population
The population is production code as [production-code.md](../production-code.md) defines it, limited to the languages above. This dimension
differs from that page in these ways:

- **Examples, samples and demonstrations are left out.** This covers the authors' own example, sample, demo, sandbox,
  playground and quickstart code.
- **Load and performance scripts are left out.** These are scripts that exist only to load-test or benchmark the
  product.
- **Static assets of a server application in another language are left out.** These are scripts that a web
  application whose server is written in another language serves unchanged as static files (for example the
  script shims of a .NET web app).
- **Email-template generators are left out.** This is code that exists only to produce email bodies (for example
  email templates written for an email markup framework).
- **The authors' own scripts and tools stay in.** They count in both the numerator and the denominator.

Files left out by [production-code.md](../production-code.md) or by this list are not in the numerator or the denominator.

## Unit and denominator
- **Unit:** a file in the population that is longer than the threshold. A file's length is its number of non-blank
  lines. Comment lines count. Blank lines and lines holding only whitespace do not.
- **Denominator:** the number of files in the population.
- **Share:** the number of large files divided by the number of files in the population.

A large file counts whatever its content. A long file that holds only data still counts, unless [production-code.md](../production-code.md)
excludes it as a data file.

## Thresholds
- **Large file:** more than 400 non-blank lines. A file with exactly 400 is not large.
- **Minimum files read:** 5 files in the languages above that are either in the population or tests. In other words,
  this is production code as [production-code.md](../production-code.md) defines it, after this page's exclusions, plus test files. Files that
  [production-code.md](../production-code.md) excludes for any other reason (for example generated, vendored or declaration files) do not count
  toward the 5.

## Score
score = 10 − 40 × (large files ÷ files in the population), clamped to the range 0 to 10.

- No large files scores 10.
- Each 2.5 % of files that are large costs 1 point.
- A share of 25 % or more scores 0.

The score does not depend on how much of the repository the population makes up. When the population is a minority
of the repository's production code, the result says so, but the score stays the same.

## Not measured when
- Fewer than 5 files in the languages above are either in the population or tests (see Thresholds).
- None of those files is in the population, for example when every one is a test.
- The repository declares no JavaScript package (for example it has no `package.json`), and every file in the
  population is one of the authors' own development tools or scripts.

## What the result is not
- It does not measure the whole repository. Large files in other languages are not counted. Other dimensions
  measure oversized types and project size.
- It does not measure complexity or responsibilities. It reads only length, so a long file that is simple and
  well organised counts the same as a tangled one.
- It does not say how far a file is over the threshold. A file of 401 lines and a file of 5,000 lines each count once.
- It does not say that any one file must be split.
