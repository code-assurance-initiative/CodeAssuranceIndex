# Licences, contributions and the name

## What is licensed how

| What | Licence |
|---|---|
| Code in this repository (the reference scorer, CLI, site, registry) | [Apache-2.0](../LICENSE) |
| The specification and documentation (`docs/`), and the published rubric catalogs (`rubrics/`) | [CC BY 4.0](../LICENSE-docs) |

Anyone may implement the standard, in any software, open or closed, commercial or not, without asking. Apache-2.0
already carries a patent licence from every contributor of code.

## Patents

The Code Assurance Initiative, and every contributor by contributing, commits not to assert any patent claim against
anyone for implementing the standard as published, in any version. Anything that would require a patent licence to
implement does not belong in the standard; if it is found there, it is a defect, and it will be removed.

## Contributions

Contributions are accepted under the **Developer Certificate of Origin** ([developercertificate.org](https://developercertificate.org)):
every commit carries a `Signed-off-by:` line (`git commit -s`), by which the contributor certifies they have the right
to submit it under the licences above. There is no contributor licence agreement and no copyright assignment.

## The name and the badge

"Code Assurance Index" and "CAI" name the standard. Anyone may use them to **refer** to it and to **state a score**,
provided the score names its rubric version and can be reproduced from its evidence ([CHALLENGE.md](CHALLENGE.md)).

- A product may say it **implements** CAI. It may say it is **qualified** only for what its current qualification
  record states ([ENGINE-QUALIFICATION.md](ENGINE-QUALIFICATION.md)).
- A badge must link to the record it claims ([codeassuranceindex.info/badge](https://codeassuranceindex.info/badge/)).
- No one may present a modified rule set as "CAI". A fork is welcome under its own name.

The name, the badge and the domain are intended to be held by an independent association once it is founded
([GOVERNANCE.md](GOVERNANCE.md)).
